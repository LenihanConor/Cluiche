Problem: The 3 red dashed lines are invisible to the manifest. No validation, no config visibility, no ordering guarantees. They rely on "set before use" convention + raw static pointers. A module author has to know to call GetStaticCanvas() and trust it's been set. The sRenderContextReleased atomic is a shutdown fence — directionally reversed (Render→Main).

Result: All cross-PU data flow is now manifest-declared. The 2 yellow lines replace 2 of the 3 red dashed statics. sRenderContextReleased is removed from scope — it's a shutdown fence, not a service handle; it will be solved as a framework lifecycle hook separately.

Module author pattern:
ServiceStreamWriter<ICanvas> mCanvas{this, "Canvas"}; → Publish(canvas) once in DoStart
ServiceStreamReader<ICanvas> mCanvas{this, "Canvas"}; → Get() anywhere after publisher's DoStart
Manifest (unified channels array):
// streams[] adds:
{ "id": "Canvas",         "kind": "ServiceStream", "payload_type": "ICanvas",          "from": "MainPU" }
{ "id": "TextureHandler", "kind": "ServiceStream", "payload_type": "ITextureHandler",  "from": "MainPU" }

// modules use unified channels[] instead of reads[]/writes[]:
"KernelModule":     { "channels": [{"id":"InputToSim","role":"writes"}, {"id":"Canvas","role":"publishes"}, {"id":"TextureHandler","role":"publishes"}] }
"RenderModule":     { "channels": [{"id":"SimToRender","role":"reads"}, {"id":"Canvas","role":"subscribes"}, {"id":"TextureHandler","role":"subscribes"}] }
"DummyLevelModule": { "channels": [{"id":"TextureHandler","role":"subscribes"}] }
"AssetServiceModule": { "channels": [{"id":"TextureHandler","role":"subscribes"}] }

Stream Kind Summary

Kind Frequency Semantics Example Roles
FrameStream Every frame Latest-value ring buffer; reader gets most recent frame SimToRender (FrameData) writes / reads
EventStream On demand Discrete events; reader consumes queue InputToSim (InputEvent) writes / reads
ServiceStream Once (at DoStart) Stable handle; published once, available forever Canvas (ICanvas) publishes / subscribes
