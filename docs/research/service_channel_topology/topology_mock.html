Growth Analysis: Current → Future

  • +2 PUs (AudioPU, NetPU) added 4 new PU-pair directions = +4 FrameStreams, +2 EventStreams
  • +4 ServiceStreams — 2 global (AudioDevice, NetSession) + 2 stage-scoped (PhysicsWorld, AIContext)
  • Zero new streams from adding physics debug, animation debug, new render features — all fold into SimToRenderFrame composite
  • 18 total streams for a mature multi-threaded engine with networking and audio — still fits in one screen
  • Max channels per module: 4–5 — no explosion
  • Stage-scoped services (PhysicsWorld, AIContext) reset on stage unload; inferred from declaring in stage manifest

Growth Ceiling Formula

  • N PUs → at most N×(N-1) directional pairs = 20 for 5 PUs (not all used)
  • Each pair gets max 2 streams (1 Frame + 1 Event) — some pairs only need one
  • ServiceStreams: ~2 per PU (global infrastructure handles) + 2-3 stage-scoped
  • Hard ceiling for 5 PUs: ~30 streams. Practical: 15-20.
  • Compare: fine-grained model at same scale would be 60-80+ streams

What Adding a New Feature Looks Like

  • "I need to send animation events to audio" → Add a Kind variant to SimToAudioFrame composite struct. No new stream.
  • "I need physics debug viz in the renderer" → Add fields to SimToRenderFrame. No new stream.
  • "I'm adding a NetworkPU" → Add 2-3 new streams (Frame/Event per direction needed). New PU = new streams. This is correct.
  • "This stage needs a stage-scoped audio mixer" → Add a stage ServiceStream in the stage manifest. 1 new stream.
  • "I need per-frame data from Audio to Main" → New PU-pair direction. 1 new FrameStream. Rare.
