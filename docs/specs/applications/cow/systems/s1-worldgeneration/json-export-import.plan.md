## Implementation Patterns

Decisions made at plan time; check against the real code before marking tasks Done.

**Schema v1 (the spec's JSON example plus these decisions).**
- Top level: `format` = `"cow.world"`, `version` = 1, `provenance`, `world`.
- `provenance`: `seed` (unsigned integer, exact to 64 bits), `generator_version`, `rules_version`, `preset_id` (string, empty when none or modified), `params` (the 20 `WorldShapeParams` keys in camelCase exactly as the shape params/preset files name them; `barrierForm` is `"Plateau"`/`"VolcanicChain"`).
- `world`: `topology` (`"hex_flat_odd_q"` only), `dimensions {width,height}`, `main_landmass`, `cells[]`, `regions[]`, `region_table {absorbed_cells, fragment_cells, limited_by}`, `sites {<kind id>: [ {cell, region, variant, flags} ]}`.
- Cell: `biome` (`Biome.*` ids from `BiomeId`), `terrain` (`TerrainTypeName`), `region`, `elevation`, `latitude` (floats written `%.9g`: 9 significant digits round-trips any float exactly), `water_source`, `depth_zone`, `landmass`, `terrain_flags`, `downstream` (0..5 or 7). All ten fields are required.
- Region: `id`, `zone`, `landmass`, `is_island`, `primary_biome`, `purity`, `cell_count`, `centre_cell`, `neighbours[]` (ids). `id` must equal index + 1.
- The writer is hand-emitted text (not `Json::StyledWriter`): fixed key order, one cell per line, `\n` newlines, no trailing spaces, so the same world always exports byte-identical text and diffs are readable.
- The reader uses jsoncpp strict mode with duplicate keys rejected and a text size cap (16 MiB) checked before parsing.

**Kind names.** `Site` stores only `kindCrc`. Export resolves a name from, in order: the four built-in node kinds, the registry's `SiteKindInfo`, a name table kept in `SiteSet` (filled on import for kinds nobody registered), else the fallback key `crc:xxxxxxxx` (lower-case hex), which import parses back to the exact CRC. The name table is excluded from `SiteSet::operator==` and cleared by `Clear()`. Unknown kinds therefore round-trip with their original text.

**Derived region fields.** `FinishRegions` computes `cellCount`, `primaryBiome`, `purity`, `centreCell`, `neighbours` from the written cells. That block is extracted into one function, `RecomputeRegionRecords(WorldStructure&)`, used by both `FinishRegions` and import, so import recomputes with exactly the generator's arithmetic (any divergence would break byte-identical round trips). A file value that differs from the recomputed one is logged at Info and listed in the import warnings; the recomputed value wins. `absorbed_cells`, `fragment_cells`, `limited_by` come from the file (not derivable from cells). `mainlandRegionCount` is derived (non-island regions).

**Validation (all-or-nothing).** Import parses and validates into a scratch `WorldStructure`; the caller's world is touched only on success. Errors are structured `{field, message}` (first error wins; message names the JSON path, e.g. `world.cells[17].elevation`). Checked: format/version (`"Unsupported cow.world version: 2"`), topology, dimensions (1..256 each, at most 65,536 cells), cell count, every cell field present/typed/in range/known enum, floats finite and in [0,1], `downstream` in {0..5,7}, `terrain_flags` <= 63, region ids <= region count, `regions[]` ids contiguous from 1, neighbours reference existing regions, site cells in bounds, site `region` <= region count, `variant`/`flags` fit uint16, no duplicate (kind, cell). Warnings (import succeeds): no water cell, region with no cells, summary mismatch, site region differs from its cell's region, unknown fields, `rules_version`/`generator_version` differ from this build, unregistered site kind. The spec's "throne count == 6 / PLAYER dynasty start" checks are dragon-layer (2026-10-18 amendment) and are not built; Reachability validation is not run on import (spec open question 3: permissive).

**Files.** Worlds live in `<out>/worlds/<name>.wld.json` (writable, PD-009: `Cluiche/out/CoW/worlds`) and read-only `<deployed>/worlds/` if configured. `name` must match `[A-Za-z0-9_-]{1,64}` (no separators, so no traversal); the extension is added by the code. Export default name = the seed. Export refuses to overwrite unless `overwrite:true`. Write is atomic: temp file in the same directory then rename (replace). Import looks in out first, then deployed. Files over 16 MiB are refused before reading into memory.

**Session integration and the lock (SD-S1-009).** `WorldGenSession::ExportWorld/ImportWorld` wrap the pure functions. Import applies seed, shape, dimensions and preset id from `provenance`, replaces `mWorld`, marks `mRegionsFresh` when the file has regions, sets `mState` Complete, bumps the revision, clears `mDirty`, and sets `mLocked`. While locked, `Set`, `SetSize`, `PresetLoad` and `Regenerate` refuse with `{success:false, error:"locked", locked:true, needsConfirm:true}` unless the args carry `unlock:true`, which drops the lock and applies the action (regenerate from the recorded provenance plus any changes; the hand edits are gone). `Regenerate{unlock:true}` with no other change reproduces the un-edited world. The generator's layer buffers cannot be reconstructed from cells, so import calls `TerrainGenerator::ImportLayers(world)`: it fills the layers derivable from cell fields (elevation, latitude, waterSource, terrainType, depthZone, landmass, terrainFlags, flowDirection, biomeIndex) and zeroes the rest, and invalidates the stage cache so the next live preview regenerates everything. `Params().effective` is then marked `imported`.

**Commands (module).** `cow.worldgen.export {name?, overwrite?}` and `cow.worldgen.import {name}`: file names only (the 64-char arg cap is fine), files carry the data. Replies: `{success, name, path, bytes, warnings[]}` (export), `{success, name, revision, locked:true, warnings[], error{field,message}?}` (import). Module config keys `worlds_dir` (deployed) and `out_worlds_dir`.

**Tests.** `TestWorldJson*.cpp` for pure export/import, `TestWorldFiles.cpp`, `TestWorldGenSessionImport.cpp`, `TestWorldGenModuleImport.cpp` (real SimQuery round trip, as the other module tests). Helpers in `Testing/WorldJsonTestWorlds.h` (hand-built small worlds with every enum value, a test site kind, unknown kind). Goldens: the exported text of a fixed hand-built world, and a hash of the exported text for the default seed (regenerate deliberately if the generator changes). SLOW_ sweep: 20 seeds x 4 presets round trip. Scoped runs: `dia run googletest --filter="*WorldJson*:*WorldFiles*:*Import*:*Region*:*Site*:*WorldGen*" --shards 2`; one full run in the last task.
