## Implementation Patterns

### Registry (Tasks 1 to 10)
- New directory `Cluiche/CoW/Shared/World/` (it does not exist yet; the kit also uses it). Files: `BiomeRegistry.h/.cpp`, `Testing/BiomeTestRegistry.h`. Namespace `CoW::World`. Added to `CoW.vcxproj(.filters)` with `dia docs vcxproj-add CoW`, never by hand.
- The API is exactly the spec's: `BiomeIndex = uint8_t`, `kNoBiome = 0xFF`, `BiomeRole { Ocean, Lake, Fallback }`, `PinRule { WaterOcean, WaterLake, Vent, Alpine, Wetland }`, `ClimateEnvelope { float t0, m0, wt, wm; }`. `TagId` is a `uint8_t` index into a vocabulary of at most 64 tags (`uint64_t` `TagMask`); `FindTag(StringCRC)` returns `kNoTag` for an unknown tag. The `DepthZone` enum (`TerrainEnums.h`) stays; zone validity is a per-biome `uint8_t` zone bitmask.
- Storage is fixed-size and PD-004 safe: rows in `Dia::Core::Containers::DynamicArrayC<Row, 254>`; `Row` holds `StringCRC id`, `String64 idText`, `String64 name`, `String256 description`, `uint32_t colour`, `uint64_t tagMask`, `uint8_t zoneMask`, `bool generated`, `bool hasClimate`, `ClimateEnvelope climate`, `PinRule pin`, `int pinPriority` (`-1` = none), `int8_t plateau` (`-1` none, `0` dry, `1` wet). The forbidden relation is a `uint8_t[254][32]` bit matrix, written symmetric at load. `ClimateBiomes()` and `PinsByPriority()` return pointer-and-count over arrays built at load (row order, and priority-descending). `Hash()` is FNV-1a 64 (the same scheme as `ParameterFile::Hash`, with `-0.0` normalised to `+0.0`), computed once in `Load`, over the row-order bytes of **only the fields that change classification or identity**: id, tag mask, zone mask, generated, climate, pin rule and priority, plateau, roles, and the forbidden matrix. Name, description and colour are excluded, so a cosmetic edit does not make every old world warn on import (audit 2026-11-20; confirm in Open item 7).
- `Load(path, err)` takes `RegistryError { String32 field; String64 id; uint32_t row; String256 reason; }`. It is all-or-nothing: parse into a **heap-allocated** candidate `BiomeRegistry` (a row is about 450 bytes, so 254 rows plus the matrix is about 120 KB, too large for the stack), validate everything, then swap into `*this` (the class needs a cheap swap or move, defined in Task 3). On failure `*this` is unchanged (empty on a first load). Strict faults are the spec's list: wrong `format`/`version`, sidecar validation failure, duplicate id, unknown tag or zone, forbidden pair naming an unknown id or listed twice (either order) or self-paired, a role held by 0 or more than 1 row, two pins with one priority or an unknown pin rule, climate width <= 0, two rows with the same plateau value, more than 254 rows. Plan Task 1's spike decides the parse route: `JsonDefinitionLoader` with `DIA_SERIALIZE` (spec ODQ 2, resolved), or a small hand parser over `Json::Value` validated against the same sidecar. In the fallback case, log the gap against DiaData in the Task 1 notes and do not bend the file shape.
- `ResolveOrFallback(StringCRC)` keeps a small `DynamicArrayC<StringCRC, 64>` of ids already warned about (per registry instance), and calls `DIA_LOG_WARNING` once per distinct unknown id. The spec says channel `WGEN`; the S-1 code today logs on channel `"CoW"` (`GenerationRun.cpp`, `WorldGenerationModule.cpp`). Task 0 records which one to use (see Open items). `Find`, `IsValidInZone`, `AreForbidden` and `HasTag` do not log.
- `Cluiche/CoW/Shared/World/Testing/BiomeTestRegistry.h` (ships with the library, PD-009 and the `Testing/` rule):
  - `const BiomeRegistry& ShippedBiomeRegistry()` loads `Assets/CoW/Global/World/biomes.json` once per process, through the same path resolution the other CoW tests use for assets (Task 0 confirms the helper).
  - `BiomeIndex B(const char* id)` asserts the id exists.
  - `ExtraBiomeRegistry()` loads the data-only-proof fixture (`Cluiche/Tests/GoogleTests/CoW/Fixtures/biomes_extra.json`, the shipped rows plus one appended climate biome). Fixtures live beside the tests, not in `Assets/`.

### Dia: `valuesFrom` and `data.incomplete-map` (Tasks 11 to 16)
- `Dia/DiaValueSchema/ValueInfo.h` gains `struct ValuesFrom { String64 format; String64 records; String64 id, label, colour, description; }` and a `bool mHasValuesFrom` on the `enum` entry. `ValueSchemaLoader.cpp` parses and validates the object shape; an `enum` entry with both `values` and `valuesFrom`, or neither, is a loader error naming the entry.
- `ValueSchemaModule` resolves `valuesFrom` before publishing: it looks the data file up by format through the catalogue, reads the `records` array, and fills `values` in record order from the `id`, `label`, `colour` and `description` fields. A missing file, record path or field puts the module in health Error naming the entry. Task 0 confirms how the module reaches the catalogue (and whether the registry may be read before `WorldGenerationModule` has started; see Open items).
- CLI: `Dia/DiaCLI/dia_cli/commands/validate/schema_rules.py` resolves `valuesFrom` the way `ref` is resolved (data documents are already indexed by format). `data_rules.py` gains `data.incomplete-map`: a `map` entry with a `keyRef` whose schema `default` omits a resolvable key reports the missing keys. Packs under `Packs/` are exempt. Pytest cases go beside the existing ones in `Dia/DiaCLI/tests/`.
- Conformance fixtures live in `Dia/DiaValueSchema/Testing/Conformance/` and are shared by C++ and the CLI. Cases: `valuesFrom` ok; missing file, record path, `id` field and `label` field; both `values` and `valuesFrom`; `incomplete-map` default (fails); a sparse pack over the same map (valid); complete default (valid). The parity test asserts C++ and the CLI agree on every fixture. `ParameterFile` already fails on a map default missing a key (Parameter Files AC 6), and the conformance test covers it too.

### S-1 production switch (Tasks 21 to 27)
- The registry is passed explicitly: `const CoW::World::BiomeRegistry*` is added to the existing input structs (`BiomeClassifyInput`, the region repair and partition inputs, `WorldGenSession`'s config, export and import contexts), and `WorldGenerationModule` owns the one instance. No singleton, no `GetStatic` (feedback_no_singletons). Task 0 lists the exact structs.
- `TerrainTypes.h`: `Cell::biome` becomes `BiomeIndex`. `BiomeTypes.h/.cpp` is removed if nothing is left, or reduced to the `BiomeIndex` alias include. Per-biome arrays are sized from `Count()` (heap arrays as `DynamicArrayC<..>` or a `Count()`-sized member; the old `[kBiomeCount]` stack arrays go).
- Classification: pins run over `PinsByPriority()`. Each pin's terrain test stays in code, in one `switch (PinRule)` inside `BiomeClassify.cpp`, and the biome it produces comes from the row. Climate scoring iterates `ClimateBiomes()` with `Climate(b)`; ties break by the lowest row index (the old list order). The plateau rule uses `Plateau(true)`/`Plateau(false)`. Region repair uses `Role(Ocean)` and `Role(Lake)`. Both hard-coded 5-biome lists (`BiomeClassify.cpp:25`, `WorldGenSession.cpp:1677`) are deleted.
- Interim bridge used only while tests migrate (Tasks 17 to 20): `Cell::biome` is still the `Biome` enum, and the registry's row order equals the enum's order. Migrated tests use `B("Biome.X")` (a `BiomeIndex`) and compare through a tiny test helper `Idx(Biome)` (`static_cast<BiomeIndex>`). A temporary test `RowOrderMatchesLegacyEnum` proves registry index == enum ordinal for all 13 rows. Task 27 deletes the enum, the test and `Idx`.
- Goldens: `Cluiche/Tests/GoogleTests/CoW/Golden/worldgen_layers.golden.json`. Never run with `DIA_UPDATE_GOLDEN`. A hash mismatch is a stop-and-report event, never a re-baseline.

### World files (Task 25)
- `WorldJson.cpp` writes ids with `IdText()`. `provenance` gains one additive field, `biome_registry_hash` (hex string of `Hash()`), written beside `generator_version` and `rules_version`. `WorldJsonImport.cpp` resolves each biome id through `ResolveOrFallback`. On a hash mismatch (field present and different) it logs one Warning and continues. A file without the field imports silently (older exports). The format `version` is not bumped (the field is additive); Task 0 checks `json-export-import.md` for the compatibility rule.

### Terrain profile (Tasks 30 and 31)
- Maps added to S-1's parameter sidecar (from Parameter Files; `Global/WorldGen/terrain_rules.schema.json`): `terrain.passable` (bool), `terrain.cost` (float, [1, 16]), `terrain.soil_depth_mult` ([0, 4]), `terrain.orographic_factor` ([0, 4]), `terrain.runoff` ([0, 1]), each keyed by every `TerrainType` id with the spec's defaults. The first two take today's `terrain_navigation.json` values.
- The key source is a `TerrainTypeMapKeys : IMapKeySource` in `TerrainRules.h/.cpp`, built from the `TerrainType` ids (enum order). `ParamBinding<T>::BindMap` (Parameter Files Task 23a, AC 20-21) binds maps into arrays; Task 31 uses it when that plan is Done and otherwise reads the maps by name from `ParameterFile::Values()` once, when the table is built for a world, copying them into its own `float`/`bool` arrays. Hot loops read those arrays (see Open items 3 and 4).

### Logging, metrics, health
- Channel: confirm in Task 0 (spec says `WGEN`). Info on a successful load (row count, hash), Error on a failed load (row, id, field), Warning from `ResolveOrFallback`. `WorldGenerationModule` health: Error, naming the field, when the registry fails to load, and generation refuses to run (same pattern as the parameter sidecar failure from Parameter Files AC 19). No new metrics here (see the Observation scan task).

### Testing
- New files under `Cluiche/Tests/GoogleTests/CoW/`: `TestBiomeRegistry.cpp` (suite `BiomeRegistry*`), `TestBiomeRegistryLoad.cpp` (suite `BiomeRegistryLoad*`, the strict-load fault table), `TestBiomeRegistryData.cpp` (suite `BiomeRegistryData*`, the shipped file), `TestBiomeDataOnly.cpp` (suite `BiomeDataOnly*`), `TestBiomeLiterals.cpp` (suite `BiomeLiterals*`, the grep test), `TestTerrainProfile.cpp` (suite `TerrainProfile*`). Dia tests go in `Cluiche/Tests/GoogleTests/DiaValueSchema/` (suite `ValueSchemaValuesFrom*`, `ValueSchemaConformance*`; Task 0 confirms the folder name).
- Strict-load faults are table-driven: one `struct { const char* json; const char* expectedField; uint32_t expectedRow; }` row per fault, inline JSON, so a new fault is one row.
- Tie-order, pin-order and plateau tests use small hand-built grids from `Testing/BiomeTestGrids.h` and the fixture registry. Determinism checks use `memcmp` over the arrays.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<the suites under work>" --shards 2` (always `--shards 2`). The feature scope `--filter="*Biome*:*WorldGen*:*WorldJson*:*Region*:*Navigation*:*Reachability*:*ValueSchema*:*TerrainRules*:*TerrainProfile*"` runs only in the verification task, plus CLI `pytest` for `validate`.
- No full suite per feature (the full suite runs once at the stack close-out). No sanitizer. No mutation checks. Perf is a Debug ballpark only. World-sim verification uses cell data and stats, not screenshots (the layer goldens are the cell-data check).
- The S-1 E2E scenario (`Cluiche/Tests/E2E/scenarios/cow/s1worldgen`) runs once, in the verification task, because the registry touches the module start path. E2E does not build; build first (feedback_dia_run_gotchas).

### Confirmed biome tag assignment (GDD-confirmed 2026-11-18, CoW/GDD session)

These are confirmed against the locked GDD. Two rows changed from the draft: Wetland gains `aquatic`, and Volcanic loses `mountain` and gains `hot`. The 12-tag vocabulary is unchanged. Volcanic `hot` is the GDD session's inference ("opposite temperature extremes", GeographyAndRegions), and the user may override it.

|---|---|
| Ocean | water, aquatic |
| Lake | water, aquatic |
| GrasslandSteppe | land, open, fuel |
| TemperateForest | land, forest, fuel |
| WetlandDelta | land, wet, aquatic |
| DesertBasin | land, open, hot |
| AlpineMountain | land, mountain, cold |
| TundraBoreal | land, open, cold |

**Tag meanings** (GDD-derived; these go into the sidecar's tag vocabulary descriptions):
- `water`: aquatic-only cells that land species cannot enter (Ocean, Lake).
- `aquatic`: aquatic species can live here (water biomes, and Wetland per A1 TechSpec section 15.1).
- `fuel`: **this biome has a fire-succession rule to BurnedAshland** (A3 sections 4.1/4.2: Grassland, TemperateForest, Scrub). It does **not** gate ignition or spread. A1 natural ignition is per land cell with fuel = grass + shrub + tree biomass (A1 TechSpec section 15.9). "Can this cell burn?" is answered by `land` plus biomass, so Rainforest and Wetland can still burn rarely.
- `mountain` and `volcanic` are distinct (B2 hard-block matrix keeps them separate).
- `coastal` is not a tag (it comes from neighbouring cells, `coastal_reach`). `fertile` is not a tag (it is the per-cell `nutrient.soil` pool, DECISION-137).
