This plan builds the pure, steppable `GenerationRun` (one attempt per `Step()`), an observer seam where Feature 5 plugs in an abort check, and runs it to completion inside `WorldGenSession::Tick` (as terrain generation already runs). `GenerationOutcome` keeps all five values so the report shape is final; only `Success` and `Unsatisfiable` are produced here. ## Implementation Patterns

Decisions made at plan time; check against the real code before marking tasks Done.

**Where the loop lives.** `GenerationRun` (CoW-Shared, `GenerationRun.h/.cpp`) is a pure object: inputs are the fixed terrain `WorldStructure` (terrain + biomes, regions/sites empty), the `SiteRegistry`, `TerrainRules`, the outer seed, `GenParams`, the WLD `RandomStream` and an optional `IGenerationObserver`. `Step()` runs exactly one attempt: copy the terrain, `RegionsAndSites::Place(copy, registry, rules, DeriveSubSeed(outer, attempt), attempt, rng, &report)`, then `ReachabilityValidator::Validate` and record. `Run()`/`GenerateWorld()` loop `Step()` until finished (headless and tests). The module's `GenerateWorld(seed, params)` of the spec maps to `WorldGenSession::Regenerate` + `Tick` (the session owns terrain generation); there is no second entry point.

**Guarantees and profiles per attempt.** Validation uses `SiteRegistry::Guarantees()` (registration order) followed, last, by a `WorldLayoutGuarantee` built for this attempt from `PlaceReport::limits` (it needs the limits, so it cannot be registered once). One `TerrainTableNavigationProfile` is injected so `Validate` does not fail on an empty profile list. `DefaultValidationSet` is NOT used (its throne guarantee fails on every S-1 world; the dragon layer registers its own kinds and guarantees). An app that registers a guarantee with `WorldLayoutGuarantee`'s id gets a duplicate; the run skips its own layout guarantee when the registry already holds that id.

**Failure classification (SD-S1-008).** Place returns `Retryable` -> attempt recorded failed (placer reason in the record), loop continues. `TerrainCause` -> the run ends `Unsatisfiable` at that attempt with the reason; no retry. Validation failure -> retry, unless a failed guarantee's diagnostic contains `(terrain cause` (the marker `WorldLayoutGuarantee` and the throne guarantee already emit) -> `Unsatisfiable` immediately, `terrainCause = true`. A terrain-caused stop at attempt 0 leaves exactly one attempt record.

**Sub-seeds.** `DeriveSubSeed(outer, attempt)` (the existing splitmix mixer, already used by Place; the spec's additive suggestion is the fallback it names, and Open Q 3 resolves to hash-based because attempt 0 must keep reproducing the Regions-plan goldens). AC5 distinctness is tested for attempts 0..9 over many outer seeds.

**GenParams.** Minimal local struct `GenParams { uint32_t maxRetryAttempts = 10; }` (placeholder default per Open Q 1, tuned by AC3 measurement, not before). `0` is clamped to 1 (at least one attempt); an upper clamp of 64 bounds report size. Session holds it; `regenerate` accepts `maxRetryAttempts`; module config `max_retry_attempts`. Not a WorldShapeParams slider and not part of the preset.

**Report.** `AttemptRecord` is trivially copyable: attempt, subSeed, passed, terrainCause, placeCode + `char placeReason[96]`, `failedGuarantees[kMaxValidationGuarantees]` (CRC values) + count, up to `kMaxAttemptDiagnostics = 4` diagnostics (`Diagnostic`, 160 chars each) + dropped count, `elapsedMs`. `GenerationReport` = outerSeed, outcome, maxAttempts, `std::vector`-free attempts via `EvidenceList<AttemptRecord>` (the Feature 2 pattern), `ValidationResult finalValidation`, worldRevision. `SameApartFromTiming(a, b)` compares everything except `elapsedMs`. Replaced wholesale per generation; report revision increments per finished generation.

**Session behaviour on failure (deviation from AC7, needs the user).** Terrain is generated into the session's world before the loop (unchanged). On `Success` the accepted copy replaces the world, revision increments, `Complete`. On `Unsatisfiable` the world keeps the freshly generated terrain with regions and sites cleared (`regionsFresh = false`), the revision still increments (the visible world did change), state is `Failed`, `report.worldRevision == 0`, and `WorldGenerationComplete` is not published. AC7's "`GetWorldRevision()` unchanged" is Feature 5's discard-and-keep-previous behaviour and is asserted at the `GenerationRun` level (no accepted world) only.

**Retry never runs on live preview.** Only the Regenerate path calls the run; live preview keeps clearing regions/sites. Unchanged.

**Telemetry.** `DIA_LOG_INFO("CoW", ...)` on success with attempt count; `DIA_LOG_WARNING` per failed attempt with the failed guarantee ids and first diagnostic; `DIA_LOG_ERROR` on exhaustion with attempt count. Logs live in `GenerationRun` so headless and module runs share them. Module: counters `cow.worldgen.attempts` and `cow.worldgen.unsatisfiable`, a `WorldGenerationRetry` bus event per failed attempt (small POD), `retryAttempts` in `WorldGenerationComplete`, health `SetFailing("generation_unsatisfiable")` after an exhausted run and back to OK on the next success.

**Feature 5 seam.** `IGenerationObserver::ShouldAbort()` is polled at each attempt boundary and returns false by default; nothing sets it yet. `OnAttemptFinished(const AttemptRecord&)` feeds progress.

**Commands.** `cow.worldgen.report` (query) returns the last report: outcome, maxAttempts, attempts[] {attempt, subSeed, passed, terrainCause, failedGuarantees[], diagnostics[], placeReason}, worldRevision, reportRevision. `status.generation` carries the one-line summary. Both are served from the SimPU-hosted session, so they use the existing EventStream request/reply pattern.

**Build wiring.** `dia docs vcxproj-add CoW "Shared\WorldGeneration\X.h" --filter Shared` (+ .cpp); `dia docs vcxproj-add GoogleTests "..\..\CoW\Shared\WorldGeneration\X.cpp"` and `dia docs vcxproj-add GoogleTests "CoW\TestX.cpp"`; check both `.filters` for a bogus `..` folder. Scoped runs: `dia run googletest --filter="*Generation*:*Retry*:*WorldGen*:*Region*:*Validat*" --shards 2`.

**Test tiers.** Default run: hand-built cases with test placers/guarantees, cheap seed subsets. 100-seed success-rate sweeps (AC3, system Test 1a/1b) in `SLOW_` suites per preset; thresholds there are tuning-gated: report numbers, do not tune.
