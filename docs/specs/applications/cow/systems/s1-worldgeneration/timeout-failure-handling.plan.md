This plan fills them in, steps a Regenerate one attempt per SimPU frame, adds `cow.worldgen.cancel`, and closes the Retry AC7 gap (a failed generation keeps the previous world).

## Implementation Patterns

Decisions made at plan time; check against the real code before marking tasks Done.

**Where the checks live.** `GenerationGuard` (CoW-Shared, `GenerationGuard.h/.cpp`) is a pure `IGenerationObserver`: a wall-clock budget (`timeoutSeconds`) read through an injectable `IGenerationClock`, plus a cancel flag. `ShouldAbort` checks Cancel first, then `elapsed > timeoutSeconds` (strict), exactly the order in the spec's state machine. Tests inject a fake clock (advanced by hand or by the test placer), so no test sleeps. Production uses a `steady_clock` implementation. Granularity is one check per attempt boundary (Open Q 2 stays "coarse"): an attempt that overruns the budget finishes, then the next boundary reports Timeout.

**Cancel flag thread-safety.** The spec asks for a `std::atomic<bool>`. All `cow.worldgen.*` commands are sim-hosted (executed on the SimPU by `SimQueryHostModule`), so `cancel` runs on the same thread as `Tick`; the guard keeps a plain `bool` and the session is single-threaded by construction (PU boundaries are streams). No cross-thread flag exists to protect. The spec's `WorldGenerationCancelled` bus event and `CancelGeneration()` are replaced by the `cow.worldgen.cancel` command (SD-S1-002: every action is a DiaAPI command) — recorded as a deviation.

**Errors.** `GenerationRun::Step` catches `std::exception` (and `...`) around the attempt (Place + validate) and ends the run `Error` with `FAILURE: <what>`; the session also catches around terrain generation. SEH/hardware faults are not caught.

**Outcome messages and logs.** `GenerationReport::failureMessage[128]` holds the distinguishing text (deterministic: the timeout text uses the budget, not the measured elapsed time): `TIMEOUT: World generation exceeded N.N seconds`, `FAILURE: World generation failed after N attempts (unsatisfiable seed or parameters)`, `FAILURE: World generation error: <what>`, `CANCEL: World generation cancelled by user`. Log levels: TIMEOUT/FAILURE error, CANCEL info. `FailureReason { TIMEOUT, UNSATISFIABLE, ERROR, MANUAL_CANCEL }` and `WorldGenerationFailed { reason, seed, attempts, message[128] }` (trivially copyable) live in `WorldGenerationMessages.h`; `FailureReasonFromOutcome`.

**Stepping.** `WorldGenSession::Tick` no longer runs a Regenerate to completion in one call. The first Tick of a Regenerate generates the candidate terrain into a separate `TerrainGenerator`/`WorldStructure` (the accepted world and generator stay untouched), creates the `GenerationRun` and steps once; if the run is not finished it stays active (`WorldGenState::Generating`) and each further Tick steps one attempt. A run that succeeds on attempt 1 finishes in the same Tick, byte-identical to before. While a run is active, `Set`, `SetSize`, `PresetLoad`, `Regenerate`, `ImportWorld` and `ExportWorld` refuse with `{success:false, error:"busy", generating:true}`; `cancel` and every query stay available. A Cancel that arrives before the run starts drops the pending Regenerate (reverts the pending request to the accepted parameters) and records a Cancelled report.

**Keep the previous world (Goal 5a, Retry AC7).** The session tracks the accepted parameters (seed, shape, size, preset id/modified) and lock/imported flags. On Unsatisfiable, Timeout, Cancelled or Error with a previous world: the candidate is discarded, `mWorld`, the generator layers, revision, regions/sites/layout, lock and imported flags are untouched, the pending parameters revert to the accepted ones, the report records the failure (`worldRevision` 0), the report revision increments, and `Tick` returns false (`WorldGenerationComplete` is not published). State: `Failed` for Unsatisfiable/Timeout/Error; Cancelled returns to the previous state (a user action is not a failure). With NO previous world (the very first generation was a Regenerate) there is nothing to keep: the candidate terrain is adopted with regions and sites cleared, state `Failed`, revision increments (the interim Retry behaviour, unchanged).

**Telemetry.** Module: `WorldGenerationFailed` event, counters `cow.worldgen.timeouts`, `cow.worldgen.errors`, `cow.worldgen.cancels` (plus the existing unsatisfiable counter), health `generation_timeout` / `generation_error` / `generation_unsatisfiable` failing until the next successful generation; Cancel is not a health failure.

**Config.** `GenParams::timeoutSeconds` (default 30, clamped 0..3600; NaN -> default; 0 means "already exceeded at the first boundary"), module config `timeout_seconds`, `Regenerate{timeoutSeconds}`.

**Build wiring.** `dia docs vcxproj-add CoW "Shared\WorldGeneration\X.h" --filter Shared` (+ .cpp); `dia docs vcxproj-add GoogleTests "..\..\CoW\Shared\WorldGeneration\X.cpp"` and `dia docs vcxproj-add GoogleTests "CoW\TestX.cpp"`; check both `.filters` for a bogus `..` folder.
