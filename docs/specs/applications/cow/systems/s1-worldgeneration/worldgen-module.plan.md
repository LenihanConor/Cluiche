## Scope

**In:** a pure `WorldGenSession` (CoW-Shared) holding the terrain generator, the pending shape/seed/size and the revision; `WorldGenerationModule` (SimPU) driving it per frame with live preview; the 10 `cow.worldgen.*` terrain-slice commands registered as sim-hosted commands/queries; CoW app wiring (`SimQueryHostModule`, streams, DebugServer host) and the S-1 stage.

**Out:** `cancel`, `export`, `import`, `validate`, `report`, `regions`, `sites`, `select`, `view`; the panel, the CellField view; source-asset alias for `preset.save` (writes `Cluiche/out/CoW/presets/`).

## Implementation Patterns

Distilled from a code survey on 2026-11-08. Check against the real code before marking tasks Done.

**Layering (UI/business separation).** `WorldGenSession` (`Cluiche/CoW/Shared/WorldGeneration/WorldGenSession.h/.cpp`, namespace `CoW::WorldGeneration`) is pure logic with no Application, bus or DiaAPI dependency. Every command is one session method returning `Json::Value`. The module is wiring only: it owns the session, calls `session.Tick(rng)` once per `DoUpdate`, publishes the bus message when `Tick` reports a new revision, and registers handlers that forward to the session.

**Session semantics.** `Set/SetSize/PresetLoad` only mutate pending state and mark dirty (last value per key wins); `Tick(RandomStream&)` runs at most one `TerrainGenerator::Update` + `WriteTerrain` per call and returns whether the world changed (revision++). `Regenerate` sets a flag that makes the next `Tick` call `Invalidate()` first (optionally with a new seed). Queries read the session directly (handlers run on SimPU, so no locking). Clamp params with `WorldShapeParams::Clamp()`; report `applied`, `clamped` (value changed by clamp) and `rejected` (unknown key). Default size is Small 66x42, Standard 80x52, Large 104x64. Provenance preset id: set on `preset.load`, cleared by any `set` that changes a param. `locked` is always false in this slice (imports do not exist yet), but `set` still honours the `unlock` arg shape.

**Presets.** Use `WorldShapePreset.h` (`LoadPreset/SavePreset/ListPresets`, directory-path API). Deployed dir comes from module config (`presets_dir`, default `Cluiche/Assets/CoW/Global/WorldGen/Presets`); save dir is `Cluiche/out/CoW/presets` (PD-009). `presets` lists both dirs, the out/ copy wins on a duplicate id. The session takes both directories as constructor arguments so tests use temp dirs.

**Json.** `#include <DiaCore/Json/external/json/json.h>`; handlers always return an object; errors are `{"success": false, "error": "..."}`.

**Module pattern** (match `Cluiche/CoW/Modules/GameSpeedControllerModule`): `class WorldGenerationModule : public Dia::ApplicationFlow::SimModule`; `kTypeId`, `kAllowedPUs = PUAffinity::kSim`, `kDescription`; `OnConfigure(configJson)`, `DoStart` (return `kLoading` while a `ModuleRef` is null), `DoUpdate(const SimTimeContext&)`, `DoStop`; `DIA_MODULE(...)` and `DIA_DESCRIBE(...)` at the end of the .cpp (`<DiaApplicationFlow/RegistrationMacrosV2.h>`). ModuleRefs: `MessageBusHostModule`, `RandomStreamModule` (`GetWorldStream()`, the WLD stream), `Cluiche::AppFlow::SimQueryHostModule`. Bus: `bus.RegisterType<WorldGenerationComplete, 4>()` is already done by GameSpeedControllerModule (registering twice must be checked), `Broadcast(msg)`. Metrics `cow.worldgen.*` via `MetricRegistry`, health via a `HealthReporterBase` subclass registered in DoStart and unregistered in DoStop. Logging `DIA_LOG_*("CoW", ...)`.

**Sim-hosted registration** (match `Cluiche/CluicheGameBaseline/Modules/EntityInspectorModule.cpp` `RegisterHandlers`): `ModuleRef<Cluiche::AppFlow::SimQueryHostModule> mHost{this};` and `"SimQueryHostModule"` in the manifest dependencies. Register in `DoStart`: `host->RegisterCommand("cow.worldgen.set", help, handler)` / `RegisterQuery(...)`. `Dia::DebugServer::SimHelpInfo` needs `description`, `category`, `owner`, `params` (static `Dia::API::ValueParam[]`, `{name,type,required,description}`), `paramCount`. Help is mandatory or registration fails. Unregister in `DoStop` (handlers capture `this`). Name strings: confirm in Task 4 whether the registered name carries the `cow.worldgen.` prefix as written.

**Testing a sim-hosted command.** `Dia::API::ExecuteCommandJson` does NOT reach sim-hosted commands (it returns "command not found"; see `TestViewerSimHostedCommands.cpp`). The spec'd round trip is DebugServer -> `SimQueryRequest` EventStream -> `SimQueryHostModule` (SimPU) -> `SimQueryReply` -> DebugServer. Templates: `Cluiche/Tests/GoogleTests/DiaCellLayers/TestCellLayersIntegrationStreams.cpp` (real streams, `Harness`, `IntMainShim`, `Call(...)`), the smaller `Cluiche/Tests/GoogleTests/CluicheGameBaseline/TestSimAnnounceResyncIntegration.cpp`, and `Cluiche/Tests/GoogleTests/DebugServer/TestSimQueryHost.cpp` (host with fake source/sink). This replaces the system plan row 8b wording "via `ExecuteCommandJson` from a non-SimPU thread".

**Module fixture** (match `Cluiche/Tests/GoogleTests/CoW/TestGameSpeedControllerModule.cpp`): local `Fixture` struct; `TypeRegistry`, `ApplicationManifestV3` with one stage and a SimPU declaration, module factories as plain functions, pump `app->Update(1.0f/30)` until `GetState() == ModuleState::kActive`.

**CoW app gap.** `Cluiche/Assets/CoW/cow_main.diaapp` has no `SimQueryHostModule`, no `SimQueryRequest`/`SimQueryReply` streams and no DebugServer host. Task 4 adds them, modelled on `Cluiche/Assets/CluicheTest/Global/Misc/ApplicationFlow/cluiche_main.diaapp` (streams ~376-392, Main-side module ~659-665, SimQueryHostModule ~967-983). Stage touch points: `cow_main.diaapp` (stages + Boot transitions), `global.stage.json`, `Stages/<Name>/<x>.diastage`, `Stages/<Name>/misc/ApplicationFlow/<x>.diaapp`, `cow.diagame` import, `assets.catalogue.json` (two entries), `CoW.vcxproj(.filters)`. `dia scaffold stage` / the `new-cow-stage` skill does these; the skill also needs the testbed id in the `cow.md` Systems table and the GDD (`$COW_GDD_PATH` or `C:\GitHub\DesignDocs\COW`).

**Build wiring.** `dia docs vcxproj-add CoW "Shared\WorldGeneration\X.h" --filter Shared` (and `.cpp`); `dia docs vcxproj-add GoogleTests "..\..\CoW\Shared\WorldGeneration\X.cpp"` for each new Shared .cpp; module files `Modules\X.h/.cpp` in CoW; GoogleTests entries `CoW\TestX.cpp`. Check the `.filters` file after a cross-project add (known bogus `..` filter bug).

**Commands.** `dia run googletest --filter="WorldGen*" --shards 2`; never run the exe directly; scoped filters while iterating, one full run at the end.
