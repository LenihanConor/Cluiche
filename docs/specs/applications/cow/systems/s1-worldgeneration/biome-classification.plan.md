## Implementation Patterns

Distilled from a code survey on 2026-11-10. Check against the real code before marking tasks Done.

**Already in place (do not redo).** `WorldShapeParams::temperatureOffset/moistureOffset` (+ Clamp), `ShapeParam::TemperatureOffset/MoistureOffset`, `TerrainStage::Temperature/Moisture/Biomes`, `FirstStageAffected` mapping both sliders, `ParamChanged` cases, the session's slider table and preset keys (`WorldGenSession.cpp:52`, `WorldShapePreset.cpp:77`). `Cell` has NO `biome` field yet.

**Stage plumbing (`TerrainGenerator.h/.cpp`).**
- Add layer rows to `TERRAIN_LAYERS_TABLE` (one row = name, type, stage): `temperature`(Float, Temperature); `waterDistance`(UInt, Moisture), `airMoisture`, `rainOut`, `moisture`(Float, Moisture); `biomeScore`(Float), `biomePin`(UInt), `biomeIndex`(UInt), `fixupChanges`(UInt) at Biomes.
- `kImplementedStageCount` 12 -> 15. `kAllImplemented` is derived from it. Update `kStageReads` rows 12-14: 12 reads `{Elevation(4)... }` — careful: spec says stage 12 reads `elevation` (stage 9 Valleys) and `latitude` (stage 11): `StageBit(Valleys)|StageBit(Latitude)`. 13 reads `Valleys, Latitude, Classify` (waterSource/masks from Classify=10, ocean/lake/river). 14 reads `Temperature, Moisture, Classify, DepthZones, Barrier, Landmass(vent flags via volcanic)`. Stage 12/13 must NOT read each other, so `temperatureOffset` dirties 12 and 14 only and `moistureOffset` 13 and 14 only (AC9).
- Dirty propagation loop in `Update` already goes `s < kImplementedStageCount`, ordered, so a terrain change dirties 12-14 automatically.
- `RunStage` gets three cases calling free functions `ComputeStage12/13/14` (match the `ComputeStageN(rules, ..., layers, debug)` style of `TerrainDepthZones.h`). Add `BiomeClassifier` as the spec's thin owner (spec Public Interfaces) ONLY if it stays thin; the free functions stay the unit-test seam.
- `WriteTerrain` fills `Cell::biome` (`Cell::biome` is the `Biome` enum, added in task 1; the memset-then-memcpy pattern keeps it byte-deterministic). Water cells get Ocean/Lake ids.
- Existing tests pin 12 stages (`TestTerrainDeterminism.cpp:224`, `TestTerrainClassify.cpp:501`, `TestTerrainPresetShapes.cpp:316,339`): update them in the integration task, not before.
- File header comment `#pragma fp_contract(off)` on every new stage .cpp (golden/bit determinism).

**Rules.** `TERRAIN_RULES_TABLE` is X(name, default, min, max). Add every `k` constant from the spec (kLatCool, kLapse, kRiverPenalty, kMoistScale, kBandBlend, kAirDecay, kOrographic, kProximityMix, kRainBonus, kWetlandMaxElev, kWetlandMoist, kPlateauWet, kMaxFixupPasses) plus the 5x4 target table (`kT0_<Biome>`, `kM0_`, `kWT_`, `kWM_`; Grassland, TemperateForest, Desert, Tundra, Rainforest). `kPlateauInner` and `kVentRadius` already exist. Bump `kDefaultRulesVersion` and update `Assets/CoW/Global/WorldGen/terrain_rules.json` (the deployed copy; check for a second copy under `Cluiche/out`). Rules tests pin the count/version: fix them.

**Geometry.** Neighbours via `Dia::Pathfinding::HexTopology` (flat-top odd-q, directions 0..5; see how `TerrainDrainage.cpp` / `TerrainDepthZones.cpp` get neighbours and the cell centre). Wind upwind neighbours: eastward wind (westerly) = directions 2 and 3, westward (easterly) = directions 0 and 5 (spec). Confirm direction 0..5 geometry against `HexTopology` before coding; if 2/3 are not NW/SW, STOP and report (spec/code conflict).

**Wind sweeps.** Per spec stage 13: two independent sweeps over columns (west->east for westerly, east->west for easterly); each cell takes the sweep matching its band, blending linearly across +/-`kBandBlend` degrees at 30/60 deg (`deg = latitude * 90`). Within a column process cells in index (y) order; upwind neighbours are in the previous column so order inside a column does not matter. Water cells: air = 1. Ocean elevation is 0 so rise uses the stored `elevation` layer.

**Tie rules.** Lowest cell index, then lowest biome enum value, for every argmax. Candidate set for zone and forbidden fix-ups = the five climate biomes (+ WetlandDelta if the cell is wetland-eligible). Forbidden fix-up: lower pin re-picks; tie on pin -> lower `biomeScore` re-picks; then lower index. Changed cell never re-picks into a forbidden pair with current neighbours.

**Vent island exception.** Cells within `kVentRadius` hex steps of a vent keep VolcanicAshland in any zone. Vents: `Stage3Debug` has the chain vents; island vents are the `volcanic` layer bit 1, chain vents bit 2 (see backlog row, S-1 Terrain amendments). Read the real layer semantics in `TerrainLandmass.cpp`/`TerrainMountains.cpp` before using them.

**Test helpers.** `Shared/WorldGeneration/Testing/` already has `TerrainShapeChecks.h` and `TerrainSliderDriver.h`. New helpers go there: `BiomeTestGrids.h` (hand-built climate grid and ridge grid for AC7/AC8) and `BiomeChecks.h` (validity helpers shared with Feature 9: zone, forbidden pairs, wetland). Default run: goldens for fixed seeds + hand-built tables + a cheap seed subset; seed sweeps and the 200-change sequence are `SLOW_`.

**Build wiring.** `dia docs vcxproj-add CoW "Shared\WorldGeneration\X.cpp" --filter Shared`; for each new Shared .cpp also `dia docs vcxproj-add GoogleTests "..\..\CoW\Shared\WorldGeneration\X.cpp"` and check the `.filters` for the bogus `..` folder. Tests: `dia docs vcxproj-add GoogleTests "CoW\TestX.cpp"`. Run from PowerShell or with literal paths, never a bash loop.

**Commands.** `dia run googletest --filter="*Biome*:*Terrain*:*WorldGen*" --shards 2` while iterating (never the exe). One full run at the end only.
