# Plan: A5 Hydrology Data & Parameters (A5 Hydrology Feature 1)

**Spec:** @docs/specs/applications/cow/systems/a5-hydrology/hydrology-data.md
**Status:** Not Started
**System plan:** @docs/specs/applications/cow/systems/a5-hydrology/a5-hydrology.plan.md (row 1)

Rebuilt 2026-11-18 against the world-sim review amendment and the Spec-6 resolutions (parameters are schema-first, biomes come from the registry, packs are sparse `cow.hydro_params` documents). This feature is the types, the parameters and `HydrologySimulation::Initialise`, as pure logic on hand-built hex terrain: no module, bus or thread.

**What it needs, by task group (name plans, never task numbers):**
- Tasks 2 to 6 (types, plain parameter struct, test grids, `BasinCurve`, derivation) touch no foundation API except the `BiomeIndex` type. They can start once the Biome Registry plan has that type (or on a local alias if the user allows a throwaway shim; ask first).
- Tasks 7 to 13 (`Initialise`, filter, in-basin directions, topology, phase seed, basin kind) need the Biome Registry plan Done (`Count()`, `ResolveOrFallback`, the `BiomeTestRegistry` fixture) and the Grid Search Helpers plan Done (`MultiSourceSteps`, `ConnectedComponents`, `HexNeighbours`, `GridSearchScratch`).
- Tasks 14 to 18 (sidecar, strict load, packs, binding) need the Parameter Files plan Done (`ParameterFile`, `ParamBinding`, `IMapKeySource`, `SchemaHash`) and the Biome Registry plan Done (`keyRef cow.biomes`, map completeness).
- Soil capacity uses S-1's `terrain.soil_depth_mult`, which needs the Biome Registry plan Done (the terrain profile maps ship there).

`water-pipeline.plan.md` (Feature 2) starts after tasks 1 to 13 here are Done. Features 3 to 6 consume the types, the bound parameter struct, `RederiveCommitted()`, the `SavedField` list and `BasinKindOf`.

All code is CoW (application) under `Cluiche/CoW/Shared/Hydrology/`. No Dia edits (AD-001). Where a task could need more than sonnet it says "ask before escalating" (feedback_confirm_opus).

## Decision: who builds the static tables (binding on both plans)

Feature 1's own ACs 16 to 18 need the downstream index, the in-basin directions and the topological order (the cycle check is EC-14), so they are built here. Split:

| Piece | Built by | Where |
|---|---|---|
| Working basin set (tiny-depression filter), basin capacity `V(spillHeight)` | **Feature 1** | `Initialise`, `BasinCurve` |
| In-basin flow directions (steepest descent on bed, flood-fill fallback) | **Feature 1** | `Initialise` |
| Downstream index (with the in-basin override) | **Feature 1** | `Initialise` |
| Topological order over cells and basin nodes (Kahn, ties by ascending index) and the EC-14 failures | **Feature 1** | `Initialise` |
| Per-cell release rate `k`, trees grouped by terminal, largest-tree size | **Feature 2** | the empty `BuildRoutingTables()` seam |
| Cascade, passes, totals | **Feature 2** | `Step` |

Feature 1 leaves a private, empty `BuildRoutingTables()` called last in `Initialise`. Feature 2 fills it. `BasinCurve.h/.cpp` and `HydrologyDerive.h/.cpp` are created here (Initialise needs capacity and level); Feature 2 consumes them and adds edge tests. See Open item 1.

## Implementation Patterns

### Types (Task 2)
- `HydrologyTypes.h/.cpp`, namespace `CoW::Hydrology`. `HydrologyFields`, `BasinState`, `BasinRecord`, `HydrologyTerrain`, `enum class Passability`, `enum class RiverState`, as in the spec.
- **Biomes are `BiomeIndex`** (`CoW::World::BiomeIndex`, from the Biome Registry plan). `HydrologyTerrain::biome` is a `DynamicArrayC<BiomeIndex>`. Per-biome arrays are sized by the registry's `Count()`, never 13.
- Terrain gains two per-cell arrays the amended spec needs but does not list (Open item 2): `terrainType` (a `uint8_t` id of S-1's `TerrainType`) and `soilDepthMult` (float, copied from S-1's bound `terrain.soil_depth_mult[terrainType]`). The test builders fill them; Feature 3's `BuildHydrologyTerrain` is the production source.
- `isCrossing` keeps its spec name; it is the GDD's `is_protected` (the selector field is `terrain.is_protected`, see Open item 3).
- `HydrologyFields::Resize(n)` zero-fills and fully replaces (assign, never just resize). `BasinState::Resize(basinCount)` likewise. `HydrologyTerrain::IsConsistent()` is false for any wrong-length array, for `width * height == 0` and for a `BasinRecord` range past `basinCells`.
- **Saved-field list (AC 2):** a `static constexpr SavedField kSavedCellFields[]` and `kSavedBasinFields[]` in the shape the World-Sim Kit codec expects (name, kind `f32`/`u8`/`u16`, per-cell or per-basin, layer sidecar key `cow.hydro.layers/<field>`). Derived fields (`openWater`, `passability`, `level`) are not in it. `basin_count` and `world_hash` stay as extras (not fields). Biomes are saved through the kit palette, so `biome` is not a per-cell saved array here. The count is **recount at build** (the struct marks 16 per-cell arrays, hydrology-save.md says 15: Open item 4).
- No `std::` type in a public signature (PD-004).

### Parameters (Tasks 3 and 14 to 18)
- **Deleted from this feature:** the 43-row `ParamDescriptor` table, the `biome_table` row descriptors, `LoadHydrologyParameters`, `ApplyOverrides`, `SetParam`, `ToJson`, `DefaultHydrologyParameters` and the params hash. Nothing of that is written.
- `HydrologyParameters` is a plain struct: 43 scalar members (**recount at build** against the sidecar's `kind: parameter` entries), `int32_t` members for the whole-number kinds, plus three `BiomeIndex`-indexed arrays (`soilCapacity`, `infilRate`, `vegFactor`) sized by the registry `Count()` at construction.
- **Sidecar** `Cluiche/Assets/CoW/Global/Hydrology/hydro_parameters.schema.json` (`for: cow.hydro_params`) is the single source of kind, range, default and description. It carries:
  - the 43 GDD keys with their names, defaults and hard ranges (from the amended spec's table);
  - `int` kinds for `basin.min_cells`, `glacier.onset_years`, `glacier.check_week`;
  - the GDD tuning ranges as `bands` where they differ from the hard range (values read from the GDD `A5_TuningParameters.md`; band names are Open item 5);
  - top-level `constraints`: `routing.release_floor <= routing.release_ceil` and `freeze.threshold <= freeze.thaw_temp`;
  - three `map` entries, `hydro.biome.soil_capacity`, `hydro.biome.infil_rate`, `hydro.biome.veg_factor`, each `keyRef cow.biomes/biomes[].id` with a `default` object listing **every** registry biome (Ocean and Lake zero; the other rows from the spec table, mapped to registry ids: Open item 6).
- **No base file and no compiled fallback.** Runtime value = sidecar default, then packs in order, then `Set`. A load failure puts the module in Failing health with the key named and refuses to step (Feature 3 wires the health; this feature only returns the error).
- **Loading** goes through `Dia::Attribute::ParameterFile::Load` with an `IMapKeySource` over the registry. Packs are `Global/Hydrology/Packs/<id>.hydro.json`: sparse `cow.hydro_params` documents carrying `basedOn`. `ApplyPack` is lenient and atomic; `Set` is strict; `Hash()` replaces the params hash. This feature only tests A5's sidecar through those APIs; it does not re-test `ParameterFile` itself.
- **`ParamBinding<HydrologyParameters>`** binds every scalar member and every map entry. `Resolve` must report no unbound parameter and no unbound binding. `Snapshot` fills the struct including modifiers. Map columns into `BiomeIndex`-indexed arrays need whatever array or map binding the Parameter Files plan ships; Task 0 checks it and Task 18 stops if it is missing (Open item 7).
- **Unknown biome:** the registry's `ResolveOrFallback` gives the fallback row's `BiomeIndex`; there is no hard-coded `GrasslandSteppe` row and no local once-per-id log (the registry logs once per id).
- **Soil capacity** used everywhere is `soilCapacity[biome] * soilDepthMult[cell]`, computed once per cell at `Initialise` into a private `effectiveSoilCapacity` array and rebuilt on a parameter-snapshot change (Open item 8). `terrain.runoff` is **not consumed**: no field, no read.
- Shipped sidecar deploys through CoW `pipeline.toml`; the file is catalogued (`assets.catalogue.json`, alias `json.hydro_params_schema`) and resolved through `PathStore`. The `FileWatcher` reload wiring is Feature 3's.

### Test grids and test parameters (Tasks 3 and 4)
- `Testing/HydrologyTestGrids.h` (shipped with the library, shared with Feature 2): pure builders returning `HydrologyTerrain`: `MakeTwoLakesDryBasinRiver()`, `MakeTinyDepressions()`, `MakeDryBasinCrossedBySpillDirections()`, `MakeLakesOnlyWorld()` (and a variant with a non-lake basin), `MakeFlowCycle()`, `MakeSpillCellAboveSpillHeight()`, `MakeRiverLeavingFootprint()`.
- `MarkProtected(HydrologyTerrain&, corridorSiteCells, passCells, riverCrossesBarrierCells, fixedSiteCells)` is the test-side helper AC 14 tests (production assembly is Feature 3's `BuildHydrologyTerrain`; Open item 9).
- `Testing/HydrologyTestParams.h`: `MakeTestParameters(const BiomeRegistry&)`. **Until Task 18** it builds the struct from literals copied from the spec table (temporary, marked). **Task 18 replaces its body** with a load of the shipped sidecar through `ParameterFile` + `ParamBinding` and reruns every `Hydrology*` suite, so the literals do not survive as a second source of defaults.
- Terrain is built on the real hex layout (`HexTopology::NeighbourAt`) so odd and even columns are exercised. Grids stay under 12 x 8 unless a test needs more.

### Initialise (Tasks 7 to 11)
- `HydrologySimulation.h/.cpp`: class shell, owned `HydrologyTerrain` copy, working basin set, committed `HydrologyFields` + `BasinState`, `bool mInitialised`. `bool Initialise(const HydrologyTerrain&, const HydrologyParameters&, const BiomeRegistry&, String256& err)`. Everything is built into a local temporary and swapped in on success, so a failed call leaves the simulation un-initialised.
- Accessors: `Fields()`, `Basins()`, `Terrain()`, `IsInitialised()`, `WorkingBasins()`, `DroppedBasinCount()`.
- **`BasinCurve::Build(terrain, basin, depthScale)`** sorts the basin's cells by bed and keeps a cumulative volume array. `Capacity()` = `V(spillHeight)`; `LevelForVolume` is a binary search plus interpolation; `VolumeForLevel` its inverse. No allocation after `Build`.
- **`RederiveCommitted()`** (free functions in `HydrologyDerive.h/.cpp`): `level` from `volume`, `openWater` (Ocean 1; inundated `1 - iceFraction`; river `wetness.river_open_water * min(1, riverFlow / max(meanFlow, flood.min_flow))`; else 0), `passability` first match (Frozen, Deep unless `isCrossing`, Fordable, Wet, Dry; lake-only worlds as the spec). Feature 2 passes 7 and 9 and Feature 4's load call the same code.
- **Validation order:** sizes, flow directions 0..6, basin cell indices (in range, in exactly one basin), spill cell (in range, not in its own basin), `bedElevation <= elevation`, lake-only has only lake basins, then (after the filter and the direction override) the topological sort. The first problem is named in `err`.
- **Tiny-depression filter:** capacity `V(spillHeight)`; drop a basin when `cellCount < basin.min_cells` or `capacity < basin.min_capacity`, unless `isLake`. Dropped basins keep S-1's directions and are never inundated. The count is logged once at Info.
- **In-basin directions:** per real basin, the hop distance from the pit over footprint cells comes from **`MultiSourceSteps`** (seed = the pit, lowest bed with ties by lowest index, `passable` = in this footprint, over `HexNeighbours`). For each footprint cell: the in-footprint neighbour with the lowest bed strictly below this cell's; if none, the footprint neighbour with the smallest distance (ties by lowest direction index). Cells outside every real basin are untouched. Lake-only worlds skip the step. A footprint cell left `kUnreached` is a disconnected footprint, which the spec does not define (Open item 10); the task does not decide it.
- **Downstream index:** `kNoCell` for terminals; basin nodes are numbered `N + basinIndex`.
- **Topological order:** Kahn's algorithm, ready set a min-heap by index. Edges: cell to downstream, every footprint cell and every cell routing into the basin to the basin node, basin node to its spill cell. Fewer nodes out than in is a cycle: `err` names the first cell in it. Separate checks name "spill cell above spill height" and "river leaves footprint" first.
- **Seeding:** allocate and zero; on land `soilMoisture = init.soil_fraction * effectiveSoilCapacity[cell]`, `groundWater = init.ground_fraction * soil.gw_capacity`; lake basin `volume = capacity`, others 0; `iceFraction` 0; lake cells hold no land stores.
- **Determinism:** no hash-order iteration, no pointer-keyed containers; byte comparison with `memcmp`.

### ApplyPhaseSeed (Task 12)
- `void ApplyPhaseSeed(const float* coldness, const uint8_t* snowSurvivesSummer)`: per cell, N each; null `coldness` = 0; values clamped to [0, 1]. Lake `volume = capacity * lerp(1.0, spinup.lake_seed_cold, basinColdness)`, `basinColdness` the mean over the basin's cells summed in ascending cell order. Masked cells: `glacier = spinup.glacier_seed_max * coldness[cell]`, `snowYears = glacier.onset_years`, `glacierEligible = 1`. Ends with `RederiveCommitted()`. At `coldness == 0` the state is byte-identical to a fresh `Initialise`.

### `glacier.check_week` mapping (Open Design Question 3)
- Task 0 reads `kWeeksPerSeason` and `WeekOfYear` and records whether the GDD's "26" is index 25. Task 14 puts the decision into the sidecar description and a test constant. The sidecar range stays 1..52. Feature 2's glacier-counter task cites the note.

### Testing
- `Tests/GoogleTests/CoW/Hydrology/TestHydrologyTypes.cpp`, `TestHydrologyParameters.cpp`, `TestHydrologyInitialise.cpp`. Suite prefixes `HydrologyTypes*`, `HydrologyParameters*`, `HydrologyInitialise*` (all match `*Hydrology*`).
- Byte-identity with `memcmp`, not `==` on floats. Known answers are computed by hand in the test, not by the production helper.
- Table-driven: one loop over the sidecar's parameter keys (read from the loaded schema) makes the below-min and above-max cases, so no per-constant tests are written by hand.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<suite prefixes>" --shards 2` (always `--shards 2`). The feature-wide `*Hydrology*` filter runs only in the scoped-verification task. No full suite (the World Step weather-stack close-out owns it), no sanitizer, no mutation checks, no `SLOW_` suites here. Debug perf is a ballpark note only. World-sim results are verified from cell data and stats, not screenshots.
- One commit per task (code, tests and the plan row together).

## Open items

1. **`BasinCurve` and `HydrologyDerive` move into this feature.** water-pipeline.md lists `BasinCurve.h/.cpp` as new under Feature 2, but `Initialise` cannot derive `level`, `capacity` or full lakes without it; `HydrologyDerive` is named in neither spec. Both are built here (Task 5). Confirm and add to the Public API table.
2. **Terrain ingest omits `terrainType` and `soilDepthMult`.** The amended spec multiplies soil capacity by `terrain.soil_depth_mult[TerrainType]`, but "Grid and terrain ingest" in a5-hydrology.md and `HydrologyTerrain` in hydrology-data.md list neither a terrain type nor the multiplier, and say nothing about how A5 receives S-1's bound parameter value. This plan adds two per-cell terrain arrays (Task 2); confirm, and amend the ingest list and `HydrologyTerrain`.
3. **`isCrossing` vs `terrain.is_protected`.** Spec-6 resolution 4 renames the selector field, and the World-Sim Kit's coverage table still says `terrain.is_crossing`; hydrology-data.md still names the terrain member `isCrossing`. Confirm whether the C++ member is renamed.
4. **Saved-field count and ranges.** The struct marks 16 per-cell arrays saved; hydrology-save.md says 15. Biomes are now a palette, not a field. The kit takes each field's range from the layer sidecar entry, but Feature 5 ships only 8 layers; fields with no layer (`riverStore`, `meanFlow`, the counters, `snowYears`) need a hydro state sidecar range that no spec defines.
5. **`bands` naming.** The spec says GDD tuning ranges "may be recorded as sidecar `bands`", but gives no band names and the tuning values exist only in the GDD file, not in the A5 specs.
6. **Biome id mapping for defaults.** The per-biome table lists GDD/enum names (`GrasslandSteppe`, `WetlandDelta`, ...). The registry's ids are `Biome.Grassland`-style, and biome-registry.md shows only six of the 13. The mapping from the 13 table rows to registry ids is not written down anywhere.
7. **Map-column binding.** `ParamBinding<T>::Bind` takes a member pointer per key, so a runtime-sized, `BiomeIndex`-indexed array (the amendment's "snapshotted into `BiomeIndex`-indexed arrays") has no stated binding mechanism in parameter-files.md.
8. **Parameter-derived tables and live edits.** `params set` applies at the next `Capture`, but release rates, the flood `alpha`, effective soil capacity, capacity curves (`basin.depth_scale`) and the tiny-depression set (`basin.min_cells`, `basin.min_capacity`) are built at `Initialise`. Which keys are live and which are init-only is undefined, and so is who takes the snapshot and how it reaches `Step`.
9. **`MarkProtected` is test-side.** AC 14 tests an `isCrossing` builder, but production assembly is Feature 3's `BuildHydrologyTerrain`. Confirm the split.
10. **Disconnected basin footprint.** The in-basin direction rule assumes every footprint cell can reach the pit; the spec defines no behaviour when a footprint is not one connected region (a `MultiSourceSteps` cell left `kUnreached`).
