# Plan: A5 HydrologyModule & World Step Stage (A5 Hydrology Feature 3)

Rebuilt 2026-11-18 against the world-sim review amendment and the Spec-6 resolutions. The stage is now a thin `WorldStepStageBase` subclass; the old tasks that hand-built stage state, the mutation queue, the spin-up slot, the discard rule, parameter load and fallback, and message structs are gone. What stays is A5's own work: terrain ingest, the `Capture`/`Run`/`Commit` split on the simulation, sinks, influences, the input resolver, the snapshot, the coupled spin-up host, and the A4 provider.

## Implementation Patterns

### Use the foundation, never reimplement it
- **Stage skeleton:** `HydrologyStage` derives `WorldStepStageBase<HydrologySimulation, HydrologyEntry, HydrologyLatch>`. The base owns revisions, `mQueue` (128), `SpinUpSlot`, the hold token, the visit generation, promotion inside `Capture`, the discard rule, `WorldGenerationFailed` handling, the `DoStop` order, the health reporter and the metrics `cow.hydro.step_ms` and `cow.hydro.discarded_steps`. A5 writes only the hooks:
  - `ExtraReady`: a water input exists (source set, or a valid fixed driver).
  - `LatchInputs`: resolves the input view, fills sinks, then influences; returns false for an invalid view (replaces `mStepValid`).
  - `InitialiseSim`: ingest result; fails with a cause code (`kInitFailed`).
  - `ApplyEntry`: A5's four mutation kinds (`SetParam`, `ApplyPack`, `Reload`, `BiomeChange`).
  - `RunStep`: builds `WaterInput{.., week = WeekOf(day) % kWeeksPerYear}` and calls `sim.Run`.
  - `PublishCommit`: publishes `HydrologyUpdated{week}` after `sim.Commit` and `SetCommittedWeek`.
  - `OnStartExtra` / `OnStopExtra`: `SetHydrologyProvider(this, this)` and `SetWaterSource(&weather)` when a `WeatherModule` resolves; undone on stop.
- **Base-owned behaviour is proved once, in the kit's `FakeWorldStage` suite.** This plan adds one smoke test per base behaviour that A5 depends on (through the real `HydrologyStage`), and does not re-test the logic. Where an AC is entirely base behaviour (22, 23, 50, 56, 57 general half) the smoke test is the A5 evidence.
- **Parameters:** `ParamBinding<HydrologyParameters>` binds the sidecar `Global/Hydrology/hydro_parameters.schema.json` (authored by the `hydrology-data.plan.md` feature). Strict load through `ParameterFile`; there is no fallback and no `DefaultHydrologyParameters()`. A failed load puts the stage in `kFailing` with a cause naming the key. `ParamBinding::Resolve` coverage (no unbound parameter, no unbound binding) is asserted in a test here. Packs: `Global/Hydrology/Packs/<id>.hydro.json` (a sparse `cow.hydro_params` document carrying `basedOn`), applied lenient and atomic with `ApplyPack`. The Queue methods validate before enqueue by calling `ParameterFile::Set` / `ApplyPack` on a candidate (strict for set, lenient for packs).
- **Params command:** the module exposes `QueueParameterSet`, `ApplyPack`, `QueueReload`; the single `cow.hydro.params {set|get|list|reload|save_defaults}` command is registered by the hydrology-debug feature via `ParamCommandHelper` and `SimCommandSet`. No `cow.hydro.set_param`, no A5-local `ToJson`/`SetParam`/`Load*`/`ApplyOverrides`.
- **Biomes:** `BiomeIndex` from the registry; no `Biome` enum; per-biome arrays sized by `Count()`; unknown biome id resolves through `ResolveOrFallback`. Lake and ocean roles come from `Role(BiomeRole::Lake)`/`Ocean`, never named.
- **Searches:** wherever the module or builder walks basins or depressions (lake-only basin table for a version-1 world, depression checks) use `ConnectedComponents` / `PriorityFlood` from DiaPathfinding with a `HexNeighbours` adapter. No local flood fill.
- **Terrain profile:** soil capacity is `soil_capacity[biome] * terrain.soil_depth_mult[terrainType]`; `terrain.runoff` is read by nothing in A5 (a test asserts changing it changes no output). The ingest therefore carries the per-cell `TerrainType` and the `soil_depth_mult` values (read from S-1's terrain parameter maps through the `WorldGenerationModule` accessor).
- **Cell fields:** the module contributes its committed fields to `WorldCellFields` under slot `hydro` (the fields the layer sidecar `cow.hydro.layers/<field>` names, plus `hydro.basin_kind` with values `none`/`lake`/`dry`). Registered on `WorldGenerationComplete` (the kit rebuilds the registry then), read on SimPU only, committed state only.
- **Events:** `HydrologyUpdated { uint64_t week; }` is declared in `cow_worldsim.diagamemessages` and generated with `dia codegen messages`. There is no hand-written `HydrologyMessages.h`.
- **Names:** stage id `hydro`, participant id `cow.hydro`, layer ids `hydro.<snake_case>`, formats `cow.hydro_params` / `cow.hydro_state`, log channel `HYD`. Build names through `WorldSimNames.h`.
- **Health:** `Dia::Observation::HealthStatus` `kOK`/`kDegraded`/`kFailing`. Causes: Degraded `kBadProviderOutput`, `kInvalidOrDiscardedStep`, `kQueueFull`, `kSeedOnlyStart`, `kParamsMismatch` (set by Feature 4); Failing `kInitFailed`, `kNoWaterInput`, `kGenerationFailed`, `kParamLoadFailed`. There is no `kFallbackParams`.
- **Data I/O:** every A5 file and sidecar is catalogued, paths resolve through `PathStore`, and `FileWatcher` (dev builds only) calls `QueueReload`.

### Pure pieces (unchanged in intent)
- **`BuildHydrologyTerrain(const HydrologyTerrainSource&, HydrologyTerrain&, String256& err)`:** `HydrologyTerrainSource` is a plain struct of arrays (dimensions, elevation, bed elevation, flow direction, `waterSource`, `BiomeIndex`, `TerrainType`, terrain flags, corridor-site cells, Hearth/Nexus/world-throne cells, optional basin table, `hasBasinTable`). `isCrossing` (the protected-cell set, S-1's `terrain.is_protected`) is the union of corridor sites, `Pass`, `RiverCrossesBarrier` and the fixed-site cells. A version-1 source builds a lake-only table from lake membership (`ConnectedComponents` over lake-role cells), sets `basinsFromLakesOnly`, and reports it through an `out` flag so the module logs the one Info. The builder never logs.
- **`Capture`/`Run`/`Commit` on `HydrologySimulation`** (additive): `Capture(const HydrologyLatch&)`, `Run(const WaterInput&, IParallelExecutor&)`, `Commit()` (array swap), `SetCommittedWeek(uint64_t)`, `CommittedWeek()`, `Fields()`, `WorkingFields()`. `HydrologyLatch` holds a `HydrologyParameters` value (a `ParamBinding::Snapshot` result, not JSON) and pending `(cell, BiomeIndex)` edits. The biome array is part of the working set. `Step(in, exec)` becomes `Capture(neutral) + Run + Commit`; the water-pipeline tests stay unchanged.
- **`HydrologyRunner`:** `StepWeek` and `RunFixed(.., cancel)` (cancel checked between weeks only); the synchronous oracle and the spin-up body. `ApplyPhaseSeed` is the caller's job before the run.
- **`HydrologySnapshot`:** const view over committed state (accessor table in the spec). `SoilMoisture` divides by the effective capacity (biome capacity times terrain depth multiplier, the same helper the pipeline uses). `RiverState` uses the real parameter constants; the 0.7 low-flow factor is the named constant `kRiverLowFraction`. `SurfaceWetness = clamp01(surfaceWater / wetness.surface_scale + wetness.soil_weight * SoilMoisture)`, with `wetness.*` read from the sidecar (owned by the hydrology-data plan; this plan adds no rows).
- **`SinkTable`:** capacity 8, sorted by `StringCRC` id on insert; `FillSinks` fills neutral, calls providers in ascending id, repairs non-finite or negative values to neutral with a once-per-id Error and a bad-output flag; no providers means arrays not allocated and `WaterSinks` nulls.
- **`ApplyGroundWaterInfluence(const float* signed, uint32_t n, float* extraWater, float* draw)`:** positive to `extraWater`, negative magnitude added to `draw`; no signed array leaves `extraWater` null and `draw` unchanged. A5 holds no influence constant.
- **`HydrologyInputResolver`:** source or fixed driver, returns `WaterInput` plus status `Ok`/`InvalidView`/`NoInput`; source wins over a configured driver (one Info).
- **`HydrologySpinUpTicket`:** owns an initialised sim, a parameter value and a runner; implements `IHydrologyInputsProvider` for A4's job; `BeginSpinUpTicket(terrain, params, SpinUpStart, err)` calls `ApplyPhaseSeed` first; `Destroy` is safe from any thread and references no module.

### Stage notes
- Week arithmetic uses `WeekOf` and the real `kWeeksPerSeason`/`kSeasonsPerYear` from `GameSpeedController.h`, never a literal 52. The captured day is stored at `Capture` (the base's `mCapturedDay`), never recomputed at `Commit`. A retried step publishes the week of the represented day.
- Ingest on `WorldGenerationComplete`: the base stores the target revision first (cancels), `InitialiseSim` reads `HydrologyTerrainSource` from `GetCurrentWorld()` (the module never keeps the pointer), builds terrain, runs `Initialise`. Ingest is idempotent per revision so `BeginSpinUp` and the handler work in either order.
- Alone spin-up: a uniform coldness array from `start_coldness`, `ApplyPhaseSeed(array, nullptr)`, then `RunFixed(fixed, spinup_weeks, exec, cancel)` on a job via `ISpinUpLauncher` (`SynchronousLauncher` inline; `JobSystemLauncher` via `TrySubmit(fn, "world")` with inline fallback and one Warning). The result goes into the base's `SpinUpSlot`, polled in `DoUpdate`. Length is always `spinup_weeks`.
- Coupled spin-up and `IHydrologySpinUpHost` are system code on top of `SpinUpSlot`: `BeginSpinUp` (null if `Initialise` failed for the revision, or `mRestoredRevision == revision` once the save feature lands), `CompleteSpinUp` (takes the ticket's sim as pending at the same `DoUpdate` poll where A4 sets its own), the seed-only path when the source is ready, no pending sim exists and `BeginSpinUp` was never called (Degraded, one Warning).
- Config keys: `parameters` (the sidecar catalogue alias), `packs` (ordered pack ids), `spinup_weeks` (integer `[0, 520]`), `start_coldness` (0..1), `fixed_input` (`mode` `constant` or `script`). A bad value is a config error naming the key (reuse World Step's config-error helper). Manifest: stage-scoped instance after `WorldStepModule` (and after `WeatherModule`); the ordering rule is a World Step plan item. Hosting stages own their real manifests; tests use a throwaway fixture manifest.

### Verification cadence
- Per task: `dia run googletest --filter="<suite under work>" --shards 2` (always `--shards 2`). The feature-wide `*Hydrology*` filter runs only in the scoped verification task. No full-suite run (the World Step weather-stack close-out owns it), no `SLOW_` suites, no sanitizer unless asked, no mutation checks. Debug performance is a ballpark, reported, not gated. World-sim results are verified from cell data and stats (dumps, counters, bit-identical comparisons), never screenshots. Concurrency tests use counters and fake executors, never sleeps. `dia validate manifest` runs only in the manifest task.
- One commit per task (code, tests, plan row in the same commit).

## Open items

Spec gaps found while rebuilding (none resolved here):

1. **Amendment items carry no numbered ACs.** The 11 amendment items change behaviour (strict load, `Reload`, `ApplyPack`, `WorldCellFields`, packs, `FileWatcher`) but ACs 47 to 52 still describe the old fallback behaviour and key form; the plan rewrites the test expectations from the amendment. Spec text should state the replacement ACs.
2. **Terrain source fields.** `HydrologyTerrainSource` (module spec "World ingest") does not list per-cell `TerrainType` or the `terrain.soil_depth_mult` values that Spec-6 item 11 and water-pipeline pass 3 need, and it names `Biome` where it is now `BiomeIndex`. Also: it is unclear whether the builder still unions corridor/Pass/barrier/fixed-site cells for `isCrossing` or reads S-1's `terrain.is_protected` field (kit Spec-6 item 3 makes that a field).
3. **Hook list mismatch.** The module amendment lists six hooks (no `RunStep`); the kit lists five plus `RunStep`/`ApplyEntry`. `PublishCommit(const TSim&, uint32_t stepDay)` and `mCapturedDay` are `uint32_t` in the kit, while this spec uses `uint64_t stepDay`, `HydrologyUpdated.week` as `uint64_t` and `SetCommittedWeek(uint64_t)`. Where `SetCommittedWeek` is called (base or `PublishCommit`) is unspecified.
4. **Parameter key form.** `hydro.biome.<column>.<BiomeId>` versus parameter-files' map expansion `<key>.<mapKey>`: if registry ids are spelled `Biome.Grassland` the full key is `hydro.biome.soil_capacity.Biome.Grassland`. Whether `<BiomeId>` includes the `Biome.` prefix is not stated. Also `ParamBinding::Snapshot` is described as per-step in parameter-files but "binds once at init" in the module amendment; the plan snapshots at `Capture` into the latch.
5. **Config key names.** The amendment replaces `config.parameters` with "the sidecar path plus a `packs` list" without naming the keys or whether `packs` holds ids or paths. Parameter-files says the caller (F-3) chooses and orders packs; whether the module config or F-3 selection owns the active list is undefined.
6. **`cow_worldsim.diagamemessages` has no home.** The file does not exist in the repo and no spec names its path, owner, or the plan that creates it. `HydrologyMessages.h` remains in the module spec's Files Touched and Public API.
7. **`WorldCellFields` registration timing for A5.** Which `hydro.*` fields are contributed (all layer-sidecar fields or a subset), who registers them and when relative to the kit's rebuild on `WorldGenerationComplete`, and what a read returns before the first commit, are not specified.
8. **`basin_kind` `dry`.** `none`/`lake`/`dry` is defined by Spec-6 but "dry" is not: a basin that is not a lake at generation, a basin with level at bed, or a lake basin currently empty. The old `basin` clause had `lake|dry|any` without a definition either.
9. **Failing semantics versus running state.** The module spec says an invalid view is Degraded but a missing water input is Failing; the base's health is a single status. Whether a transient `NoInput` at a later step (a source cleared at runtime) is Failing and recovers when `SetFixedInput` is called is not stated.
10. **Spin-up host and restored A4.** `IHydrologySpinUpHost::BeginSpinUp` null-return rule for `mRestoredRevision` is owned by the save feature, but the coupled-spin-up text here and the kit's restore sequence both set `mRestoredRevision`; whether it lives in the base or the module is undefined.
11. **Stale spec text left in place.** "Unhealthy" in the stage table, "Observability" and ACs 7, 13, 31; AC 3 uses stage id text; Files Touched lists `hydrology_parameters.json` and the `wetness.*` rows as edits here (they are now sidecar entries owned by the hydrology-data plan); "Spec edits owed" still lists A5 Features 1 and 2 split.
12. **Blackboard scopes** are not referenced by any A5 spec; confirmed not used.
