## Implementation Patterns

### Files and layout
- Pure, in `Cluiche/CoW/Shared/Hydrology/`: `HydrologyCoupling.h` (header-only: `WaterSourceView`, `IWaterInputSource`, `WaterSinkBuffers`, `IWaterSinkProvider`, `SpinUpStart`, `IHydrologySpinUpHost`), `HydrologyTerrainBuilder.h/.cpp`, `HydrologyRunner.h/.cpp`, `HydrologySpinUp.h/.cpp` (`HydrologySpinUpTicket`), `HydrologySnapshot.h/.cpp`, `SinkTable.h/.cpp`, `HydrologyInputResolver.h/.cpp`. Edited: `HydrologySimulation.h/.cpp`, `HydrologyParameters.h/.cpp`, `hydrology_parameters.json`.
- Module, in `Cluiche/CoW/Modules/`: `HydrologyModule.h/.cpp` (SimModule, `IHealthReporter`, `IHydrologyInputsProvider`, `IHydrologySpinUpHost`), `HydrologyStage.h/.cpp` (`class HydrologyStage final : public IWorldStepStage`, built by the module, holds a `HydrologyModuleState` struct so it is testable without the module), `HydrologyMessages.h` (hand-written POD, follow `GameSpeedMessages.h`).
- Test fakes ship with the library in `Cluiche/CoW/Shared/Hydrology/Testing/`: `FakeWaterSource.h` (poisonable working buffers, swap-on-commit mode), `FakeSinkProvider.h` (records call thread and order), `FakeHydrologyWorldSource.h`, `FakeWorldStepRegistry.h`, `FakeStepChain.h` (calls Capture/Run/Commit in order for a list of stages), `SynchronousLauncher.h`, `ObservingExecutor.h`, `FakeA4SpinUpJob.h`. Reuse the Weather `Testing/` fakes where they already exist rather than copying.
- Tests: `Cluiche/Tests/GoogleTests/CoW/Hydrology/{TestHydrologyTerrainBuilder,TestHydrologyStage,TestHydrologySpinUp,TestHydrologySinks,TestHydrologyModule}.cpp`.
- Namespace `CoW::Hydrology`. Members `m` prefix, constants `k` prefix, log channel `HYD`. Dia containers only in public APIs (PD-004).

### Task 2: BuildHydrologyTerrain
- `bool BuildHydrologyTerrain(const HydrologyTerrainSource&, HydrologyTerrain& out, String256& err)`. `HydrologyTerrainSource` is a plain struct of arrays (dimensions, elevation, bed elevation, flow direction, `waterSource`, biome, terrain flags, corridor-site cells, Hearth/Nexus/world-throne cells, optional basin table, `hasBasinTable`).
- `isCrossing` is the union corridor sites, `Pass`, `RiverCrossesBarrier`, fixed-site cells. A version-1 source (no basin table) builds a lake-only table from lake membership, sets `basinsFromLakesOnly`, and reports it through an `out` flag so the module logs the one Info. The builder itself does not log.

### Task 3: Capture / Run / Commit split
- Additive on `HydrologySimulation`: `Capture(const HydrologyLatch&)`, `Run(const WaterInput&, IParallelExecutor&)`, `Commit()` (array swap, not copy), `SetCommittedWeek(uint64_t)`, `CommittedWeek()`, `Fields()` (committed), `WorkingFields()`. `HydrologyLatch` holds a parameter copy and pending `(cell, biome)` edits. The biome array is part of the working set. `Step(in, exec)` becomes `Capture(neutral) + Run + Commit` and Feature 2's tests stay unchanged.

### Task 4: HydrologyRunner and pure spin-up
- `HydrologyRunner(HydrologySimulation&)`: `bool StepWeek(uint32_t weekIndex, const WaterInput&, IParallelExecutor&)` and `bool RunFixed(const FixedWaterInput&, uint32_t weeks, IParallelExecutor&, const CancelFn&)` (false if cancelled; the cancel check is between weeks only). This is the synchronous oracle and the spin-up body, so no other week loop exists. Seeding (`ApplyPhaseSeed`) is not `RunFixed`'s job; the caller does it before the run.

### Task 5: Snapshot
- `HydrologySnapshot` is a const view over committed state with the accessor table in the spec. `RiverState` uses the real parameter constants; the 0.7 low-flow factor is the GDD's fixed value and lives as a named constant `kRiverLowFraction`, not a magic number. `SurfaceWetness = clamp01(surfaceWater / wetness.surface_scale + wetness.soil_weight * SoilMoisture)`. Add the two `wetness.*` rows to Feature 1's table and `hydrology_parameters.json` here if Feature 1 has not (the spec says it owes them); descriptor-table tests then cover them automatically.

### Task 6 to 8: Sinks, influences, inputs
- `SinkTable`: fixed capacity 8, sorted by `StringCRC` id on insert. `RegisterSinkProvider` false for null, duplicate or the ninth. `FillSinks(stepDay, WaterSinkBuffers)` fills neutral, calls providers in ascending id, then repairs non-finite or negative values to neutral, once-per-id Error flag, and reports "bad provider output" to the caller for Degraded. No providers: arrays not allocated, `WaterSinks` nulls.
- Influence translation is a free function `ApplyGroundWaterInfluence(const float* signed, uint32_t n, float* extraWater, float* draw)`: positive goes to `extraWater`, negative adds the magnitude to `draw`. No signed array: `extraWater` stays null and `draw` is unchanged. A5 holds no influence constant (Open Design Question 4).
- `HydrologyInputResolver` picks the source or the fixed driver for a step and returns a `WaterInput` plus a status (`Ok`, `InvalidView`, `NoInput`). A bad view (false return, null required pointer, `cellCount != N`) is `InvalidView`. Source wins over a configured driver (one Info, reported through the status).

### Task 9: HydrologySpinUpTicket (pure)
- Self-contained: owns an initialised `HydrologySimulation`, a parameter copy and a runner; implements `IHydrologyInputsProvider` for A4's job. `StepWeek(weekIndex, const WaterSourceView&, exec)` delegates to `HydrologyRunner::StepWeek`. Constructed by a free function `BeginSpinUpTicket(terrain, params, SpinUpStart, err)` which calls `ApplyPhaseSeed` before returning. `static Destroy(ticket)` is safe from any thread and references no module.
- `FakeA4SpinUpJob` (in `Testing/`) runs a fake A4 week and then `ticket->StepWeek` with the fake's working view, the same order the real A4 job uses.

### Task 10 to 11: Stage
- `Capture(stepDay)`: 1. promote `mPending` to `mActive` (chain idle; old sim destroyed). 2. drain `mQueue` in arrival order into a `HydrologyLatch`. 3. `mCaptureRevision = mActiveRevision`, `mCapturedDay = stepDay`. 4. resolve the input view, set `mStepValid`. 5. fill sinks, then influences. 6. `sim.Capture(latch)`. `Run(exec)` does nothing when `!mStepValid`, otherwise builds `WaterInput{.., week = WeekOf(mCapturedDay) % kWeeksPerYear}` and calls `sim.Run`, timed. `Commit()` discards (no `sim.Commit`, no message, counter, Info) when `!mStepValid` or `mCaptureRevision != mTargetRevision`; otherwise `sim.Commit()`, `SetCommittedWeek(WeekOf(mCapturedDay))`, record `LastStepMs`, publish `HydrologyUpdated{week}` through an injected `IHydrologyPublisher` seam (recorder in tests).
- Week arithmetic uses `WeekOf` and the real `kWeeksPerSeason`/`kSeasonsPerYear` from `GameSpeedController.h`, never a literal 52. The captured day and week are stored at `Capture`, never recomputed at `Commit`.
- `HydrologyStage::SerializePending`/`DeserializePending`/`ValidatePending` exist as empty overrides here (Feature 4 fills them).
- `FakeStepChain` runs `["weather", "hydrology", "ecology"]` as Capture all, Run all, Commit all so AC 26 and 27 test the real order.

### Task 12: Queue
- `MutationQueue`: fixed-capacity `DynamicArrayC<HydrologyMutation, 128>`; entries are tagged PODs (`SetParam`, `ParamOverrides`, `Reload`, `BiomeChange`). Overrides carry a validated, merged `HydrologyParameters` copy so draining cannot fail halfway. `Queue*` validate before enqueue (on a copy through Feature 1) and return false with `ParamError`. A full queue returns false, one Warning, Degraded. Drain order is arrival order inside `Capture`, before `sim.Capture`. Feature 6 will add preset and state-replace entry types; leave the tag enum open.
- `IParameterSource` seam (injectable file reader) so the file read count is observable (AC 52).

### Task 13: IHydrologyInputsProvider
- The module returns A4's `HydrologyInputs` (`surfaceWetness`, `openWater`, `glacierEligible` copies from `sim.Fields()`, plus `glacierCheckWeek` and `glacierSnowFloor` from `mParams`). `HydrologyInputsProvider.h` is A4's header; if A4 Feature 3 has not built it, use a local copy behind the same names and flag it in notes.

### Task 14 to 16: Ingest, alone spin-up, launcher
- `WorldGenerationComplete`: store `mTargetRevision` first (cancels), read `HydrologyTerrainSource` from `GetCurrentWorld()` (module never keeps the pointer), `BuildHydrologyTerrain`, `Initialise`, then spin-up. Ingest is idempotent per revision (`mIngestedRevision`), so `BeginSpinUp` and the handler may run in either order.
- `ISpinUpLauncher { virtual void Launch(callable, JobTag) }` is the seam. `SynchronousLauncher` runs inline. `JobSystemLauncher` uses `JobSystemService::TrySubmit(fn, "world")` with the DeferredStep capped executor; a `TrySubmit` failure runs inline with one Warning (never drop). Completion goes into a SimPU-owned `SpinUpSlot` (`Idle/Running/Done/Cancelled`, revision, sim pointer), polled in `DoUpdate`. No bus message, no callback onto SimPU. Same pattern as `WeatherModule`; reuse its slot type if it is already a shared header.
- Every job result carries `(revision, visitGeneration)`; both must match or the sim is destroyed with a Warning.
- Alone: fill a uniform coldness array from `start_coldness`, then `ApplyPhaseSeed(array, nullptr)` (seam fix 2026-11-17) then `RunFixed(fixed, spinup_weeks, exec, cancel)`. Length is always `spinup_weeks`; no code path lengthens it.

### Task 17: Coupled spin-up
- `HydrologyModule::BeginSpinUp(revision, start)` ingests if needed, returns null if `Initialise` failed for the revision (or, after Feature 4, if `mRestoredRevision == revision`), else a ticket. `CompleteSpinUp(ticket, revision)` takes the ticket's sim as `mPending` at the same `DoUpdate` poll where the fake A4 sets its own. In `DoUpdate`, if the source reports `IsReadyForRevision(target)`, A5 has no pending sim and `BeginSpinUp` was never called, take the seed-only path (state equals fresh `Initialise`), Degraded, one Warning.

### Task 18: Config and manifest
- Keys: `parameters`, `spinup_weeks` (integer `[0, 520]`), `start_coldness` (0..1), `fixed_input` (`mode` `constant` or `script`). A float or out-of-range value is a config error naming the key. Reuse World Step's config-error helper. Manifest: stage-scoped instance listed after `WorldStepModule` (and after `WeatherModule` where present); the ordering rule is World Step Feature 2's, this feature adds the type, `dependencies` and `soft_dependencies`. Register stage `"hydrology"` in `DoStart`, unregister in `DoStop`, `kAllowedPUs = Sim`, register the type like `GameSpeedController`. Hosting stages (S-2.6, S-3.5) own their real manifests; the test uses a throwaway fixture manifest and never commits a broken real one.

### Task 19 to 21: Timing, observability, lifecycle
- `LastStepMs()` is set only on an applied step. `IHealthReporter` cause bitmask: Degraded `kFallbackParams`, `kBadProviderOutput`, `kInvalidOrDiscardedStep`, `kQueueFull`, `kSeedOnlyStart`; Unhealthy `kInitFailed`, `kNoWaterInput`, `kGenerationFailed`. `DIA_TRACE_ZONE` on `Capture`, `Commit`, ingest and the spin-up job. Only SimPU writes health and logs (SD-PERF-7).
- `DoStop`: `UnregisterStage`, `SetHydrologyProvider(nullptr, nullptr)` if weather is still there, clear source and sink table, cancel and join the own job, destroy both sims, clear the queue, release the hold if held. A per-visit `mVisitGeneration` increments in `DoStart`.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<suite under work>" --shards 2` (always `--shards 2`); the feature-wide `*Hydrology*` filter runs only in task 24 (2026-11-17, speed-ups). One full-suite run is not part of this plan; it is the worldstep.plan.md Weather-stack close-out. No `SLOW_` suites. No mutation checks. Sanitizer: on request only (user, 2026-11-17). Concurrency tests use counters and fake executors, never sleeps. Run `dia test e2e` only if a task note says so (none do); it does not build first.
- One commit per task (code, tests, plan row in the same commit).
