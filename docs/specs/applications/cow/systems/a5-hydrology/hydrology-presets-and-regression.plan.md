## Implementation Patterns

### Preset data and loader (Tasks 4, 5)
- `Cluiche/CoW/Shared/Hydrology/HydrologyPreset.h/.cpp`. Files `Cluiche/Assets/CoW/Global/Hydrology/Presets/<name>.hydropreset.json`, envelope `{"format": "cow.hydrology_preset", "version": 1}` (directory is `Presets/`, matching A4).
- `HydrologyPreset { name; startWeek (0 to 51); selectors; fills; phases }`, `DynamicArrayC` and `String64`/`String256` only (PD-004).
- `Selector`: AND-combined optional clauses `elevation {min,max}`, `latitude {min,max}` (inclusive, [0,1]), `waterSource` (list of `None|Ocean|Lake|River`), `river` (bool), `crossing` (bool, `isCrossing`), `basin` (`lake|dry|any`), `distanceToRiver {min,max}` (hex steps), `upstreamOfCrossing {maxSteps}`. `"all"` predefined. `min > max` invalid.
- `Fill { field (soilMoisture, groundWater, surfaceWater, glacier, ice); value or fraction (fraction for soil and ground only); selector }`; `basinFill { selector, fraction of spill volume }`. Range-checked per field.
- `Phase { weeks; waterToGround, temperature, snowPack, glacierInput each {base, where[{selector, value}]}; optional seasonAmplitude on temperature and waterToGround; optional melt {where, perWeek, weeks} }`.
- Limits: at most 12 selectors, 16 fills, 16 phases, total weeks at most 5,200.
- `bool LoadHydrologyPreset(const Json::Value&, HydrologyPreset& out, PresetError& err)`: strict (unknown key invalid at every level), all-or-nothing: build into a local, move to `out` only on success. Touches no `HydrologySimulation`. `PresetError { path; reason }` is shared with `HydrologyPresetError`.
- `ResolveSelector(const Selector&, const HydrologyTerrain&, DynamicArrayC<uint32_t>& outSortedCells)`: sorted ascending, de-duplicated. `distanceToRiver` uses a multi-source breadth-first search over the hex topology (fixed queue, no recursion). `upstreamOfCrossing` follows each cell's downstream path up to `maxSteps` to an `isCrossing` river cell. A zero-cell result is reported so apply can name the selector.

### `ScriptedWaterInput` (Task 9)
- `ScriptedWaterInput.h/.cpp`: `bool Build(const HydrologyPreset&, const HydrologyTerrain&, String256& err)` resolves selectors once; `WaterInput ForWeek(uint32_t week, const HydrologySimulation&)` fills four owned per-cell float buffers (`waterToGround`, `temperature`, `snowPack`, `glacierInput`) and returns the `WaterInput` over them (`extraWater` null, `sinks` neutral); `uint32_t TotalWeeks() const`. `glacierInput` is written only where `glacierEligible != 0`. The seasonal swing is a **constant 52-entry table in code** (no libm). No RNG. Past the last phase the last week repeats. Feature 2's `FixedWaterInput` is unchanged.

### `RebaselineStorage` and `ApplyHydrologyPreset` (Tasks 10 to 13)
- `HydrologySimulation::RebaselineStorage()` is a Feature 2 addition: it resets the storage baseline so the first step's balance error excludes fills. Task 0 checks whether Feature 2 built it; otherwise Task 10 adds it and notes the amendment to Feature 2 (re-approval is the user's step).
- `HydrologyPresetApply.h/.cpp`: `HydrologyPresetResult ApplyHydrologyPreset(HydrologySimulation&, const HydrologyPreset&, const HydrologyTerrain&, const HydrologyParameters&)`, `HydrologyPresetResult { bool ok; uint8_t startWeek; HydrologyPresetError error; }`.
- Order: (1) precondition: no step in flight (Debug assertion; Release returns an error; neither mutates); (2) **validate everything first** against the terrain: every used selector resolves to at least one cell, fills and phases in range; any failure returns before any mutation (atomic); (3) reset to the clean base by re-running Feature 1's seeding; (4) fills in file order, clamp to capacity, `basinFill`, recompute derived fields (levels, `openWater`, `passability`); (5) `RebaselineStorage()`; (6) return `startWeek`. Apply does not own the clock.
- Coupled mode (`mode=coupled`) applies fills only and ignores `phases`. That switch lives in Feature 5's command, not here; this feature exposes a `ApplyFillsOnly` flag only if Task 0 shows Feature 5 needs it (open item 5).

### Test grids and terrain adapter (Tasks 8, 17)
- `Cluiche/CoW/Shared/Hydrology/Testing/HydrologyTestGrids.h` (shared with Features 1 and 2; **additive edits only**): add `MakeRiverWithCrossing`, `MakeColdUplands`, `MakeWetBasin`. Deterministic, no RNG, named cell lists returned so tests never re-derive predicates.
- `BuildHydrologyTerrain(const WorldStructure&, const BasinData&, HydrologyTerrain&)` in `Cluiche/CoW/Shared/Hydrology/BuildHydrologyTerrain.h/.cpp`: pure, deterministic. `isCrossing` = union of corridor sites, `Pass` cells, `RiverCrossesBarrier` cells and Hearth, Nexus and world-throne site cells (Feature 1 AC 14). Feature 3 reuses it.

### Scenarios (Tasks 14 to 20)
- `Cluiche/Tests/GoogleTests/CoW/Hydrology/TestHydrologyRegression.cpp`, serial executor, hand-built grids, default parameters, the shipped preset files loaded through `LoadHydrologyPreset` and played by `ScriptedWaterInput`. Suite names start with `Hydrology` so `*Hydrology*` picks them up.
- Every check **prints its measured value** and warns when it passes with under 10% margin. R-Melt records `k` (`Wm - Wh`) on the first run and asserts no number until it is known (spec Open Question 1). Thresholds marked TBD are recorded on the first run, and the user signs off on each before it is fixed (Task 21).
- R-Balance (hand-built grids, whole preset length): `|error| <= 1e-4 * max(in, out, 1)` every week and cumulative `|error|` under `1e-3 *` cumulative throughput (Feature 2 AC 22 and 23). R-Determinism: bit-identical at 1, 2, 7 and 16 ranges and serial vs a 3-range executor over the first 104 weeks (reuse Feature 2's range executor).

Verify world behaviour by cell data and stats, not screenshots.
- **No full-suite run in this feature** (once, in the worldstep.plan.md Weather-stack close-out). No mutation checks. Sanitizer: on request only (user, 2026-11-17). Run time is reported, not gated; perf numbers are Debug ballpark only, and a bad ballpark queues a perf pass. No Release timing here (2026-11-17, speed-ups).
