## Implementation Patterns

### Preset data and loader
- `Cluiche/CoW/Shared/Hydrology/HydrologyPreset.h/.cpp`. Files `Cluiche/Assets/CoW/Global/Hydrology/Presets/<id>.hydro_preset.json`, envelope `{"format": "cow.hydro_preset", "version": 1}` (spec-6 resolution 2; the format and file names come from `WorldSimNames.h`).
- `HydrologyPreset { name; startWeek (0 to 51); derived and selectors (a CellSelectorSet document); fills; phases }`, `DynamicArrayC` and `String64`/`String256` only (PD-004).
- **Selectors are not parsed here.** The preset hands its `derived` and `selectors` blocks to `CellSelectorSet`, which validates (unknown slot or field, unknown selector, cycle, `maxSteps` < 1) and resolves to sorted cell lists. The loader adds only the checks the selector set cannot do: a fill or phase names a selector that exists, `all` is predefined.
- `Fill { field (soil_moisture, ground_water, surface_water, glacier, ice); value or fraction (fraction for soil and ground only); selector }`; `basinFill { selector, fraction of spill volume }`. Range-checked per field. Field-name casing in preset JSON follows the snake_case field names (open item 5).
- `Phase { weeks; water_to_ground, temperature, snow_pack, glacier_input each {base, where[{selector, value}]}; optional season_amplitude on temperature and water_to_ground; optional melt {where, perWeek, weeks} }`.
- Limits: total weeks at most 5,200; at most 16 fills and 16 phases; selector and derived counts follow the kit's caps (32 and 16), not the spec's old 12 (open item 3).
- `bool LoadHydrologyPreset(const Json::Value&, HydrologyPreset& out, PresetError& err)`: strict (unknown key invalid at every level), all-or-nothing: build into a local, move to `out` only on success. Touches no `HydrologySimulation`.

### Hydro fields in `WorldCellFields` (new, replaces `ResolveSelector`)
- A5 contributes its committed fields under slot `hydro` (soil_moisture, ground_water, surface_water, river_flow, flooded, ice, glacier, passability, open_water, glacier_eligible, and `basin_kind`). `hydro.basin_kind` is an enum `none`, `lake`, `dry`; the old `any` is `!= none`. Readers read committed state only (SimPU, never during `Run`).
- Test side: a helper that builds a `WorldCellFields` from a hand-built `HydrologyTerrain` plus `HydrologySimulation` (in `Testing/`), so selector tests and the driver need no module.
- `terrain.is_protected` replaces `crossing` (spec-6 resolution 4). The adapter and S-1 supply it; a hand-built fixture supplies it in tests.

### `ScriptedWaterInput`
- `ScriptedWaterInput.h/.cpp`: `bool Build(const HydrologyPreset&, const CellSelectorSet&, const WorldCellFields&, String256& err)` resolves selectors once; `WaterInput ForWeek(uint32_t week, const HydrologySimulation&)` fills four owned per-cell float buffers and returns the `WaterInput` over them (`extraWater` null, `sinks` neutral); `uint32_t TotalWeeks() const`. `glacierInput` is written only where `glacierEligible != 0`. The seasonal swing is a **constant 52-entry table in code** (no libm). No RNG. Past the last phase the last week repeats. `FixedWaterInput` is unchanged.

### `RebaselineStorage` and `ApplyHydrologyPreset`
- `HydrologySimulation::RebaselineStorage()` is an addition to the water-pipeline class: it resets the storage baseline so the first step's balance error excludes fills. Task 0 checks whether it exists; otherwise the Rebaseline task adds it and notes the amendment.
- `HydrologyPresetApply.h/.cpp`: `HydrologyPresetResult ApplyHydrologyPreset(HydrologySimulation&, const HydrologyPreset&, const ResolvedSelectors&, const HydrologyTerrain&, const HydrologyParameters&)`; `HydrologyPresetResult { bool ok; uint8_t startWeek; HydrologyPresetError error; }`. The parameters argument is the `ParamBinding<HydrologyParameters>` snapshot, not a private default.
- Order: (1) no step in flight (Debug assertion; Release returns an error; neither mutates); (2) **validate everything first**: every selector used by a fill or phase resolves to at least one cell (the consumer's check, naming the selector), fills and phases in range; any failure returns before any mutation; (3) reset to the clean base by re-running `Initialise` seeding; (4) fills in file order, clamp to capacity (soil capacity = `hydro.biome.soil_capacity[biome] * terrain.soil_depth_mult`), `basinFill`, recompute derived fields; (5) `RebaselineStorage()`; (6) return `startWeek`. Apply does not own the clock.
- Coupled mode (`mode=coupled`) applies fills only; that switch lives in the debug plan's `cow.hydro.preset`. This plan exposes an `ApplyFillsOnly` flag only if Task 0 shows it is needed.

### Test grids and terrain adapter
- `Cluiche/CoW/Shared/Hydrology/Testing/HydrologyTestGrids.h` (shared; **additive edits only**): add `MakeRiverWithCrossing`, `MakeColdUplands`, `MakeWetBasin`. Deterministic, no RNG, named cell lists returned. Fixtures also provide the `terrain.*` and `hydro.*` field values the selectors read.
- `BuildHydrologyTerrain(const WorldStructure&, const BasinData&, HydrologyTerrain&)` in `BuildHydrologyTerrain.h/.cpp`: pure, deterministic; biomes are `BiomeIndex` from the registry; protected cells from `terrain.is_protected`; basin searches may use `PriorityFlood` / `ConnectedComponents`. The module reuses it.

### Scenarios
- `TestHydrologyRegression.cpp`, serial executor, hand-built grids, parameters from the sidecar defaults via `ParameterFile` (no compiled defaults), the shipped preset files loaded through `LoadHydrologyPreset`, played by `ScriptedWaterInput`. Suite names start with `Hydrology`.
- Every check **prints its measured value** and warns when it passes with under 10% margin. R-Melt records `k` (`Wm - Wh`) on the first run and asserts no number until the user signs off (spec Open Question 1). TBD thresholds are recorded on the first run and signed off in the tuning task.
- R-Balance: `|error| <= 1e-4 * max(in, out, 1)` every week and cumulative `|error|` under `1e-3 *` cumulative throughput (water-pipeline plan's tolerance and drift tests). R-Determinism: bit-identical at 1, 2, 7 and 16 ranges and serial vs 3-range executor over the first 104 weeks.

### R-Reach harness
- `Testing/ReachCycleScript.h/.cpp`: the wet/dry/cold script as data for `ScriptedWaterInput` (a wet year, a dry decade, a normal decade, a 4-decade cold phase, a warm ramp and a melt pulse, then normal to week 5,200) and the **Deep-blocking profile decorator** (`DeepBlockingProfile : INavigationProfile`): `Deep` impassable; `Frozen`, `Wet`, `Fordable`, `Dry` passable. If `ReachabilityValidator::Validate` cannot take a per-cell override, Task 0 flags it and a CoW-side S-1 amendment (`ICellBlockMask`) is a separate user-approved task.
- `SLOW_HydrologyReach.ReachLongRun` (suite name carries `SLOW_` so the default filter `-SLOW_*:*/SLOW_*` skips it; user decision 2026-11-17): for each S-1 Small preset (seed 1) build a Small world, `BuildHydrologyTerrain`, `Initialise`, spin up 52 weeks, then 5,200 weeks. **Every week:** no protected cell (`terrain.is_protected`, including corridor sites) is `Deep`. **Every simulated year:** `ReachabilityValidator::Validate` with the decorator reports the same findings as the unflooded world. Run time reported, not gated.
- `SLOW_HydrologyReach.ReachCoupledA4A5`: a skipped stub; real body Blocked.

### Goldens
- `Cluiche/Tests/GoogleTests/CoW/Golden/hydrology_layers.golden.json` via `CellLayerGolden.h`. Keys `scenario/<preset>/seed<N>/<layer>` with layer ids from `WorldSimNames` (spec-6 field names); the pipeline plan owns the `pipeline/` prefix, add and never overwrite. Scope: eight base layers x 4 presets x seeds 1 to 3 at Small, `ScriptedWaterInput`, serial executor, 52 weeks = 96 hashes (4 x 3 x 8; recount at build if the layer list changes). Update only with `DIA_UPDATE_GOLDEN=1`, once, after tuning is final; review the diff summary only.

### Tuning
- Allowed levers in order: the preset data values; the `cow.hydro_params` sidecar defaults (edited in the sidecar, or through `cow.hydro.params save_defaults` in a dev build, not a C++ table); then **stop and flag** (a mechanic in the water pipeline). Each change is appended to the **Tuning log** in the spec's Status section (parameter, old, new, test that forced it). A changed default is a new GDD fold-back item. One lever per iteration; three failed attempts on the same check stop and report.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<task suite>" --shards 2` (always `--shards 2`; `HydrologyPreset*`, `ScriptedWaterInput*`, `HydrologyRegression*`, `HydrologyGolden*`, plus `*CellSelector*:*CellFields*` when selector or field tasks touch the kit fixtures). The feature-wide `*Hydrology*` filter runs only in the scoped verification task.
- `SLOW_` suites (`SLOW_HydrologyReach.*`, `SLOW_HydrologyBalance.*`) are skipped by default and run explicitly once in the scoped verification task with `dia run googletest --filter="SLOW_*" --shards 2` (Task 0 confirms the flag), and once in the World Step weather-stack close-out. Kill any leftover game exe before E2E; E2E does not build, so run the compile stage first. Verify world behaviour by cell data and stats, not screenshots.
- **No full-suite run in this feature** (World Step weather-stack close-out owns it). No mutation checks. Sanitizer on request only. Run time is reported, Debug ballpark only; no Release timing here.

## Open items

SPEC GAPS found while rebuilding (not resolved here):

1. **Flood travel time** (spec Open Question 1). R-Melt records `k` on the first run and asserts no number. If `k` is 0 or 1: a lever, then a pipeline flag. User signs off the threshold.
2. **Validator profile override** (spec Open Question 3). Task 0 finds out whether `ReachabilityValidator::Validate` accepts a per-cell block; otherwise a user-approved CoW-side S-1 amendment gates the decorator and reach tasks.
3. **Selector limits.** The spec still says at most 12 selectors; the kit caps a set at 32 selectors and 16 derived fields. Which limit applies to presets is unwritten.
4. **`crossing` vs `terrain.is_protected`.** The presets amendment table maps `crossing` to `terrain.is_crossing`, spec-6 and the kit renamed it `terrain.is_protected` (a wider set, including Hearth, Nexus, throne and Pass cells, not only river cells). Consequences are unspecified for `flash_flood_fords` (`upstreamOfCrossing` was defined for an `isCrossing` river cell), AC 4, AC 24, AC 26a, AC 30 and the R-Ford "crossing cell". The spec text and `HydrologyTerrain::isCrossing` still use the old name.
5. **Preset JSON field names and format.** The spec's example and AC 1 still use `cow.hydrology_preset`, `.hydropreset.json`, camelCase keys (`soilMoisture`, `waterToGround`, `snowPack`, `glacierInput`, `seasonAmplitude`) and a `where: "all"` form; spec-6 gives format `cow.hydro_preset` and `.hydro_preset.json` but not the key casing. Where the `derived` block sits in the preset document is not shown in the example either.
6. **Who contributes `hydro.*` to `WorldCellFields`.** Stated only in this spec's amendment (item 2). Whether `hydro.basin_kind` `dry` means "non-lake basin at generation" or depends on committed level is undefined, as is how `ScriptedWaterInput::Build` resolves selectors that read committed `hydro.*` fields that change over time ("resolves selectors once").
7. **Selector resolution needs a `WorldCellFields` outside a module.** The spec's `Build(preset, terrain, err)` signature and the hand-built-grid tests assume no module; the kit builds the registry on `WorldGenerationComplete`. A test-side builder is assumed (task 6); the spec does not mention it.
8. **R-Reach is "default GoogleTest" in the spec (AC 23, Test Plan) but `SLOW_` by the user decision of 2026-11-17** recorded in the old plan; Status text in the spec is not updated.
9. **Tuning lever text** still says "default parameter file values (Feature 1's table)". With no base file and no C++ table, the lever is the sidecar default; the spec's Tuning-log wording should follow.
10. **Layer ids in goldens.** `scenario/<preset>/seed<N>/<layer>` keys and the spec's layer list use the pre-rename `hydro.soil`, `.ground`, `.surface`. Spec-6 renames them; the golden key spelling must match `WorldSimNames`.
11. **Biome fills and the soil-depth multiplier.** `fraction` fills are "fraction of biome capacity"; the capacity now includes `terrain.soil_depth_mult` (amendment 11). The spec does not say whether fills use the multiplied capacity (this plan assumes yes).
12. **Seed set and crossing availability** (spec Open Question 2) remain a user decision from the spike.
13. **`basinFill`'s selector** selects cells, but basins are what is filled; how a cell selector maps to basins is unspecified.
14. **Water-pipeline amendments** to re-approve with this feature: `RebaselineStorage()` and the `pipeline/` golden prefix.
