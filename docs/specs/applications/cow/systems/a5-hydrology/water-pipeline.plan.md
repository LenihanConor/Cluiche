## Decision: who builds the static tables (binding on both plans)

Feature 1 already built (its ACs 16 to 18 need them): the working basin set and capacities, the in-basin flow directions, the **downstream index** and the **topological order**. **This plan fills the empty `BuildRoutingTables()` seam**: per-cell release rate `k`, trees grouped by terminal, the largest-tree node count. It reads the downstream index and the order; it does not rebuild them. If Feature 1's tables lack something the cascade needs (for example a per-node tree id), the field is added to Feature 1's table struct in a named step of the routing-table task and Feature 1's tests rerun. `BasinCurve` and `RederiveCommitted()` come from Feature 1; this plan adds edge tests only.

## Implementation Patterns

### Parameters come from the snapshot (changed)
- Every pass reads one `HydrologyParameters` struct (the per-step `ParamBinding<HydrologyParameters>` snapshot). No pass reads `ParameterFile`, a hash lookup or a JSON value.
- The biome lookups `soil_capacity[biome]`, `infil_rate[biome]`, `veg_factor[biome]` read the struct's `BiomeIndex`-indexed arrays. Biome count is the registry's `Count()`.
- **Soil capacity** in passes 3, 7 and 8 and in the soil-room limit is `effectiveSoilCapacity[cell]` = `soilCapacity[biome] * soilDepthMult[cell]`, built by Feature 1. `terrain.runoff` is not consumed: no code reads it, and `HydrologyTerrain` has no such member.
- `routing.release_floor <= routing.release_ceil` and `freeze.threshold <= freeze.thaw_temp` are sidecar constraints, so passes assume them and carry no defensive check for them (only an assert in Debug).
- Which parameters are live between steps and which are init-only is undefined in the spec (Open item 1). One task below is parked on that answer.

### Public types (Task 3)
- `WaterInput.h` (header only): `WaterSinks`, `WaterInput` (`waterToGround`, `temperature`, `snowPack`, `glacierInput`, `extraWater`, `sinks`, `uint8_t week`) and `WaterTotals` (double `in, seaOut, etOut, drawOut, drawUnmet, basinEvapOut, fixedLakeMakeup, storage, error`; `uint32_t floodedCells, deepCells, glacierCells, largestTreeNodes`), as the spec. Null `extraWater` or sink arrays mean zero and one, read through one small inline accessor each.
- `FixedWaterInput`: `SetConstant`, `SetScript` (two equal-length `DynamicArrayC<float>`, played in a loop), `ForWeek(week)` returning pointers into member arrays; `snowPack` and `glacierInput` are zero arrays. No `std::` type in the signature (PD-004).

### Lifecycle (Task 4)
- `HydrologySimulation` gains `Step(const WaterInput&, IParallelExecutor&)`, `LastTotals()`, `RebaselineStorage()`. `Step` before `Initialise` asserts in Debug and is a no-op in Release.
- Two field sets: committed and working. `Step` copies committed into working, runs the passes on working, then swaps. "Inundated" in any pass reads the **committed** flag (last week's), held in a stable array.
- `Step` reads only its `WaterInput`, the committed fields, the parameter snapshot and the immutable terrain and tables (DFS-002).
- **No heap allocation in `Step`.** Every scratch array is sized at `Initialise` or `BuildRoutingTables()`. The test records every array's data pointer and capacity before and after `Step` and asserts they are unchanged.
- Pass order, one function per pass in `HydrologyPipeline.cpp`: `P0 Inputs`, `P1 Freeze`, `P2 Glacier`, `P3 Infiltration`, `P4 ET and sinks`, `P5 Runoff and baseflow`, `P6 Cascade` (in `HydrologyRouting.cpp`), `P7 Basin level`, `P8 Floodplain and counters`, `P9 Passability`, `P10 Glacier counters`, `P11 Clamp and totals`. Each local pass is one `executor.ParallelFor(N, kMinRange = 256, fn)` writing only its own cells, wrapped in `DIA_PROFILE_SCOPE`.

### Routing tables and basin curve (Tasks 5 and 6)
- `HydrologyRouting.h/.cpp`: release rate `k[c] = isRiver ? clamp(release_min + release_slope * drop, release_floor, release_ceil) : hillslope_release`, `drop = max(0, elevation[c] - elevation[downstream[c]])`, 0 at a terminal. `ReleaseRate(...)` is exported (Feature 5 calls it).
- **Trees** are the connected components of the routing graph (cells plus basin nodes), one per terminal. Grouping uses **`ConnectedComponents`** over a small `RoutingGraph` adapter (satisfies `CIndexGraph`; neighbours are the downstream node and the upstream nodes, in a fixed order, node count `N + basinCount`), not a local flood fill. The result is stored as a CSR (`treeFirst[]`, `treeNodes[]`) in the Feature 1 topological order within each tree. `largestTreeNodes` is the biggest tree.
- **Cascade (P6):** `ParallelFor` over trees, ranges balanced by prefix sums fixed at build time. Each tree is serial in stored order. Per cell node (not inundated): `total = riverStore + inflow; out = k * total; riverStore = total - out; riverFlow = isRiver ? out : 0; route(out, downstream)`. `route` adds to `inflow[target]`, except a target that is an inundated cell or a basin pit, which adds to that basin's `inflow`. Per basin node: `volume += inflow + directInput`; `basinEvapOut += basin.evap_rate * meanT * openCells` (`openCells = inundatedCount * (1 - iceFraction)`, clipped to volume); `overflow = max(0, volume - capacity)` routed to the spill cell in the same pass; `volume = min(volume, capacity)`; `inflow = 0`. Terminals: ocean to `seaOut`; a `kFlowSink` land terminal keeps its water as `surfaceWater`.
- Inflow is summed in topological order. Every inflow array is zeroed at the start by the owning range.
- Lake-only worlds: each lake's `volume` stays pinned at capacity, inflow passes through to the spill cell, an evaporation shortfall is added to `fixedLakeMakeup`.

### Local passes (Tasks 9 to 16)
- **P0:** non-inundated land cell `surfaceWater += waterToGround + max(extraWater, 0)`; an inundated cell's amount goes to a per-cell staging array that the cascade gathers into the basin's direct input. Negative `extraWater` is a sink applied through the draw rule (Open item 4).
- **P1:** cell freeze/thaw with hysteresis; basin ice from the mean `T` over the basin's inundated cells (gather by basin range, serial inside a basin). Basin ice never changes `volume`.
- **P2:** `glacier += glacierInput`; melt above `glacier.melt_threshold` goes to `surfaceWater` (or the basin direct input on an inundated cell) and routes this week.
- **P3:** infiltration with `frozen_ground_factor`, using `infilRate[biome]` and `effectiveSoilCapacity`; percolation above `field_capacity * effectiveSoilCapacity`; springs return the ground-water excess to `surfaceWater`. Inundated cells skip.
- **P4:** soil ET with `vegFactor[biome]`, surface evaporation, then `sinks.draw` from surface then soil, never `riverStore`; the unmet remainder to `drawUnmet`; each amount to its own double total per range. An inundated cell's draw is unmet. `etMultiplier` applies to soil ET only.
- **P5:** `runoff = max(0, surfaceWater - routing.surface_retention)` and `baseflow = baseflow_rate * groundWater` move into the cell's own `riverStore` on every non-inundated land cell.
- **P7:** per basin: `level = LevelForVolume(volume)`; inundation from `bed < level`; newly inundated cells move `surfaceWater`, `soilMoisture`, `groundWater`, `riverStore` into the volume (their `ice` stays); newly exposed cells start empty; then `inundatedWeeks` / `exposedWeeks` (`exposedWeeks` counts only where the cached biome is the registry's **Lake role** and the cell is not inundated); then `openWater` through Feature 1's derivation. No biome is named in code: compare against `registry.Role(Lake)`.
- **P8:** `meanFlow += alpha * (riverFlow - meanFlow)` with `alpha = 1 - 0.5^(1/flood.mean_weeks)` computed once per parameter snapshot; flag gather in direction order (neighbours through `HexNeighbours`, order 0..5) into `flooded`; recharge as a serial loop in cell-id order over rivers in flood; recharge room is `effectiveSoilCapacity - soilMoisture`. `lowFlowWeeks` (a frozen week, `ice >= ice_crossing_min`, neither counts nor resets), `glacierWeeks`, `glacierFreeWeeks`. Inundated cells skip the flood part.
- **P9:** calls Feature 1's passability function; writes `passability`; counts `floodedCells`, `deepCells`, `glacierCells`.
- **P10:** only on the check week (mapping recorded by Feature 1's foundation check): `snowYears` increments where `snowPack >= glacier.snow_floor` (equal counts), else 0; `glacierEligible = snowYears >= onset_years`.
- **P11:** clamp every field non-negative with the excess pushed into the next store (never dropped), clamp `iceFraction` to [0, 1], then totals: per-range `double` sums combined in range order into `WaterTotals`. `error = in - out - (storage - storagePrev)`; `RebaselineStorage()` resets `storagePrev`.

### Determinism
- Local passes write only their own cells. Cascade ranges own whole trees; basins live inside trees. Flood flags are a gather; recharge is serial in cell-id order. Totals reduce per range and combine in range order. Bit-identical at 1, 2, 7 and 16 ranges, with `SerialExecutor`, and with a reverse-order executor.
