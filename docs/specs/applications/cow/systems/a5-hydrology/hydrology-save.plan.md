## Implementation Patterns

### Use the kit, never reimplement it
- **Record and codec:** declare A5's arrays as a `SavedField[]` (name, kind `f32`/`u8`/`u16`, per-cell or per-basin, layer sidecar key `cow.hydro.layers/<field>`); the kit writes the header (`ready, width, height, cell_count, step_day`, `params_hash`) and the extras A5 declares (`basin_count`, optional `world_hash`), writes arrays at 17 digits with `-0.0` as `+0.0`, and runs the shared `Validate`. There is no `EncodeState`/`DecodeState`/`EncodePending`/`DecodePending` here, no `HashHydrologyParameters`, no in-record `"version"`.
- **Per-cell fields (recount at build from `HydrologyFields`):** `surface_water`, `soil_moisture`, `ground_water`, `river_store`, `river_flow`, `mean_flow`, `ice`, `glacier`, `inundated_weeks`, `exposed_weeks`, `low_flow_weeks`, `glacier_weeks`, `glacier_free_weeks`, `snow_years`, `glacier_eligible`, `flooded`, plus the biome array through the kit's biome palette. Per-basin: `basin_volume`, `basin_ice_fraction`. The list is built by iterating the hydrology-data plan's saved members, so a new saved field is covered by the round-trip test automatically.
- **Ranges** come from the layer sidecar entry `cow.hydro.layers/<field>` (min/max). A field with no layer gets its range from a hydro state sidecar entry. A test fails if any `SavedField` resolves no range from either place.
- **Biomes** are stored through the kit's palette (`biome_palette: [ids]`, per-cell index into it). On load the palette is remapped through `ResolveOrFallback` with one Warning per unknown id; a registry-hash mismatch with a clean remap is one Info. `biome` validates against the palette length, never against a literal 13.
- **Version:** `GetVersion()` returns `kFormatVersion`; upgrades use `RegisterMigration` (kit-tested). No `"version"` key in the record. The export file `cow.hydro_state` keeps the F-3 envelope (owned by the debug feature).
- **Participant id** `cow.hydro` (registered in `HydrologyModule::DoStart`, unregistered in `DoStop`; `SaveLoadModule` is a soft dependency).
- **Params hash:** `params_hash = ParameterFile::Hash()` (covers the three biome maps). A mismatch is one Warning plus Degraded (`kParamsMismatch`), cleared by a reload or a pack apply, no rescale (kit step 6).
- **Restore sequence** is the kit's seven steps, including the event-order fallback (stash the validated record, apply on the next matching `WorldGenerationComplete`). A5 supplies only the hooks: `InitialiseSim`, `RestoreCommitted(record)`, the dimension/`basin_count`/`world_hash` identity check, and `mRestoredRevision` semantics (ignore a re-announce at that revision; `BeginSpinUp` returns null for it; ignore a `CompleteSpinUp` whose revision is not the target or equals `mRestoredRevision`).
- **Pending blob** is the kit's `{pending_version: 1, valid, step_day, cell_count, ...}`; a discarded or invalid step writes `{pending_version: 1, valid: false}` (never nothing). A5 adds `basin_count`, the basin arrays and `WaterTotals` (doubles bit-exact, counters as integers). `ValidatePending` runs the same checks as `Validate`. The coordinator wraps the stage in `stage_N`, so the stage writes at the current node.
- Nothing latched is saved (sinks, influences, source view, fixed-driver position). A pending step is a completed working set and is applied, never re-run.

### A5-specific pieces
- **Simulation surface** on `HydrologySimulation`: `RestoreCommitted(uint64_t week, const HydrologyStateRecord&)`, `RestoreCompleted(const HydrologyStateRecord&, const WaterTotals&)`, `RederiveCommitted()` (the code `Initialise` ends with for basin `level`, `openWater`, `passability`; factor out if inline), `GetWorkingBasins()`, `GetWorkingTotals()`. All validate sizes and return false without changing state. `HydrologyStateRecord` is a plain struct of `DynamicArrayC` (PD-004); biome is `BiomeIndex`.
- **`IWorldHashSource` seam** returns "none" until F-3 builds `GetWorldContentHash()`; the hash check runs only when both sides have one.
- **Mixed A4/A5 table** (kept as in the spec): both in save restore both; A4 in, A5 absent: A5 loads fresh and takes the seed-only path (Degraded); A5 in, A4 absent: A5 restores and `BeginSpinUp` returns null for that revision.
- Participant registration order is by attach time: after S-1's, before DeferredStep's (that participant attaches on `DeferredStepModule`'s first `DoUpdate`). `FakeSaveRegistry` records order.

## Open items

Spec gaps found while rebuilding (none resolved here):

1. **Header mismatch.** The kit header carries `step_day`; hydrology-save's record carries `week` (`int64_t`) and ACs 6 and 15 talk about the "restored week". It is not stated whether the committed record's `week` is replaced by the kit's `step_day`, kept as an A5 extra, or derived with `WeekOf`.
2. **Field-count drift.** The spec says "the constant list now has 15 per-cell entries" but the hydrology-data members are 16 per-cell arrays (surface, soil, ground, river store, river flow, mean flow, ice, glacier, inundated, exposed, snow years, glacier eligible, low flow, glacier weeks, glacier-free weeks, flooded) plus biome. The plan says recount at build.
3. **Stale spec text.** hydrology-save.md still has, in body and ACs, `"version": 1`, `HashHydrologyParameters` (AC 3), the hand-rolled `Validate` list (`biome >= 13`, literal ranges), `EncodeState`/`DecodeState`/`EncodePending`/`DecodePending` in Public API and "Codec (pure)" ACs 1 to 4 that the kit now covers. The amendment says which supersede, but there are no replacement ACs (AC 3 and AC 12 in particular), and Files Touched lists `HydrologyStateCodec.h/.cpp` as new.
4. **State sidecar undefined.** The kit says a field with no layer "gives its range in the system's state sidecar", but no spec names the hydro state sidecar's path, schema key, or which owner authors it. The hydrology-debug spec decides which saved fields have layer entries.
5. **Restore hooks into the base.** The kit's restore sequence sets `mRestoredRevision` and the pending-restore step sets the captured day, valid flag and capture revision, but `WorldStepStageBase` exposes none of these through its hook list; how `DeserializePending`/`RestoreCompleted` write base-owned members is undefined. The module amendment also does not say whether `mRestoredRevision` lives in the base or the module.
6. **Palette versus `uint8_t` saved arrays.** The kit palette (Spec-6 item 1) changes the biome array to a palette index, but hydrology-save AC 2 still says "a biome >= 13", the Public API record has `DynamicArrayC<uint8_t> biome`, and the pending blob example still shows raw biome ids. Whether the pending blob also carries a palette (and a second remap) is not stated.
7. **Size and Release.** AC 28 asks for a Release report; current verification rules drop Release gates (moved to the World Step weather-stack close-out). Also the 8 MB bound against A4's 5 MB with both pending blobs is unchecked against `SaveContext::kBufferSize`.
8. **`GetWorldContentHash()`** remains an unbuilt F-3 seam; the hash branch is tested only against a fake.
9. **`Apply` tolerance ownership** for `chain.Commit() == false` is claimed by both the World Step feature (AC 20a) and the A4 weather-save plan; this plan only asserts it. If neither builds it, tasks 19 and 20 block.
10. **Spec text on registration** still says `RegisterParticipant(StringCRC("cow.hydro"), ...)` in `HydrologyModule::DoStart` while the module amendment moves provider wiring into `OnStartExtra`; whether participant registration is a base hook or stays in the module's `DoStart` is unstated.
