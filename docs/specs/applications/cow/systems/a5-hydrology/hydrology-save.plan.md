## Implementation Patterns

### Files and layout
- New: `Cluiche/CoW/Shared/Hydrology/HydrologyStateCodec.h/.cpp` (pure; `HydrologyStateRecord`, `EncodeState`, `DecodeState`, `EncodePending`, `DecodePending`, `HashHydrologyParameters`), `Cluiche/CoW/Modules/HydrologySaveParticipant.h/.cpp` (thin `ISaveable`, `cow.hydrology`). Edited: `HydrologySimulation`, `HydrologyModule`, `HydrologyStage`.
- Tests: `Cluiche/Tests/GoogleTests/CoW/Hydrology/{TestHydrologyStateCodec,TestHydrologySaveParticipant,TestHydrologyPendingSave}.cpp`. Fakes live in `Cluiche/CoW/Shared/Hydrology/Testing/` (reuse the Feature 3 fakes: `FakeWaterSource`, `FakeStepChain`, `FakeWorldStepRegistry`, `SynchronousLauncher`; add `FakeSaveRegistry.h` that records participant registration order).
- `vcxproj` through `dia docs vcxproj-add` only. Namespace `CoW::Hydrology`; log channel `HYD`.

### Tasks 3 to 6: Codec (pure)
- `HydrologyStateRecord` is the decoded form of the JSON (width, height, cellCount, basinCount, `int64_t week`, paramsHash, optional worldHash, `HydrologyFields fields`, `DynamicArrayC<uint8_t> biome`, `DynamicArrayC<float> basinVolume`; basin `iceFraction` rides in the record too). The JSON dependency stays at the codec boundary: `Json::Value`-level functions `EncodeState`/`DecodeState`; the participant writes through `SaveContext`.
- Saved arrays are exactly Feature 1's saved list: `surface_water`, `soil_moisture`, `ground_water`, `river_store`, `mean_flow`, `ice`, `glacier`, `inundated_weeks`, `exposed_weeks`, `low_flow_weeks`, `glacier_weeks`, `glacier_free_weeks`, `snow_years`, `glacier_eligible`, plus `biome`, `river_flow`, `flooded`, `basin_volume`, `basin_ice_fraction`. Iterate Feature 1's descriptor list so a new saved field is covered by the round-trip test automatically.
- Arrays are written with `BeginArray` and `CurrentNode().append(double)` (no array-element writer on `SaveContext`). Floats widen to double at 17 significant digits; `-0.0` is normalised to `+0.0`; `uint8_t`/`uint16_t` are integers. Bit identity is proved through real JSON text (write, `Flush`, parse), never the in-memory `Json::Value`.
- Decode is all-or-nothing: into scratch, moved on success. Error type is a small struct (key, reason) in `String256`, no STL. Range table: floats finite and `>= 0`; `basin_ice_fraction` `[0,1]`; counters `0..65535`; `flooded`/`glacier_eligible` 0 or 1; `biome < 13`; `cell_count == width*height`, `<= 65,536`; `basin_count <= 4,096`; `week >= 0` (`int64_t`, cast to `uint64_t` only after the check); `version` missing, 0 or greater than 1 fails; `ready: false` needs only `version` and `ready`.
- `HashHydrologyParameters`: FNV-1a 64-bit over the bit patterns (`memcpy` to `uint32_t`) of the effective parameters in descriptor-table order, then the biome table in enum order. Adding a row changes the hash by construction.
- Pending: `EncodePending(record, WaterTotals, stepDay, out)` and `DecodePending(..., valid, err)`. Totals are doubles (bit-exact, written at 17 digits); integer counters in `WaterTotals` stay integers. `{"pending_version":1,"valid":false}` decodes with `valid == false` and nothing else required. The coordinator wraps the stage in `stage_N`, so the stage writes at the current node.

### Task 7: Simulation surface
- `RestoreCommitted(uint64_t week, const HydrologyStateRecord&)`, `RestoreCompleted(const HydrologyStateRecord&, const WaterTotals&)`, `RederiveCommitted()` (the same code as `Initialise`'s final derivation of basin `level`, `openWater`, `passability`; factor it out if `Initialise` has it inline), `GetWorkingBasins()`, `GetWorkingTotals()`. All validate sizes and return false without changing state.

### Tasks 8 to 16: Participant and module
- `class HydrologySaveParticipant final : public ISaveable` holds `HydrologyModule&`. `Serialize` writes the record; `Validate(LoadContext&)` calls the codec's pure check and mutates nothing (a test snapshots module state before and after); `Deserialize` runs the seven spec steps in order, factored into `HydrologyModule::OnLoadRestore(const HydrologyStateRecord&)` so the participant stays thin. `GetVersion()` returns `kFormatVersion` (1).
- Registration: `SaveLoadModule::RegisterParticipant(StringCRC("cow.hydrology"), &mParticipant)` in `HydrologyModule::DoStart` only if `SaveLoadModule` resolved (soft dependency); unregister in `DoStop`. DiaDeferredStep's participant attaches on `DeferredStepModule`'s first `DoUpdate`, so it always follows; the registration-order test uses `FakeSaveRegistry`.
- `Deserialize` step 3 builds a `HydrologyTerrain` through Feature 3's `BuildHydrologyTerrain`; a dimension, `basin_count` or (when both sides expose one) content-hash mismatch, or a failing `Initialise`, takes the discard path: one Warning naming both values, ordinary fresh path, load succeeds. `GetWorldContentHash()` is an unbuilt F-3 seam, so the hash check is behind an `IWorldHashSource` that returns "none" until it exists.
- `mRestoredRevision` is module state; the `WorldGenerationComplete` handler and `BeginSpinUp` (returns null when `mRestoredRevision == revision`) honour it. `CompleteSpinUp` for a ticket whose revision is not `mTargetRevision` or equals `mRestoredRevision` is ignored.
- `params_hash` mismatch: one Warning, `kParamsMismatch` Degraded cause, cleared by the next `QueueParameterOverrides` or reload apply. Water is not rescaled.

### Tasks 17 to 21: Pending result
- `HydrologyStage::SerializePending(SaveContext&)` writes `{pending_version, valid, step_day, cell_count, basin_count, totals, arrays, biome, basin_volume}` from `WorkingFields()`, the working biome, `GetWorkingBasins()` and `GetWorkingTotals()`; `step_day` is `mCapturedDay`. If there is no valid completed set (`!mStepValid`, or `mCaptureRevision != mTargetRevision`, or nothing captured) it writes `{"pending_version":1,"valid":false}`, never nothing (World Step's `Validate` refuses a save missing a blob for a stage in `order`). The committed set is unchanged by the call.
- `DeserializePending` runs after the participant's `Deserialize`: validate counts against `mActive`, `RestoreCompleted`, set `mCapturedDay = step_day`, `mStepValid = true`, `mCaptureRevision = mActiveRevision`. A `valid: false` blob restores the discard marker, so `Commit()` is a logged no-op with no `HydrologyUpdated`. With no `mActive` or a count mismatch it returns not-ready with an Error. `ValidatePending` shares the codec's checks (no live-state comparison).
- `WorldStepModule::Apply` tolerance for `chain.Commit() == false` (World Step Feature 3 AC 20a) is shared with A4 Feature 4 task 19. Check whether it already exists; if not, add it here with its test in the same commit.
- Nothing latched is saved (sinks, influences, source view, fixed driver position). Tests prove that with fakes absent at load time.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<suite under work, e.g. HydrologyStateCodec*>" --shards 2` (always `--shards 2`); the feature-wide `*Hydrology*` filter runs only in task 25 (2026-11-17, speed-ups). Float fidelity is tested against real text, never mocks. No full-suite run in this plan (the worldstep.plan.md Weather-stack close-out owns it). No `SLOW_` suites. No mutation checks. Sanitizer: on request only (user, 2026-11-17). Timing for AC 28 is a Debug ballpark, reported, not gated; Release check moved to worldstep.plan.md Weather-stack close-out (2026-11-17). One commit per task (code, tests, plan row).
