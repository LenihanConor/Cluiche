## Implementation Patterns

### Files and layout
- Module (`Cluiche/CoW/Modules/HydrologyDebug/`): `HydrologyLayerRegistration`, `HydrologyInundationOverlay`, `HydrologyCommands`, `HydrologyCellDetails`, `HydrologyHistoryEvents`, `HydrologyObservation`, plus `HydrologyDebugDomain` (`#if DIA_DEBUG` only).
- Pure (`Cluiche/CoW/Shared/Hydrology/Debug/`): `HydrologyCommand` (typed model and parser for `state`, `basins`, `find`, `preset`, `balance`), `FloodEpisodeDetector`, `DryRiverDetector`, `LakeRecordTracker`, `FreezeUpDetector`, `ExplainHydroCell`, `HydroFindQueries`, `WeekTotalsRecord`, `InundationOverlayPlan`, `HydroEventConfig`.
- **Not built here (kit owns them):** a parameter command parser, parameter key validation, reply shapes for `set|get|list|reload|save_defaults`, command registration and rollback. `HydrologyCommands` supplies the `cow.hydro.params` binding (the stage's `ParameterFile` and mutation queue) to `ParamCommandHelper` and nothing else for parameters.
- Layer sidecar: `Cluiche/Assets/CoW/Global/Hydrology/` (file name fixed by Task 3), entries `cow.hydro.layers/<field>` for the eight layers (label, unit, ramp, `min`/`max`, hotkey, passability enum with five swatches) and six `kind: "event"` entries. Keys come from `WorldSimNames.h`. The same entry's `min`/`max` is the save range, so the save plan reads this file; neither plan may redefine ranges. Deployed by CoW `pipeline.toml` with `Global/Hydrology/`.
- Tests: `Cluiche/Tests/GoogleTests/CoW/Hydrology/{TestHydrologyLayers,TestHydrologyCommands,TestHydrologyDetectors,TestHydrologyCellDetails,TestHydrologyObservation}.cpp`. Fakes (`FakeCellLayerRegistry`, `FakeSimQueryHost` that can fail the Nth registration, `FakeCellHistoryRecorder`, fake metric and health sinks, `FakeDebugDraw`) go in `Cluiche/CoW/Shared/Hydrology/Testing/`. Reuse the kit's `FakeWorldStage` and fixture `ParameterFile` where they exist. Hand-built terrains come from `HydrologyTestGrids.h` (water-pipeline plan, extended by the presets plan).
- Layers, commands, metrics, health and events compile in **all** configurations (S-3.5 headless needs them in Release). The `IDebugDomain`, card and overlay draw callback are `#if DIA_DEBUG`.
- Namespace `CoW::Hydrology`. No STL in public APIs (PD-004). Stage id is `hydro`; log channel `HYD`; participant id `cow.hydro`.

### Typed command model and sinks
- `struct HydrologyCommand`: tagged union `State{cell?}`, `Basins{id?}`, `Find{kind, limit}`, `Preset{name, mode}`, `Balance{weeks?}`. **No `SetParam`.** `bool ParseHydrologyCommand(const Json::Value&, HydrologyCommand&, CommandError&)` validates every field, names the offending field, parses once. Cell arguments that select cells use `CellSelectorSet` / `WorldCellFields` vocabulary where a selector is accepted. Resolvers are injected (cell count, `{q, r}` to index, basin ids, preset names) so the parser stays pure.
- `class IHydrologyCommandSink { virtual bool Apply(const HydrologyCommand&, CommandReply&) = 0; }` for `preset`. Parameter changes are not a `HydrologyCommand`: the live path is `ParamCommandHelper` over the stage's queue. For the direct-versus-queued equivalence test, a thin `ParamSetAdapter` applies a `params set` either through `ParameterFile::Set` plus rebind between steps (headless runner, S-2.6 scenario setup) or through the queue; it adds no validation of its own.
- `DirectSink` binds a `HydrologySimulation&`; `QueuedSink` calls the module's queue entries (names recorded by Task 0). Equivalence (AC 26) is one test running the same list (one `params set`, one `preset`) and steps against both and comparing state byte for byte. A full queue returns a clear error, never a drop (AC 27). The panel posts the same JSON commands through the console path and never calls the module.

### Pure detectors, explanation, queries, totals record
- Each detector is `update(snapshot view) -> events array`, state in the detector, restarted by `Reset()`. Caps (4 per type per week, largest first) are applied by one `ApplyEventCaps(...)` helper, which also returns the dropped count.
- `FloodEpisodeDetector`: neighbour-connected sets of `flooded` found with `ConnectedComponents` over `HexNeighbours` (predicate `flooded`). A new set with no cell in common with last week's starts an episode; a merge keeps the older id; end when no flooded cell remains. Anchor = highest `riverFlow / (bankfull_factor * meanFlow)`, ties by lowest index.
- `DryRiverDetector`: connected river sets (`ConnectedComponents` with a river-and-dry predicate) of at least `dry_min_cells` with `riverFlow < dry_fraction * meanFlow` and `meanFlow > flood.min_flow`; one event per episode; ends after one non-dry week.
- `LakeRecordTracker`: per-basin high and low since load, `record_margin`, `record_warmup_weeks` record-only; `Reset()` on world change and on load.
- `FreezeUpDetector`: fraction of river cells with `ice >= freeze.ice_crossing_min`; fires on an upward crossing of `freeze_up_fraction`; re-arms below half.
- `HydroEventConfig` is read from `.diaapp` `hydro_events` and `hydro_overlay`, validated by `ValidateHydroEventConfig(...)` and `ValidateHydroOverlayConfig(...)` (key named, defaults used). Thresholds are provisional.
- `ExplainHydroCell(snapshot, terrain, params, cell)` calls the water-pipeline plan's pure helpers (release rate, basin curve, passability rule) and adds nothing to them. Static rows: the three biome maps read through the bound parameter snapshot, `terrain.soil_depth_mult` and the effective soil capacity, biome name and colour from the registry, `terrain.is_protected`, flow direction, release rate `k`. `terrain.runoff` is not shown (A5 does not consume it). If a helper is not exported, only its linkage changes, proven by running the existing `HydrologyPipeline*` tests in the same filter.
- `WeekTotalsRecord`: compact JSON under 1 KB: per-store storage (surface, soil, ground, river store, ice, glacier, basins), the named flows (`in`, `seaOut`, `etOut`, `drawOut`, `drawUnmet`, `basinEvapOut`, `fixedLakeMakeup`), `error`, `floodedCells`, `deepCells`, `glacierCells`, `largestTreeNodes`. Stores must sum to `WaterTotals.storage`.
- `HydroFindQueries`: `floods`, `dry_rivers`, `records`, `deep` over a snapshot plus the detectors' current state; `limit` 1 to 200, reply says when truncated. The `state` and `basins` reply builders live here, paged under the reply cap. The `state` reply's parameter source uses the same `source` vocabulary as `params get` (`default`, `pack:<id>`, `set`).

### Overlay plan and sidecar
- `InundationOverlayPlan`: input `HydrologySnapshot` (`OpenWater(cell)`, per-basin `Level`, `Volume`) and `max_primitives` (default 4,000); output the fill cell set plus basin outline segments, truncated to a coarser mask over the cap with a `truncated` flag. Recomputed only when the version changes.
- The sidecar is validated with `dia validate schema`. Float layers need `min`/`max`, passability needs the enum, six event entries, hotkeys with no clash against A4.

### Module wiring (needs hydrology-module plan Done)
- **Layers.** `CellLayerRegistry::Register(CellLayerDesc)` after `WorldGenerationComplete` for the eight layers, ids from `WorldSimNames::LayerId("hydro", field)`. Base layers, pull callback `read(float*, uint32_t)` copies the committed array; `version()` is the commit counter. `flooded` and `passability` (`uint8_t`) are converted to float at `Commit` into module-owned buffers. `ice` is clamped for display. Count mismatch writes zeros and logs once. Not-ready callbacks report zero cells. Unregister in `OnStopExtra` / `DoStop`; re-entry re-registers with no duplicate. A result other than `Ok` logs Error and sets Degraded through the base's health reporter (cause code).
- **Overlay.** `CellOverlayDesc` draw callback, `DIA_DEBUG` only, thin over `InundationOverlayPlan`. Truncation Warning once per world.
- **Details.** `CellLayerRegistry::Details()` rows (64 max) for exactly one selected cell, plus hover extra, from `ExplainHydroCell`. Committed values are read through the `hydro.*` fields in `WorldCellFields` where they exist, not a private list.
- **Commands.** Six names through **`SimCommandSet`** (all-or-nothing, own-kind rollback): `cow.hydro.state`, `.basins`, `.find`, `.params`, `.preset`, `.balance`. Each has `SimHelpInfo` (description 1 to 256 chars, category `hydrology`, owner `HydrologyModule`, at most 16 `ValueParam`s). `cow.hydro.params` is created by `ParamCommandHelper`; A5 registers no system action. One handler per remaining name: parse, call the sink or the query builder, format the reply (mutations say they latch at the next `Capture`). `DIA_TRACE_ZONE` per handler. `cow.hydro.balance weeks=N` runs on a copy of the committed state under the fixed-input driver; if Task 2 finds no async reply, cap `weeks` low or run it in the headless runner only, and flag it (Open Question 3, user decides).
- **History.** No history layers beyond the eight base layers. `kDefaultTrackedHydroLayers[4]` = `river_flow`, `soil_moisture`, `flooded`, `glacier` (names after the spec-6 rename). The module only exposes the list; S-2.6 posts `cells.history.track`. Events through `CellHistoryRecorder::Emit(HistoryEvent{type, group, cell, payloadJson, text})` from the stage's commit hook (`PublishCommit` area). `hydro.totals` every applied week. Detector state is SimPU-only and not saved.
- **Metrics** (`MetricInfo`, written once per applied step on SimPU only). The base registers `cow.hydro.step_ms` and `cow.hydro.discarded_steps` (amendment 5): this plan registers none of those. This plan adds `cow.hydro.balance_error`. `cow.hydro.largest_tree_nodes` and `cow.hydro.events_dropped` are open item 1: count the dropped events (AC 16 needs it) but register them only when the spec is clarified.
- **Health** extends the base's reporter with A5 cause codes: Degraded when `|error| > 1e-4 * max(in, out, 1)`, clearing after a clean week; Failing on any NaN or infinite total; Degraded on layer, overlay or command registration failure.
- **Logs** (`HYD`): Info on init, layers and commands registered, preset loaded; Warning on balance breach and unmet draws (each at most once per simulated year with a suppressed count), hotkey clash, rejected command, truncated overlay, untracked history layer; Error on registration failure or non-finite total.
- **Card** (`#if DIA_DEBUG`): `HydrologyDebugDomain : IDebugDomain`, description at most 80 chars, accent from `DebugGroupAccents`, registered through the route found in Task 2. Reads `HydrologyDebugStats` from the stream found there, never module state. Shows the week, counts, water totals, balance error gauge, step ms, largest tree nodes, input source. Toggles the overlay and posts commands only. Layout is S-2.6's.

- Per task: narrow `dia run googletest --filter="<suite under work>" --shards 2` (always `--shards 2`). Add `:*CellLayer*` only when a task touches layer registration and could affect DiaCellLayers fakes; add `:*SimCommandSet*:*ParamCommand*` when a task touches command registration. Run the build before any E2E (`dia pipeline --target cluichetest --stage compile-code`, or the CoW equivalent); kill any leftover game exe first. Verify world behaviour by cell data and stats, not screenshots.
- **No full-suite run in this feature** (once, in the World Step weather-stack close-out). No mutation checks. Sanitizer on request only. Perf is a Debug ballpark, reported, not gated. The Release compile check lives in that same close-out.

## Open items

SPEC GAPS found while rebuilding (not resolved here):

1. **Metric set.** Amendment 5 says the base registers `step_ms` and `discarded_steps` and this feature adds "the water-balance gauge only". AC 29, Goal 8 and the instrumentation text still list `cow.hydro.largest_tree_nodes` and `cow.hydro.events_dropped`, and AC 16 counts into `events_dropped`. Spec must say whether those two stay.
2. **Per-store split of `WaterTotals.storage`.** `hydro.totals` needs a per-store array (surface, soil, ground, river store, ice, glacier, basins). Water-pipeline spec has one `storage` double. Needs agreement before the totals task.
3. **Layer ids not renamed in this spec.** The layer table, AC 10 and `kDefaultTrackedHydroLayers` still say `hydro.soil`, `.ground`, `.surface`, `soil`. The a5-hydrology.md spec-6 resolution renames them to `hydro.soil_moisture` and so on, and hydrology-debug.md has no spec-6 section. This plan uses the renamed ids.
4. **Params key form.** Amendment 1 writes `hydro.biome.<column>.<BiomeId>`; the kit addresses a map column as `<key>.<mapKey>`, and the biome maps are `hydro.biome.soil_capacity` etc., so the form is key-then-id with a dotted id (`Biome.Grassland`). Ordering and dotted ids need one written rule. ACs 19 and 21 still name `set_param` and `biome_table.<BiomeId>.<column>`.
5. **`balance weeks=N` hitching** (spec Open Question 3) is still open. Any shipped cap or async reply is a user decision, and an async reply is AD-001.
6. **Sidecar file name and event entry key form** are not given. Amendment 3 fixes `cow.hydro.layers/<field>` for layers only; the six `kind: "event"` entries have no key pattern in `worldsim-conventions` terms. Also the debug spec says "the schema file ships with this feature" while hydrology-save reads ranges from the same entries; owner and order are undefined.
7. **Panel route.** The spec names `DiaDebugDomainRegistry`/`DiaDebugPanel` and `VisualDebuggerModule::RegisterDomain`; the kit has no shared debug-card piece and the brief says ModuleDebugRegistry. Task 2 settles the route; the spec text should be aligned.
8. **Health cause codes.** The kit says the base holds one reporter and each system declares cause codes, but gives no hook to add A5 gauges-driven Degraded conditions (balance breach, registration failure). Spec says "adds to Feature 3's". Mechanism undefined.
9. **Detail rows and `isCrossing`.** The detail-row Static bullet still lists `isCrossing`; spec-6 renames the clause to `terrain.is_protected` (a wider set than crossings). Amendment 4 covers the biome maps and `soil_depth_mult` only. A4's debug amendment says detail rows read `WorldCellFields`; the A5 amendment does not.
10. **Who contributes the `hydro.*` fields to `WorldCellFields`** is stated only in the presets spec; this plan consumes it from the presets plan.
11. **Direct sink for parameters.** The kit defines only a queued `params set`. AC 26's direct-versus-queued equivalence for parameters needs a direct path that the kit does not define (this plan uses a thin `ParameterFile::Set` adapter).
12. **Display ranges, event thresholds, region groups** (spec Open Questions 1, 4 and the `history.group: true` check) remain provisional, as before.
13. **Queue entry names** for parameter change, `reload` and preset application come from the hydrology-module plan; Task 0 records them.
