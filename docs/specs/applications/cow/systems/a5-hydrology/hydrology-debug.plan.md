## Implementation Patterns

- Module (`Cluiche/CoW/Modules/HydrologyDebug/`): `HydrologyLayerRegistration`, `HydrologyInundationOverlay`, `HydrologyCommands`, `HydrologyCellDetails`, `HydrologyHistoryEvents`, `HydrologyObservation`, plus `HydrologyDebugDomain` (`#if DIA_DEBUG` only).

- Schema: `Cluiche/Assets/CoW/Global/Hydrology/hydrology_schema.json` (DiaValueSchema entries `hydro/<key>`: eight layers, passability enum with five swatches, six `kind: "event"` entries). Deployed by CoW `pipeline.toml` with `Global/Hydrology/`.
- Tests: `Cluiche/Tests/GoogleTests/CoW/Hydrology/{TestHydrologyLayers,TestHydrologyCommands,TestHydrologyDetectors,TestHydrologyCellDetails,TestHydrologyObservation}.cpp`. Fakes (`FakeCellLayerRegistry`, `FakeSimQueryHost` that can fail the Nth registration, `FakeCellHistoryRecorder` recording `Emit` and track calls, fake metric and health sinks, `FakeDebugDraw`) go in `Cluiche/CoW/Shared/Hydrology/Testing/`. - Layers, commands, metrics, health and events compile in **all** configurations (S-3.5 headless needs them in Release). The `IDebugDomain`, card and overlay draw callback are `#if DIA_DEBUG`.
- Namespace `CoW::Hydrology`. No STL in public APIs (PD-004): `DynamicArrayC`, fixed-capacity arrays, `String64`/`String256`.

### Tasks 4, 5a, 5b: Typed command model and sinks
- `struct HydrologyCommand`: tagged union `State{cell?}`, `Basins{id?}`, `Find{kind, limit}`, `SetParam{key, value}`, `Preset{name, mode}`, `Balance{weeks?}`. `bool ParseHydrologyCommand(const Json::Value&, HydrologyCommand&, CommandError&)` validates every field, names the offending field, parses once. Handlers and both sinks consume only the typed value.
- Resolvers are injected (cell count and `{q, r}` to index, basin ids, biome ids and columns, preset names, `SetParam` check from Feature 1) so the parser stays pure.
- `class IHydrologyCommandSink { virtual bool Apply(const HydrologyCommand&, CommandReply&) = 0; }` for the two mutating commands. `DirectSink` binds a `HydrologySimulation&` and applies between steps (headless runner, S-2.6 scenario setup). `QueuedSink` calls Feature 3's parameter-change and preset-application entries (names TBD in Feature 3, recorded by Task 0). Equivalence (AC 26) is one test running the same list and steps against both and comparing state byte for byte. A full queue returns a clear error, never a drop (AC 27).
- The panel posts the same JSON commands through the console path. It never calls the module.

### Tasks 6 to 11: Pure detectors, explanation, queries, totals record
- Each detector is `update(snapshot view) -> events array`, state in the detector, restarted by `Reset()`. Caps (4 per type per week, largest first) are applied by one `ApplyEventCaps(...)` helper, which also returns the dropped count for `cow.hydro.events_dropped`.
- `FloodEpisodeDetector`: neighbour-connected sets of `flooded`; a new set with no cell in common with last week's starts an episode; a merge keeps the older id; end when a set has no flooded cell. Anchor = highest `riverFlow / (bankfull_factor * meanFlow)`, ties by lowest index.
- `DryRiverDetector`: connected river sets of at least `dry_min_cells` with `riverFlow < dry_fraction * meanFlow` and `meanFlow > flood.min_flow`; one event per episode; ends after one non-dry week.
- `LakeRecordTracker`: per-basin high and low since load, `record_margin`, `record_warmup_weeks` record-only; `Reset()` on world change and on load.
- `FreezeUpDetector`: fraction of river cells with `ice >= freeze.ice_crossing_min`; fires crossing `freeze_up_fraction` upward; re-arms below half.
- `HydroEventConfig` is read from `.diaapp` `hydro_events` and `hydro_overlay`, validated by `ValidateHydroEventConfig(...)` and `ValidateHydroOverlayConfig(...)` (key named, defaults used). Thresholds are provisional.
- `ExplainHydroCell(snapshot, terrain, params, cell)` calls Feature 2's pure helpers (release rate, basin curve, passability rule) and adds nothing to Feature 2. If a helper is not exported, only its linkage changes (no behaviour change), proven by running the existing `HydrologyPipeline*` tests in the same filter.
- `WeekTotalsRecord`: compact JSON under 1 KB: per-store storage (surface, soil, ground, river store, ice, glacier, basins), the named flows (`in`, `seaOut`, `etOut`, `drawOut`, `drawUnmet`, `basinEvapOut`, `fixedLakeMakeup`), `error`, `floodedCells`, `deepCells`, `glacierCells`, `largestTreeNodes`. Stores must sum to `WaterTotals.storage`.
- `HydroFindQueries`: `floods`, `dry_rivers`, `records`, `deep` over a snapshot plus the detectors' current state; `limit` 1 to 200, reply says when truncated. `state` and `basins` reply builders live here too, paged under the reply cap.

### Tasks 12 to 14: Overlay plan, schema
- `InundationOverlayPlan`: input `HydrologySnapshot` (`OpenWater(cell)`, per-basin `Level`, `Volume`) and `max_primitives` (default 4,000); output the fill cell set plus basin outline segments, truncated to a coarser mask over the cap with a `truncated` flag. Recomputed only when the version changes.
- The schema file is validated with `dia validate schema` (Task 14). Float layers need `min`/`max`, passability needs the enum, six event entries, hotkeys with no clash against A4.

### Tasks 15 to 22: Module wiring (Blocked until A5 F3)
- **Layers.** `CellLayerRegistry::Register(CellLayerDesc)` after `WorldGenerationComplete` for `hydro.soil`, `.ground`, `.surface`, `.river_flow`, `.flooded`, `.ice`, `.glacier`, `.passability`. Base layers, pull callback `read(float*, uint32_t)` copies the committed array; `version()` is the commit counter. `flooded` and `passability` (`uint8_t`) are converted to float at `Commit` into module-owned buffers, not on the render path. `ice` is clamped for display. Count mismatch writes zeros and logs once. Not-ready callbacks report zero cells. Unregister in `DoStop`; re-entry re-registers with no duplicate. A result other than `Ok` logs Error and sets Degraded.
- **Overlay.** `CellOverlayDesc` draw callback, `DIA_DEBUG` only, thin over `InundationOverlayPlan`. Truncation Warning once per world.
- **Details.** `CellLayerRegistry::Details()` rows (64 max) for exactly one selected cell, plus hover extra, from `ExplainHydroCell`.
- **Commands.** Six names through `SimQueryHostModule` with `SimHelpInfo` (description 1 to 256 chars, category `hydrology`, owner `HydrologyModule`, at most 16 `ValueParam`s). `RegisterAll()` records each success; on any failure it unregisters those done in that call and sets Degraded naming the failing name. Unregister in `DoStop`. One handler per name: parse, call the sink or the query builder, format the reply (mutations say they latch at the next `Capture` and name the week when known). `DIA_TRACE_ZONE` per handler. `cow.hydro.balance weeks=N` runs on a copy of the committed state under the fixed-input driver; if Task 2 finds no async reply, cap `weeks` low or run it in the headless runner only, and flag it (Open Question 3, user decides).
- **History.** The module registers no history layers beyond the eight base layers. `kDefaultTrackedHydroLayers[4]` = `river_flow`, `soil`, `flooded`, `glacier`. The module only exposes the list; S-2.6 posts `cells.history.track` with it. Events through `CellHistoryRecorder::Emit(HistoryEvent{type, group, cell, payloadJson, text})` from `HydrologyStage::Commit` (the driver's next sample commits them). `hydro.totals` every applied week. Detector state is SimPU-only and not saved; detectors restart on load or world change.
- **Metrics** with `MetricInfo`, written once per applied step on SimPU only: `cow.hydro.step_ms` (gauge, sum of Feature 2's per-pass CPU), `cow.hydro.balance_error`, `cow.hydro.largest_tree_nodes` (gauges), `cow.hydro.events_dropped` (counter).
- **Health** (`IHealthReporter`, added to Feature 3's): Degraded when `|error| > 1e-4 * max(in, out, 1)` clearing after a clean week; Failing on any NaN or infinite total; Degraded on layer, overlay or command registration failure.
- **Logs** (`HYD` channel): Info on init, layers and commands registered, preset loaded; Warning on balance breach and unmet draws (each at most once per simulated year with a suppressed count), hotkey clash, rejected command, truncated overlay, untracked history layer; Error on registration failure or non-finite total.
- **Card** (`#if DIA_DEBUG`): `HydrologyDebugDomain : IDebugDomain`, description at most 80 chars, accent from `DebugGroupAccents`, registered with `VisualDebuggerModule::RegisterDomain`. Reads `HydrologyDebugStats` from the stream found in Task 2, never module state. Shows the week, counts, water totals, balance error gauge, step ms, largest tree nodes, input source. Toggles the overlay and posts commands only. Layout is S-2.6's.
