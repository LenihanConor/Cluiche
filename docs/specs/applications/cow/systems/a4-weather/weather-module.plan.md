# Plan: A4 WeatherModule & Deferred Step (A4 Weather Feature 3)

**Spec:** @docs/specs/applications/cow/systems/a4-weather/weather-module.md
**Status:** Not Started
**System plan:** @docs/specs/applications/cow/systems/a4-weather/a4-weather.plan.md (row 3)

Rebuilt 2026-11-18 against the world-sim review amendment. `WeatherStage` now **derives
`WorldStepStageBase<WeatherSimulation, WeatherEntry, WeatherLatch>`** from the World-Sim Kit. The base owns the
active/pending sims, the revision trio, the 128-entry `MutationQueue`, `SpinUpSlot`, `HoldGeneration`, the
discard rule, the visit generation and the `DoStop` order, and tests them once on a fake stage. This plan
therefore **deletes** the hand-written stage state, the hand-rolled queue and spin-up slot, the parameter
loader with its fallback, and the hand-registered message. It supplies the five hooks and the module around them.

**Start conditions.** Needs these plans Done:
- `parameter-files.plan.md` (Dia) and `biome-registry.plan.md` (S-1): `ParameterFile`, `ParamBinding`,
  `BiomeRegistry`.
- `worldsim-kit.plan.md` (World Step): `WorldStepStageBase`, `MutationQueue`, `SpinUpSlot`, `FakeWorldStage`,
  the health cause-code mechanism, `WorldSimNames.h`.
- The World Step plans `step-chain.plan.md` (`IWorldStepStage` with `ValidatePending`, `RegisterStage`) and
  `module-and-cadence.plan.md` (`WorldStepModule`, the world blackboard it owns).
- `blackboard-scopes.plan.md` (Dia): the world board's `Set` for summaries.
- DiaDeferredStep Features 1 to 4 (`IParallelExecutor`, the capped executor, `DeferredStepModule`).
- A4 Features 1, 2 and 6 built (`WeatherSimulation`, `WeatherRunner`, `ApplyPreset`).

`grid-search-helpers.plan.md` is not needed. **Startable earlier on fakes:** `SpinUpJob`, `WeatherCalendar`, the
baseline clamp and the hook bodies (Tasks 4, 5, 8 to 12) are driver-level against `FakeWorldStage` and a
`SerialExecutor`, once the kit's base and fakes exist. Tasks that need the real `WorldStepModule`,
`WorldGenerationModule` events or the capped executor (Tasks 14 to 19) wait for those plans.

No Dia files are added or edited (AD-001 not triggered). If a task finds it needs one, stop and mark it
`AD-001 ask first`.

## Implementation Patterns

### Files and layout
- `Cluiche/CoW/Modules/WeatherModule.h/.cpp` (SimModule), `Cluiche/CoW/Shared/Weather/WeatherStage.h/.cpp`
  (`class WeatherStage : public WorldStepStageBase<WeatherSimulation, WeatherEntry, WeatherLatch>`),
  `WeatherEntry.h` (the nine entry kinds), `WeatherCalendar.h`, `HydrologyInputsProvider.h`
  (`IHydrologyInputsProvider`, its own header so A5's modules do not include `WeatherModule.h`), `SpinUpJob.h/.cpp`
  (pure).
- `WeatherUpdated` is **not hand-written**: it is declared in `cow_worldsim.diagamemessages` and generated by
  `dia codegen messages` (amendment 4). No `WeatherMessages.h`.
- Names (stage id `weather`, save id `cow.weather`, metrics, schema keys) come from `WorldSimNames.h` only; no
  string literals in A4 code (amendment, item 9).
- Tests: `Tests/GoogleTests/CoW/Weather/{TestSpinUpJob,TestWeatherStage,TestWeatherModule}.cpp`. Helpers
  specific to A4 live in `Cluiche/CoW/Shared/Weather/Testing/` (`FakeHydrologyProvider.h`,
  `ObservingExecutor.h`); the stage fakes come from the kit's `Testing/FakeWorldStage.h`.
- Namespace `CoW::Weather`, log channel `WTH`.

### Hook map (replaces the hand-written stage table)
| Base hook | A4 supplies |
|---|---|
| `InitialiseSim(sim, world, cause)` | Read terrain from `GetCurrentWorld()` into a `WeatherTerrain` (biomes as `BiomeIndex`), EC-01 (no water source) returns false with cause `kNoWaterSource`; build the `WeatherSimulation`; the spin-up job (coupled when a host is set) is launched through the base's `SpinUpSlot` |
| `ExtraReady()` | Default true (A5 is a consumer here, not a prerequisite) |
| `LatchInputs(latch, key)` | `ParamBinding::Snapshot` of the `ParameterFile` into the latch's `WeatherParameters`; season and week from `stepDay`; the baseline (provider or table, clamped); A5's `HydrologyInputs`; `mInfluences.Latch()`; `LatchClimate(stepDay)`; returns true |
| `ApplyEntry(working, latch, entry)` | The nine kinds: `SetParam` (`ParameterFile::Set`), `ParamOverrides` (`ApplyPack`), `Reload` (`ParameterFile::Reload`), `Forcing`, `RegionForcing`, `BiomeChange`, `Preset`, `StateReplace`, `ClearWindOverrides` |
| `RunStep(working, latch, exec)` | `sim.Run(exec)`; reads only the latch |
| `PublishCommit(committed, stepDay)` | `sim.Commit()`, `SetCommittedWeek`, `mInfluences.Age(commitDay)`, publish the generated `WeatherUpdated{week, season}`, then `Blackboard::Set` of season, climate phase and drought flags on the world board; ages nothing on a discarded step (the base does not call it) |
| `OnStartExtra` / `OnStopExtra` | Subscribe and unsubscribe the `FileWatcher` reload (dev builds) and the baseline and hydrology provider slots |

### Parameters
- `DoStart` resolves the sidecar and packs through the catalogue and `PathStore`, loads with
  `ParameterFile::Load` (strict) against the `BiomeRegistry` key list, applies the active packs with `ApplyPack`,
  and binds `ParamBinding<WeatherParameters>`. **A sidecar fault sets health Failing naming the key and the stage
  is never ready.** There is no `DefaultWeatherParameters` and no fallback (amendment 2).
- `QueueParameterSet` validates strictly now (`ParameterFile::Set` on a probe, or the helper's validate path) and
  queues; the value applies when drained in `Capture`. `QueueParameterOverrides` takes a pack and calls
  `ApplyPack` when drained. `QueueReload` calls `Reload`. These are the same entries `cow.weather.params`
  (Feature 5, `ParamCommandHelper`) enqueues.
- In dev builds `FileWatcher` calls `QueueReload`; the reload still applies at `Capture`.
- `params_hash` for saves is `ParameterFile::Hash()` (Feature 4).

### Health
`HealthStatus` is `kOK` / `kDegraded` / `kFailing` with an A4 cause-code enum plus text, reported through the base's
one `IHealthReporter`. Degraded: fallback baseline, discarded step, queue full. Failing: no water source,
generation failed, parameter sidecar fault. The text "Unhealthy" does not appear in A4 code or tests. Metrics
(`cow.weather.step_ms`, `cow.weather.discarded_steps`) come from the base; this feature registers none.

### SpinUpJob (pure, Task 4)
- `class SpinUpJob { SpinUpJob(WeatherSimulation& sim, const WeatherTerrain&, uint32_t revision, uint32_t weeks, const IRevisionSource&); enum class Result { Completed, Cancelled }; Result Run(IParallelExecutor&); }`.
  `IRevisionSource { virtual uint32_t GetTargetRevision() const = 0; }` is the only thing it reads from the
  stage. The job checks it **between weeks** and returns `Cancelled`. It delegates the week loop to
  `WeatherRunner::Start(...)`; if the runner exposes no per-week hook, add a cancel predicate to the runner in
  CoW Shared, never duplicate its loop. It publishes nothing: spin-up is silent.
- Spin-up runs `spinup_weeks` from calendar offset 0 (Spring); 52 weeks ends one step before Spring and the first
  live step takes its season from its step day (gap amendment 4). **Length is `spinup_weeks` with climate cycles
  frozen at the start phase (`climateFreezeDay`); nothing extends it.**
- The job's completion goes through the base's `SpinUpSlot`, polled in `DoUpdate`; no bus message or callback.
- Launch seam `ISpinUpLauncher`: `SynchronousLauncher` runs inline (tests); `JobSystemLauncher` uses
  `JobSystemService::TrySubmit(fn, tag)` with the `world` tag and the capped executor, falling back to inline with
  one Warning if `TrySubmit` fails (never drop).
- Coupled spin-up (A5): when an `IHydrologySpinUpHost` is set the stage calls `BeginSpinUp(rev, start)` as it
  launches, steps the returned ticket after each A4 week with A4's working view, then `CompleteSpinUp` at the same
  poll that sets pending; a null ticket means A4 alone; stale or cancelled calls `Destroy(ticket)`.

### A5 seams
- `WeatherModule` implements `IWaterInputSource` (`GetWorkingOutput`, `CopyGroundWaterInfluence`,
  `IsReadyForRevision`) from A5's header-only `HydrologyCoupling.h`. Working buffers are allocated once per
  promotion; the pointers are identical at `Capture` and `Commit`.
- `SetHydrologyProvider(IHydrologyInputsProvider*, IHydrologySpinUpHost*)`, non-owning, null means no A5.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<suite under work>" --shards 2` (always `--shards 2`); the
  three-suite filter runs only in the scoped-verification task. The full suite runs once in worldstep.plan.md,
  Weather-stack close-out. No sanitizer unless asked. No `SLOW_` suites. No mutation checks. Spin-up wall time is
  a Debug ballpark only. Concurrency tests use counters and fake executors, never sleeps.

## Open items

1. **Hosting stage for the manifest.** Resolved by gap amendment 3: every hosting stage declares its own instance after its own `WorldStepModule`; S-2.5 owns the sample.
2. **World blackboard keys.** Amendment item 18 says A4 writes "season, climate phase and drought flags" with `Blackboard::Set`, but the spec and `blackboard-scopes.md` name no keys, value types or owning module. Task 11 needs them; they are a spec gap.
3. **Re-announced identical world** (spec Open Q1) is a known one-week loss; no task builds a content-hash skip. Still open by design.
4. **Spin-up wall time at the Slowest preset on a 2-worker cap** (spec Open Q2) is unmeasured; Task 15 records a Debug ballpark only.
5. **Active and pending as pointers** (spec Open Q3) is now the base's decision (the kit's `TSim* mActive/mPending`); nothing to decide here.
6. **The stage-level text "Unhealthy"** appears throughout the module spec body; the amendment maps it to Failing. This plan treats every instance as Failing.
7. **`WeatherModule` implements `IWaterInputSource`, but the spec does not say who calls `SetWaterSource`** on a test path with no `HydrologyModule`: `FakeHydrologyProvider` is assumed.
8. **A4 reads `ParameterFile` value changes by `Snapshot` per step, but `ParamBinding::Snapshot` is documented for a plain-struct copy "once per step"; whether the `Set` queued mid-step is visible to `LatchInputs` of the same step is not stated.** The plan applies the queue first (arrival order), then snapshots.
9. **Kit hook signature drift.** `LatchInputs(latch, StepKey key)` takes a `StepKey`, while the module spec derives from `stepDay`; the key-to-day conversion is not stated. Task 0 records it.
- **Review 2026-11-16:** `WeatherStateRecord` is created by this feature as a plain struct (decision 5); Feature 4 fills it.
