**Absent, and what this plan does about it:**
- **Real `cow.weather.layers/<field>` and `cow.weather_state` sidecar entries do not exist** (no JSON anywhere; only `weather-debug.plan.md` mentions them). Tasks 4-5 run on a fixture sidecar; the open item says who authors the real ones.
- **No S-1 save participant exists** (WorldGenerationModule is not an `ISaveable`; only `game_speed` and `random_streams` register). The spec's "registers after S-1's" cannot be asserted against a real S-1 participant. Task 1 therefore records what really happens, with the world as the live module state, and the ordering test (Task 12) asserts only "weather before DeferredStep's participant".
- **Features 7 and 8 are not built** (no influence book, no cycles). Record and pending blob omit `influences` and `climate`; the spec lets an absent block load clean. AC 22 and 23 are **Skipped** (Task 16 holds the row).
- **Base gap found by this audit:** after `DeserializePending`, the base does not re-arm commit state: `mStepValid`, `mInFlight`, `mCaptureRevision` and `mCapturedDay` stay at their pre-load values, so a restored step's `Commit()` takes the discard branch (`!mStepValid`) and `SerializePending` after a load writes `valid:false`. `RestorePending` gets no way to set them. Task 6 fixes this in the base (CoW Shared, not Dia).
- `WeatherSimulation` has no `RestoreCommitted`, `RestoreCompleted` or `GetWorkingBiomes`. Biome is not double-buffered (it lives in the owned terrain), so there is no "working biome" array; see Decisions 3.

## Decisions for this build

1. **Layout.** All A4-specific code is CoW under `Cluiche/CoW`; the data half already exists in Draoi and is called, not copied (no new Draoi header). New: `Cluiche/CoW/Shared/Weather/WeatherSaveFields.h/.cpp` (the `FieldDecl[]` of the ten arrays, `ResolveSavedFields` wiring, `EncodeRecord`/`DecodeRecord`/`EncodeState`/`DecodeState`, pending blob field write and read), `Cluiche/CoW/Modules/Weather/WeatherSaveParticipant.h/.cpp` (thin `ISaveable`, id `cow.weather`, `GetVersion()` = 1). Edited: `WeatherStage` (`WeatherHooks` restore and pending hooks, `SetRecordSpec`/`NoteCommittedRecord` wiring, a `Restore` pass-through), `WeatherModule` (registration, `ModuleRef<SaveLoadModule>`), `WeatherStateRecord.h` (fills it), `WeatherSimulation` (Draoi edit, Task 3), `WorldStepStageBase.h` (Task 6). Tests: `Tests/GoogleTests/CoW/Weather/{TestWeatherSaveFields,TestWeatherSaveParticipant,TestWeatherPendingSave}.cpp`. vcxproj through `dia docs vcxproj-add` only.
2. **Record shape follows the kit, not the spec's literal JSON** (spec world-sim review amendment 2, 4, 5 win): no in-record `version` (`ISaveable::GetVersion` and `SaveRegistry::RegisterMigration`); `params_hash` is `ParameterFile::Hash()`; field ranges from the sidecar; biomes as `biome_palette` + per-cell palette index; header from `WriteHeader` (`ready, width, height, cell_count, step_day, params_hash, basin_count, world_hash`); weather writes `basin_count` 0 and `world_hash` 0 (no S-1 world hash is available to A4).
3. **`week` vs `step_day`.** The kit header has `step_day` (int32), the spec record has `week`. Plan: write `step_day` = `committedWeek * kDaysPerWeek` (the first day of the last committed week, so `WeekOf(step_day)` is exactly the saved week and no new sim state is needed) and restore `week = WeekOf(step_day)`. Flagged in Open items 2. **Biomes:** the saved biome array is `sim.Terrain().biome` (the A4-cached biome including `SetCellBiome` changes). The pending blob carries the ten field arrays only (the biome is not step-buffered, so it adds nothing a committed record lacks); `GetWorkingBiomes()` is not built (spec deviation, Open items 3). `RestoreCommitted` applies biomes through a new `WeatherSimulation::SetBiomes` or a `SetCellBiome` loop (Task 3 picks the loop unless it fails the no-allocation rule).
4. **Ordering and the world.** The weather participant registers in `WeatherModule::DoStart` (after `GameSpeed`/`RandomStreams`, before DeferredStep, which attaches on its first `DoUpdate`). The kit's `Restore` handles both event orders (record before world is stashed; world before record applies at once), so A4 adds no stash of its own. Task 1 records which one the real E1 path takes.
5. **Missing optional state.** Forcings, wind overrides, the queue and presets are not saved (spec Non-Goals). `influences` and `climate` blocks are not written and an incoming record that has them is accepted with the blocks ignored and one Info (Features 7 and 8 own them when built).
6. **StateReplace apply is not built here.** This feature builds the encode and decode and fills `WeatherStateRecord`; the Capture-time apply branch belongs to the plan that owns `state import` (Feature 5) because it needs Feature 6's reseed. The `kStateReplace` drain warning stays until then.
7. **Verification cadence.** Per task `dia run googletest --filter="<suite under work>" --shards 2` only; the three-suite filter runs in the scoped-verification task; the full suite, single Release build and cross-feature determinism run once in `worldstep.plan.md` Weather-stack close-out. No sanitizer unless asked, no `SLOW_` suites, **no mutation checks**. The AC 20 timing is a Debug ballpark. Float fidelity is tested through real JSON text (a real `SaveManager` temp slot), never mocks.
8. **AD-001 / escalation.** Task 3 edits an existing Draoi class (no new Draoi file) and is marked ask-first; no Dia file is touched.

## Open items for the user (resolve before building)

1. **Sidecar ranges.** `cow.weather.layers/<field>` entries (or `cow.weather_state/<field>`) do not exist in any JSON. Tasks 4-5 run on a fixture, but a real save needs the ten ranges (`water_to_ground` and `pressure_anomaly` may have no layer). Decide: author them in this feature (add a task) or leave them to `weather-debug.plan.md`. `wind_direction` is `[0, 2pi)` in the spec but a sidecar `[min, max]` is inclusive (the kit uses `[0, 2pi]` and the caller normalises).
2. **`week` vs `step_day`.** The spec record has `week`; the built kit header has `step_day`. This plan saves `step_day = week * 7`. Confirm, or amend the spec/kit.
3. **`GetWorkingBiomes()` and biomes in the pending blob.** Biome lives in the sim's owned terrain (not double-buffered), so the spec's `GetWorkingBiomes`, `RestoreCompleted(fields, biomes)` and the pending `biome` array have nothing to carry. Plan drops them (pending blob = ten arrays). Confirm.
4. **"Registers after S-1's participant" cannot be true:** no S-1 save participant exists, so on a load the world is whatever the live module holds. Is an S-1 participant (or a world-from-seed rebuild on load) planned? If so the world-order assumption in Task 1 and AC 13 changes.
5. **Spec contradictions that the amendment already resolves** (plan follows the amendment): the record's in-record `version`, `HashWeatherParameters`, `biome >= 13`, hand-ordered `Deserialize`, the `WorldStepModule::Apply` edit, `"valid:false"` omission text. No action needed unless you disagree.
6. **Base fix (Task 6)** edits the shared `WorldStepStageBase` so a restored pending step can commit; it affects every world-sim stage. Confirm placement (it is CoW Shared, not Dia).
7. **Task 3 edits Draoi `WeatherSimulation`** (adds restore methods; no new header). Confirm under the escalation rule.
8. **Features 7 and 8 are unbuilt:** ACs 22-23 and the `influences`/`climate` blocks stay Skipped; spec stays Approved-with-deferrals unless you decide otherwise. StateReplace apply (Decisions 6) is left to Feature 5/6.
9. Spec Open Design Question 2 (a `strict` load option for S-3.5 R2) stays unbuilt.
