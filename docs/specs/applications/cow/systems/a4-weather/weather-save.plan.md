## Implementation Patterns

### Files and layout
- New: `Cluiche/CoW/Shared/Weather/WeatherStateCodec.h/.cpp` (pure), `Cluiche/CoW/Modules/WeatherSaveParticipant.h/.cpp` (thin `ISaveable`). Edited: `WeatherSimulation`, `WeatherModule`, `WeatherStage`.
- Tests: `Tests/GoogleTests/CoW/Weather/{TestWeatherStateCodec,TestWeatherSaveParticipant,TestWeatherPendingSave}.cpp`.
- `vcxproj` through `dia docs vcxproj-add` only.

### Task 1: E1 + S-1 event-order spike (gating)
- An integration test, not a unit test: real `SaveManager`/`SaveLoadModule` with a probe participant registered after S-1's, a real or faithful S-1 world source, then `Load`. Record in order: probe `Validate`, probe `Deserialize`, every `WorldGenerationComplete` with its revision, and whether `GetCurrentWorld()` is non-null and at what revision at probe `Deserialize` time.
- Output is a written finding in notes with one of three outcomes: (A) completion arrives before A4's `Deserialize` with a revision A4 sees; (B) completion arrives after with an unseen revision (the bad case); (C) no completion on load. Tasks 10, 14, 15 follow outcome A or C as written in the spec; outcome B switches task 10 to the committed fallback design (amendment 3): the participant stashes the parsed, validated record and applies it on the **next** `WorldGenerationComplete` after the load (instead of spinning up) provided dimensions match; a mismatching completion discards the stash with a Warning and spins up; the stash is dropped on `DoStop` and on any later regeneration. Do not write the participant's Deserialize before this finding is recorded.

### Tasks 3 to 6: Codec (pure)
- `WeatherStateCodec`: `bool EncodeState(const WeatherSnapshotData&, SaveContext&)`-style split into pure halves: `Json::Value`-boundary functions `EncodeFields(const WeatherFields&, const DynamicArrayC<uint8_t>& biomes, Json::Value& out)` and `DecodeFields(const Json::Value&, uint32_t cellCount, WeatherFields&, DynamicArrayC<uint8_t>&, CodecError&)`. `CodecError` is a small struct (key, reason), no STL, like `ParamError`.
- Arrays are written with `BeginArray` plus `CurrentNode().append(double)`; `-0.0` normalised to `+0.0` on write. Floats widen to double and narrow back; the test proves bit identity through the actual JSON text (write, `Flush`, parse), not through the in-memory `Json::Value`.
- Decode is all-or-nothing: decodes into scratch and moves on success. Range table: seven fields `[0,1]`, `windDirection [0, 2π)`, `pressure_anomaly [-0.5, 0.5]` (amended 2026-11-17 (row 6d)), biome `< 13`, `cell_count <= 65536`.
- `version` missing, `0` or greater than 1 fails (amendment 1). `week` is `int64_t` in the record and is range-checked (`>= 0`) in the codec; cast to `uint64_t` only after that check and pass the unsigned value to `SetCommittedWeek`.
- Task 6 adds the `cow.weather_state` envelope (`format`, `version`, then the save record's fields) with `EncodeState(sim, out)` / `DecodeState(json, record)`, used by the participant and by Feature 5's commands.
- `HashWeatherParameters`: FNV-1a 64-bit over the bit patterns (`memcpy` to `uint32_t`) in descriptor-table order, so adding a parameter row changes the hash by construction.

### Tasks 7 to 14: Participant
- `class WeatherSaveParticipant : public ISaveable` holds `WeatherModule&`. `Serialize` writes the record; `Validate(LoadContext&)` calls the codec's pure check with a no-mutation guarantee (a test snapshots module state before and after); `Deserialize` runs the seven steps in the spec in order, factored into `WeatherModule::OnLoadRestore(const DecodedWeatherState&)` so the participant stays thin.
- Participant registration lives in `WeatherModule::DoStart` and unregisters in `DoStop`, only if `SaveLoadModule` resolved. The DeferredStep participant attaches on `DeferredStepModule`'s first `DoUpdate` (World Step Feature 3 amendment 5), so it always follows every stage participant regardless of manifest order (amendment 4). The registration-order test uses a fake registry that records the order in which participants arrive.
- `mRestoredRevision` is private state; the `WorldGenerationComplete` handler ignores `revision == mRestoredRevision` only after the spike's finding says that is the right rule.

### Tasks 15 to 19: Pending result
- `WeatherSimulation` additions: `RestoreCommitted(uint64_t week, const WeatherFields&, const DynamicArrayC<uint8_t>& biomes)`, `RestoreCompleted(const WeatherFields&, const DynamicArrayC<uint8_t>&)`, `GetWorkingFields()`, `GetWorkingBiomes()`. All validate sizes and return false without changing state.
- The coordinator wraps each stage in `BeginObject("stage_N")` (amendment 5); this stage writes into the current node.
- `WeatherStage::SerializePending(SaveContext&)` writes `{pending_version, valid, step_day, cell_count, 10 arrays, biome}` from `GetWorkingFields()` (the ninth array is `waterToGround`, not `groundWater`, and the tenth `pressure_anomaly`; `glacierInput` and `influenceWater` are not saved; `step_day` is `mCapturedDay`; amended 2026-11-17 (A5 Hydrology and row 6d)); `DeserializePending`/`ValidatePending` share the codec's consistency checks (no live-state comparison in Validate).
- Save-time discard guard: if `mCaptureRevision != mTargetRevision` (or no step was captured), write `{"pending_version":1,"valid":false}`, **not nothing** (AC 19; amended 2026-11-17 (row 6d): World Step's `Validate` refuses a save missing a blob for a stage in `order`). `DeserializePending` of that blob records "nothing pending" and the later `Commit()` is a logged no-op.
- `WorldStepModule::Apply` tolerance (World Step Feature 3 amendment): when `chain.Commit()` returns false, log one Warning, raise no signal, update no metric. This edits `WorldStepModule` (CoW) in the same commit as the test.

### Verification cadence
- Per task: narrow `dia run googletest --filter="<suite under work, e.g. WeatherStateCodec*>" --shards 2` (always `--shards 2`); the three-suite filter runs only in the scoped-verification task (task 22).
- Float fidelity is tested against real text, never mocks. The full suite runs once in worldstep.plan.md, Weather-stack close-out. No `SLOW_` suites. Sanitizer: on request only (user, 2026-11-17). No mutation checks. The AC 20 timing is a Debug ballpark only; Release measure moved to worldstep.plan.md Weather-stack close-out (2026-11-17, speed-ups).
