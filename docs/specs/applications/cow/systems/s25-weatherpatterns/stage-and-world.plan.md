### Conventions
- Namespace `CoW::S25`, S25 prefix on every type (AD-002). Members `m`-prefixed, constants `k`-prefixed.
- Public APIs use Dia containers and `String*`; jsoncpp only at the load edge (PD-004).
- Loaders are all-or-nothing: parse into a local, commit on success, typed error naming the field. Unknown keys are invalid.
- Every external collaborator is a small interface so the module is testable on fakes: `IS25WorldSource` (set preset/seed/size, `IsReady(revision)`, terrain read), `IS25SessionHintReader`, `IS25WorldStep` (`SetDeferred`, `Step`, `IsIdle`). Real adapters wrap `WorldGenerationModule`, F-3's reader and `WorldStepModule` through `ModuleRef`; no singletons, no `GetStatic`.
- Cross-PU rule: the card never reads module state across threads. `S25CardStats` is a plain struct published on SimPU through the debug-domain stats path.
- Health uses DiaObservation levels `kOK`, `kDegraded`, `kFailing`. The stage's own health is Degraded on a failed precheck; a `Failing` health from `WeatherModule` (for example a sidecar fault, which has no fallback) is surfaced on the card, never masked.

### World table and prechecks
- `S25WorldTable::Load(const Json::Value&, S25WorldTableError&)`; entries `{id, preset, seed, size, DynamicArrayC<StringCRC> prechecks, thresholds}`. Threshold defaults are the spec's (`minOceanCells` 200, `minCoastCells` 40, `minRidgeCells` 6, `minLowlandCells` 20, `minInteriorCells` 30); they are data in the file.
- `struct S25PrecheckResult { StringCRC id; bool passed; double measured; double required; double margin; }` with `margin = measured - required`. One free function per precheck plus a `RunPrechecks` driver.
- **Distances** use DiaPathfinding's multi-source step distance over `HexNeighbours` on the `WeatherTerrain`'s `HexTopology` (A4's hand-built `ComputeWaterDistance` is deleted by A4's world-sim amendment). Wind direction uses `PrevailingDirection` from A4's exports. No new distance code here.
- `ridge_crosses_wind` is the one non-trivial precheck: enumerate ridge-crest cells (elevation >= 0.6), find windward/leeward pairs at least 3 steps apart along `PrevailingDirection(latitude)`, require a crest of at least `minRidgeCells`. The "parallel ridge" negative case (AC 6) is the first test.
- Hand-built terrain helpers live in `S25/Testing/S25TestTerrain.h` (`OceanStrip`, `Ridge(angle)`, `Lowlands`, `Interior`); reuse A4's shared test terrains or Feature 2's `ScriptedTrace` terrain builder if they cover the shape.
- Results are cached keyed by world revision; re-run on `WorldGenerationComplete`.

### S25WeatherModule
- `class S25WeatherModule : public Dia::ApplicationFlow::SimModule`: `LoadWorld(StringCRC)`, `GetWorldStatus()`, `GetStepMode()`. `DoStart` resolves collaborators via `ModuleRef`, loads the table, picks the default or hinted world, registers commands.
- World load: set S-1 inputs through the `IS25WorldSource` seam, then wait on later ticks for `IsReady(revision)` (non-blocking state machine `Idle -> Requested -> Ready/Failed`). Never touch `GetCurrentWorld()` except to copy terrain for prechecks (SD-S1-010).
- `S25WorldStatus { id, preset, seed, size, revision, prechecks[], verdictEligible, curated }`; `verdictEligible = curated && size == Small && all prechecks passed`. Failed precheck: status carries "invalid world: re-pick the seed", stage health Degraded, the run continues.
- Size change goes through `cow.worldgen.set_size`; the module re-runs prechecks after A4 re-spins. Readiness after the change is `WeatherModule::IsReady(revision)` for the new revision.
- Session hint at `DoStart`: reader returns `{found, valid, bundlePath}`; absent uses the default, unreadable or invalid logs one Warning and uses the default.
- Step mode: `S25StepMode { Sync, Deferred }` mirrors `WorldStepModule` through `IS25WorldStep`. Mode switches call `SetDeferred(bool)` and show the refusal reason verbatim.
- The stage manifest configures `WeatherModule` with its **sidecar through the catalogue alias** (no `.diaapp` `parameters` path and no `history_weeks`; both are superseded), `spinup_weeks` 52, the `history` block (tracked layer names come from A4's current layer list, `weather.<snake_case>` ids) and the wind overlay. `WorldStepModule` order is `["weather"]`.

### Tools wiring
- Step-back: the card model computes the button state from `{driverPresent, historyAvailable}` with the two spec reasons ("history driver not built", "no history yet"). Real action posts `cells.history.view` / `cells.snapshot.restore`; tests use a `FakeHistoryDriver`.
- Click-to-inspect and layer picker are DiaCellLayers shared widgets hosted on the card; this feature tests only the wiring (selection state, command names, hotkey table has no clash for A4's layers). Layer ids are listed from A4's schema keys `cow.weather.layers/<field>`; do not hard-code a count (recount at build).
- Boundary switch posts `cow.weather.params {"action":"set","key":"boundary.edge_inflow","value":0|1}`; the reply is `{queued, key, value, effectiveDay, visibleDay}` and the switch reads `visibleDay` for "effective next week".

### Commands
`cow.s25.world` (command) and `cow.s25.status` (query), sim-hosted, category `s25`, mandatory help, JSON-object arguments. They are entries in `S25CommandList`, which `S25WeatherModule` owns and hands to the kit's `SimCommandSet` as **one** all-or-nothing list; Feature 3 adds its four entries to the same list. `SimCommandSet` rolls back with each entry's own kind's unregister and logs one Error; no private rollback code is written here. Feature 4's `cow.scenario.*` names belong to `ScenarioModule` and roll back separately. Unknown world or size returns an error listing valid names and changes nothing. Handler budget is the per-PU cap, 192.

### Card
`S25CardModel` (pure) owns the ordered control list `{controlId, label, commandName, enabledReason}` and the `S25CardStats` struct; `S25Card : IDebugDomain` renders it per the signed-off mockup, accent from `DebugGroupAccents`, description <= 80 characters, posts commands only. AC 23's test walks the control list against the registered command names.

### Instrumentation
Channel `S25`: logs and `DIA_TRACE_ZONE` per the spec; `IHealthReporter` Degraded on a failed precheck; metric `s25.world_ready_ms` with `MetricInfo`, written on SimPU. `cow.weather.step_ms` is registered by A4's stage base; this feature only reads it (AC 26).

### Verification cadence
- Per task: narrow `dia run googletest --filter="S25Prechecks*" --shards 2` style filters on the suite under work; the feature-wide `--filter="S25*"` runs only in the scoped verification task.
- No full suite per feature (the weather-stack close-out owns it). No sanitizer, no mutation checks. Perf is Debug ballpark only. Long tests (the real-world scout run) are tagged `SLOW_`.
- World-sim results are verified from cell data and the report, not screenshots; the one screenshot per feature is the user's taste check on the card, not a gate.
- Never call `CluicheTest.exe`/`GoogleTests.exe` directly: `dia run` / `dia launch` only. Kill leftover `CluicheTest.exe` before E2E.

## Open items

Spec gaps found while rebuilding this plan. None are resolved here.
- **Stale `ComputeWaterDistance`.** The spec's Depends-on and prechecks text cite A4 Feature 6's `ComputeWaterDistance`, which A4's presets-and-regression amendment 1 deletes (distance is now a `CellSelectorSet` derived `distance {from: water}` or DiaPathfinding's step distance). Whether prechecks should be expressed as `CellSelectorSet` selectors over `WorldCellFields` instead of free functions is unstated (stage-and-world.md, presets-and-regression.md, worldsim-kit.md).
- **"Ocean cell" definition.** `ocean_present` and the storm cell chooser say "ocean cells"; with `Cell::biome` a `BiomeIndex` and `BiomeRole::Ocean` in the registry, versus `waterSource`, the spec does not say which defines ocean (stage-and-world.md, biome-registry.md).
- **Stale `WeatherModule` config wording.** The module-list text says `WeatherModule (config: parameters file, ...)` and the system spec mentions `history_weeks`; A4's amendment makes the sidecar the only source, with no `.diaapp` `parameters` path (stage-and-world.md, a4-weather.md).
- **Layer counts and names.** AC 20 says "A4's seven layers"; A4's later amendments say eight scalar base layers plus two wind component layers. The tracked history layer `weather.water_to_ground` is still marked "name TBD" in this spec (stage-and-world.md, a4-weather.md). Recount at build.
- **Amendment already absorbed elsewhere.** The spec lists `SetDeferred` and the `cow.worldstep.step` `action` argument as edits this feature makes to World Step Feature 2, but the World Step module-and-cadence spec already contains them (with its own AC), so ownership is ambiguous (stage-and-world.md, module-and-cadence.md).
- **Command-list ownership.** The gap-pass amendment names `S25CommandRegistrar` to roll back all `cow.s25.*` names; the kit's `SimCommandSet` provides all-or-nothing registration with correct rollback. This plan treats the registrar as an entry aggregator over `SimCommandSet`; the spec wording is unchanged (stage-and-world.md, worldsim-kit.md).
- **`cow.s25.*` and the naming test.** The kit's `WorldSimNames` pattern test lists world-sim system tokens; `s25` and the `cow.s25_*` formats are not among them, so whether the pattern test applies is unstated (worldsim-kit.md).
