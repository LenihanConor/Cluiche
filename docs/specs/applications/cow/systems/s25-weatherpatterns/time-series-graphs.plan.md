# Plan: Time-Series Graphs (S-2.5 Feature 5)

**Spec:** @docs/specs/applications/cow/systems/s25-weatherpatterns/time-series-graphs.md
**Status:** Not Started
**System plan:** @docs/specs/applications/cow/systems/s25-weatherpatterns/s25-weatherpatterns.plan.md (row 5)

Starts once S-2.5 Feature 1 (stage, card, tracked-layer `history` block, `S25WeatherModule`) and Feature 3 (the runner, `RecordedTrace`, the run table, the report) are Done, and A4 Feature 5 (the seven weather layers and their schema entries, plus `WeatherCommand`) is Done. S-3.5 Feature 1's `HistoryDriverModule` is **soft**: the live tasks (6-9) need it for end-to-end behaviour, but they are written against a scripted `OnWorldStepApplied` driver and a real `CellHistoryRecorder`, so they can proceed without it; the stage-level proof (task 13) waits for it. The headless tasks (3, 10-12) need Feature 3 and the spike in task 1, not the driver.

This is a small feature with **no Dia edits** and no new command names. No in-game graph is built (decided 2026-11-16). The one Dia-adjacent risk is the standalone recorder (task 1); if it fails, the headless half is dropped and recorded as a deviation, never solved with a recorder change (AD-001). All implementation tasks are **sonnet**; if one needs more, **ask before escalating**. No mutation checks. Release figures are reported, not enforced. Scoped `--filter` while iterating, one full run at the end with `--shards 2` or more.

## Implementation Patterns

### Placement
- `Cluiche/CoW/Modules/TraceHistoryWriter.h/.cpp` (S25 prefix, feature-local, AD-002). Namespace `CoW::S25`.
- Edited: `S25WeatherModule` (Export history button wiring, status reason), Feature 3's `S25HeadlessRunner` (`export_history` option, output paths).
- Tests: `Cluiche/Tests/GoogleTests/CoW/S25/TestS25HistoryAggregates.cpp` (live) and `TestTraceHistoryWriter.cpp` (headless). Test helpers in `CoW/Modules/Testing/` (`ScriptedStepDriver`, `HandBuiltTerrainFixture`), not in GoogleTests.
- vcxproj entries through `dia docs vcxproj-add CoW "Modules\TraceHistoryWriter.h" --filter Modules`, and the same for the `.cpp` and the two test files in `GoogleTests`. No Dia project is touched.

### Live aggregates (tasks 4-9)
- Nothing new is recorded by S-2.5. Aggregates exist for **every** layer registered with `CellLayerRegistry` in the aggregate tier (CH-001); the tests only prove they are present and correct for the seven weather layers: `weather.moisture`, `.pressure`, `.temperature`, `.precipitation`, `.snow_pack`, `.cloud_cover`, `.ground_water`.
- Test rig: a real A4 `WeatherModule` stepping on hand-built terrain, a real `CellHistoryRecorder` constructed over the registry, and a `ScriptedStepDriver` that calls `Sample` once per applied week, labelled by `stepDay`. No stage, no bus.
- Equality test (AC 2): for each week and layer, compute min/mean/max of the committed field in **double** (mean accumulated in ascending cell order; amendment 3), round to `float32`, and compare with the recorded aggregate for the `world` group and for at least one region group, with `memcmp` on the float, not a tolerance. The expected values come from the test's own loop over the committed fields, never from the recorder.
- Region groups require S-1's region category layer to carry `history.group: true` in its schema `ui` (task 2). If it does not, **flag it to the user and do not edit S-1**; the region assertions are then skipped with a clear message and only the `world` group is asserted.
- Group cap (amendment 2): DiaCellHistory allows up to 127 non-world groups while S-1's `kMaxRegions` is 64. The budget **estimate** uses 64; the test uses the real group count.
- Budget arithmetic (AC 3): derive bytes per sample from the real group count (`AggregateStore::BytesPerSample()` and `HistoryStatus::mAggregateBytes`), run 208 weeks, assert total under the 64 MB aggregate budget and measured bytes per sample within 10% of the spec's estimate (about 12 bytes per layer per group per sample). The 5.5 KB per week and 1.1 MB per 208 weeks figures are reported.
- AC 4 reuses Feature 1's scrub test with aggregates on: the three tracked layers still scrub 13 weeks within 16 MB.
- AC 5: without a driver nothing records; the card reports "no history driver"; the button is disabled with that reason; a log-capture test asserts no per-frame error (zero Error lines over N ticks).

### Export (tasks 10-11)
- The card button posts `cells.history.export path=out/CoW/s25/live_<world>_<seed>.history.json` through the existing command; **this feature adds no command name**. `S25WeatherModule` builds the path and the disabled reason ("no history driver" / "no history yet"); the card calls the same command a console would (editor-actions rule). UI depends on the typed model only.
- AC 6 round trip: export then re-read with DiaCellHistory's loader; aggregates identical, the seven weather layers' schema entries (labels, ranges) and groups present. AC 7: second export overwrites atomically; a forced write failure leaves the previous file intact and logs one Error. Atomicity is DiaCellHistory's exporter's; the test only observes it (no Dia change).

### Headless history (tasks 3, 12-14)
- `TraceHistoryWriter`: `bool Write(const IWeatherTrace&, const WorldInfo&, const char* runId, const char* outPath, WriteStats&)`. It builds a **standalone** `CellHistoryRecorder` (registry, schema service pointer, `HistoryConfig`, a fixed `runIdSeed` so output is reproducible), with the same layer registrations, schema entries and groups as live. Per amendment 1 it builds a **private `CellLayerRegistry` holding real `CellField`s** (one per weather layer, sized from the terrain, with the same schema keys as live) and a `CellGridDesc` from the terrain dimensions, uses no module and no bus, then for each week in the trace copies the trace values into the fields and calls `Sample` with a `SampleInfo` whose label follows the live calendar (`Y<year> W<week>`); then export. Writes to a temp path and renames; aggregate-only tier so no per-cell rings are written.
- `export_history` is an `S25RunParams` option, **default on** in the `SLOW_` test output directory and for `cow.s25.run`. For runs R1, R2, R3, R4, R5a, R6, R7 the file is `out/CoW/s25/history_<run>_<world>.json`.
- AC 9 compares the headless file's aggregates with the `RecordedTrace`'s min/mean/max per week using the same double-then-float32 arithmetic as AC 2. AC 10 (amendment 4): R1 vs R2 aggregates identical; R3's aggregates differ from R1's in **at least `weather.moisture`** (the layer the edge toggle acts on directly). The test asserts `weather.moisture` differs and does not assert which other layers differ (downstream effects).
- Fallback (AC 11): if task 1 shows the recorder cannot run standalone, **drop tasks 12-14**, mark them `Dropped` through `dia docs plan`, record the deviation in the plan notes, and implement only the runner skip with one Info log (task 14 reduces to that skip).

### Instrumentation (task 15)
- Info log on export (path, weeks, groups, bytes); Warning when the region layer is not a grouping layer (once per world) and when export is requested with no history; Error on a failed write; `DIA_TRACE_ZONE` around the export. No new metric.

### Verification cadence
- Per task: `dia run googletest --filter="S25HistoryAggregates*:TraceHistoryWriter*" --shards 2`.
- One full `dia run googletest --shards 2` in the final verification task only.

## Open items

Resolved items are kept for traceability.

1. **How the writer fills the recorder.** **Resolved by amendment 1 (2026-11-16)**: private `CellLayerRegistry` with real `CellField`s plus a `CellGridDesc`.
2. **Group count and the cap.** **Resolved by amendment 2 (2026-11-16)**: estimate uses 64; test uses the real count; the recorder cap of 127 is an edge case.
3. **Pending-driver dependency.** Still open: everything live is gated by `HistoryDriverModule` (S-3.5 Feature 1); this plan proves aggregates with a scripted driver, and acceptance of AC 1/5/6 on the real stage waits (task 16).
4. **R3 expected-layer set.** **Resolved by amendment 4 (2026-11-16)**: R3 differs from R1 in at least `weather.moisture`.
5. **Float32 rounding vs Feature 2's aggregates.** **Resolved by amendment 3 (2026-11-16)**: double mean in ascending cell order rounded to float32; task 1 confirms the recorder's own arithmetic.
6. **Snow coverage.** The spec excludes snow coverage percent as a series; the spec's checks still use it. No action here, noted so nobody adds it.
7. **No visible curves.** Open Design Question 1 stands: until T-1 Feature 7 exists the series are only JSON. No graph task exists in this plan by design.
