### CommandLine
- `struct CommandLine { StringCRC name; DynamicArrayC<Arg, kMaxArgs> args; }`, `Arg { String64 key; String256 value; bool positional; }`. No STL (PD-004).
- `bool ParseCommandLine(const char*, CommandLine&, ParseError&)`; `ParseError { uint32_t offset; String128 message; }`; `void RenderCommandLine(const CommandLine&, String512& out)`. Render(Parse(x)) is identical text for every valid line; quoting re-applied only when the value contains a space. Rejects unterminated quote, empty command, duplicate named argument, each with the offset.
- Positional binding is a second step, `BindPositional(CommandLine&, const ICommandCatalogue&)`, so parsing stays pure. The tokenised line converts to the sim-hosted command's JSON object via `ToJsonArgs(const CommandLine&, const ICommandCatalogue*, Json::Value&)` (jsoncpp only at this edge).
- `ICommandCatalogue` is a small interface over DiaValueSchema's command entries (`FindCommand(name)` returning arg names, order, type, range, enum values, required). Production wraps the DiaValueSchema export. A4's consolidated commands are written with **named** arguments (`cow.weather.params action=set key=boundary.edge_inflow value=0`, `cow.weather.force action=storm cell=412 intensity=1.0 weeks=3`, `cow.weather.params action=reload`).

### ScenarioValidator
- Signature exactly as spec: `Findings Validate(const Json::Value&, const ICommandCatalogue&, const IScenarioVocabulary&, const IWorldIds&)`. Pure, never throws, deterministic ordering (fixed table order, then array index).
- `Finding { Severity; String128 jsonPath; uint32_t line; String256 message; }`. `LoadScenarioFolder` builds a `JsonLineMap` (token offset to line) per file and passes it as an optional `ILineMap`; with none, findings carry the JSON path only (line 0). Setup-entry line numbers are the 1-based entry index.
- One test per T-2 rule: envelope/id missing; id differs from file name; id duplicate in folder; mode not in vocabulary; world not found (Warning); setup command unknown; argument unknown / missing required / wrong type / out of range / not an enum value / too many positional; command missing from this stage's export but in the base export (Warning); check not in vocabulary; duplicate check (Warning); no checks (Warning); walkthrough overlay not in vocabulary; walkthrough `check` not among own `checks`; empty `watch` (Warning). Missing catalogue and missing vocabulary each give exactly one Warning and skip dependent rules.
- **No rule is added beyond the T-2 table.** If a task seems to need one, stop and send it to T-2 first.
- Known limit (AC 4): "required when `action` is X" is not expressible, so a missing `cell` for `action=storm` is deliberately not a finding. Now also true of `cow.weather.params` (for example `action=set` without `key`); the handler reports it at run time.

### CheckRegistry and loader
- `CheckRegistry`: `Register(const ICheck&)` false on duplicate id; `Find(StringCRC)`; `ListIds`. Fixed-capacity container; non-owning pointers to function-local statics owned by `S25WeatherChecks` (valid for the process lifetime).
- `LoadScenarioFolder(path, validator, registry, ..., LoadResult&)`. `LoadResult { DynamicArrayC<Scenario> valid; Findings findings; uint32_t rejected; }`. A bad JSON file or any Error finding rejects only that file (recorded with file and line); Warnings load and keep the finding. Unregistered check ids are rejected here (AC 6), distinct from the validator's vocabulary rule. File access goes through an `IFolderSource` seam.
- Runs at stage start and on `cow.scenario.list {"reload":true}`.

### LiveTraceRing and check lines
- `LiveTraceRing : IWeatherTrace`, capacity 65 weeks, full float32 copy of the committed fields from `WeatherSnapshot::GetFields()`, oldest dropped first; `Clear()`; never serialised. Preallocated at world load from cell count (about 7 MB Small, 16 MB Large; recount when A4's field list is read). It is fed from the **generated** `WeatherUpdated` message (declared in `cow_worldsim.diagamemessages`), through the generated subscriber wiring, not hand registration; tests use a scripted feed.
- Cleared on world load, `cow.scenario.run` and parameter changes that restart weather (the module wires these).
- `CheckLineModel`: per scenario check `{ id, label, kind, state (Pass|Fail|MagnitudeMiss|Pending|InvalidWorld|HeadlessOnly), measured, threshold, detail }`. `Update(const ICheck&, const IWeatherTrace&, const WorldInfo&)` calls Feature 2's `Evaluate`; unmet requirements become `Pending` with the reason (`needs weeks 1..52, have 9`); a check whose `CheckRequirements.needsComparison` is true has no comparison trace live, so it becomes `HeadlessOnly`, never Pending.
- AC 9 is a real-A4 test on hand-built terrain: the same 13 weeks into a `RecordedTrace` and a `LiveTraceRing`, state and `measured` compared bit-for-bit (`memcmp` on the double, not a tolerance). AC 11 timing uses the `scn.check_eval_ms` metric; report the figure, assert no bound.

### Runner, sinks and walkthrough
- `ScenarioRunner` state machine `Idle -> LoadingWorld -> SettingUp -> Ready -> Running`, plus terminal `SetupFailed`. Driven by tick-style calls from `ScenarioModule` (SimPU only).
- Dependencies by interface: `IWorldSource`, `IScenarioCommandSink` (`bool Execute(const CommandLine&, ExecResult&)`), `IClockControl` (`Pause()`), `IOverlayControl` (`Set(overlayId, bool)`, `RestoreDefaults()`; plus `Snapshot()`/`Restore()` only if the spike finds a DiaCellLayers overlay-query), `ICheckEvaluator`. Fakes live in `Testing/`.
- Setup lines run strictly in order; the first error stops in `SetupFailed` with line index, command and error; the world is left as it was after the lines that succeeded. `cow.scenario.run` pauses the clock and skips `LoadWorld` when the target world is already the ready current world.
- `<chosen>` storm cell: resolved at run time with Feature 3's chooser; until Feature 3 exists, a fake chooser is used.
- Sinks: `LiveCommandSink` (calls the sim-hosted dispatch) and `HeadlessCommandSink` (converts `cow.weather.*` lines to A4's typed `WeatherCommand` and applies them through the direct sink; any other command is reported unsupported; a `cow.weather.params` action with no typed mutation is reported unsupported, see Open items).
- Walkthrough: `Walk(next|prev)` clamps at both ends, refused with a reason when idle or no steps. Showing a step turns on exactly its overlays and the others off **through the layer/overlay commands** (no private path), shows text, pins the check line. Leaving restores the stage defaults from the stage config (base layer `weather.precipitation`, wind overlay off) unless the spike finds an overlay-query.

### ScenarioModule, commands, panel
- Registers `cow.scenario.list` (query), `cow.scenario.run` (command, `{"id"}` or `{"action":"stop"}`), `cow.scenario.walk` (command, `{"action":"next"|"prev"}`), category `scenario`, mandatory help, **through the kit's `SimCommandSet`** (all-or-nothing, rollback by each entry's own kind; no private rollback). The three names are not in the `cow.s25.*` list; they roll back separately. Forced-failure test at registration position 1, 2 and 3.
- Invalid arguments (unknown id, action, `walk` with no scenario) return an error naming the field and change nothing.
- The panel reads a **published model** (immutable snapshot each update through the shared-card mechanism), never module state across threads. It posts only the three commands. It shows scenario id, watch text, check lines labelled "understanding, not verdict", and walkthrough controls.
- Instrumentation: channel `SCN`; Info for loaded/rejected counts, run start, state transitions, walkthrough step; Warning for validator Warning, headless-only check shown, failed `LoadWorld`; Error for setup failure and failed registration. `DIA_TRACE_ZONE` around load, validation, per-week evaluation. Health: Degraded when any file was rejected (DiaObservation levels). Metric `scn.check_eval_ms`.

### Content
- Fourteen files per the spec's table (nine tests plus five presets), all `s25_coast_range` except `s25_t6_droughts` and `s25_t7_variability` (`s25_dry_interior`). Each has `watch` (1-3 sentences) and a 2-4 step walkthrough. Preset scenarios load `cow.weather_preset` files through `cow.weather.load_preset`; they contain **no inline selector syntax** (cell selection lives in the preset files under `CellSelectorSet`; the storm cell is an index placeholder). `vocabulary.json` (`cow.scenario_vocabulary` v1): the checks, overlays and layers, `modes: []`. `s25_t8_boundary` and `s25_t9_determinism` are mostly `HeadlessOnly` live: their `watch` text says so and names `cow.s25.run`.
- Vocabulary sync test fails both ways: registered but absent, and listed but unregistered.

## Open items

Spec gaps found while rebuilding this plan. None are resolved here.
- **Where a scenario chooses cells.** Amendment item 2 says "any preset or cell selector in a scenario uses `CellSelectorSet`", but the scenario file format has no selector block and setup arguments carry only a numeric `cell` index (and the `<chosen>` placeholder). Whether selectors may appear in a scenario at all is unstated (scenarios-and-walkthrough.md, worldsim-kit.md).
- **`requiredWhen` grows with the params command.** `cow.weather.params` adds `set`, `get`, `list`, `reload`, `save_defaults` and `cycle` actions under one name, so the validator's blind spot for per-action required arguments is wider than the spec's storm example. Open Design Question 3 is unchanged and unresolved (scenarios-and-walkthrough.md, worldsim-kit.md).
- **Headless conversion of params actions.** `HeadlessCommandSink` maps lines to typed `WeatherCommand`s; which `cow.weather.params` actions have a typed mutation (`set` does; `reload`, `get`, `list` and `save_defaults` are queries or dev-only) is not stated, and "any non-`cow.weather.*` command is unsupported" does not cover them (scenarios-and-walkthrough.md, weather-debug.md).
- **Overlay ids versus layer ids.** Walkthrough overlay ids are short (`wind`, `precipitation`, `water_to_ground`); A4 layer ids are `weather.<snake_case>` and the stage-default base layer is written `weather.precipitation`. The mapping between vocabulary overlay ids and layer ids is not defined, and `water_to_ground` is still "id set by the A4 amendment, TBD" (scenarios-and-walkthrough.md, a4-weather.md).
- **Live trace type contradiction.** weather-checks.md still describes `HistoryTrace` (a live view over DiaCellHistory) while this spec decided the live trace is the module's own `LiveTraceRing`; the ring's "nine fields" also predates A4's tenth saved field and `waterToGround` rename (scenarios-and-walkthrough.md, weather-checks.md, a4-weather.md).
- **Stale check counts.** The spec says 34 checks over 65 weeks and per-test counts (`t1.*` 5, `t2` 3, `t3` 5, `t4` 5, `t5` 4, `t6` 3, `t7` 2, `t8` 3, `t9` 1) sum to 31; `t5.gw_peak_week` keeps a ground-water name. Recount at build.
- **Local dispatch and the kit.** The Open Design Question about an in-process execute on `SimQueryHost` does not mention that the kit's `SimCommandSet` may or may not add one; the spike checks it (scenarios-and-walkthrough.md, worldsim-kit.md).
- **Command-name pattern test.** `cow.scenario.*` is not a world-sim system token, so whether the kit's naming test covers it is unstated (worldsim-kit.md).
- **Overlay restore** remains stage-defaults-only unless the spike finds a DiaCellLayers overlay-query (gap-pass amendment 3).
- **Open Design Questions 1, 2 and 4** of the spec stand as written (local dispatch, pause-on-run default, content authoring as its own reviewed task); the system plan's review kept pause-on-run and deferred `requiredWhen`.
- **DiaAutomation scenario location and format** follow F-2's pattern only.
