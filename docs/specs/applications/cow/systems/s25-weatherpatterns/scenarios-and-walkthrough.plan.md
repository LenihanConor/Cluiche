### CommandLine (tasks 3-4)
- `struct CommandLine { StringCRC name; DynamicArrayC<Arg, kMaxArgs> args; }` where `Arg` is `{ String64 key; String256 value; bool positional; }`. No STL (PD-004).
- `bool ParseCommandLine(const char*, CommandLine&, ParseError&)`; `ParseError { uint32_t offset; String128 message; }`. `void RenderCommandLine(const CommandLine&, String512& out)`. Round-trip property: Render(Parse(x)) is identical text for every valid line; quoting is re-applied only when the value contains a space.
- Rejects unterminated quote, empty command, duplicate named argument, each with the offset.
- Positional binding is a **second step**, `BindPositional(CommandLine&, const ICommandCatalogue&)`, so parsing stays pure and catalogue-free. The tokenised line converts to the JSON object the sim-hosted command takes via `ToJsonArgs(const CommandLine&, const ICommandCatalogue*, Json::Value&)` (jsoncpp only at this edge).
- `ICommandCatalogue` is a small interface over DiaValueSchema's command entries (`FindCommand(name)` returning arg names, order, type, range, enum values, required). Tests use `FakeCatalogue`; production wraps the DiaValueSchema export.

### ScenarioValidator (tasks 5-7)
- Signature exactly as spec: `Findings Validate(const Json::Value&, const ICommandCatalogue&, const IScenarioVocabulary&, const IWorldIds&)`. Pure, never throws, deterministic ordering (rules run in the fixed table order, then by array index).
- `Finding { Severity; String128 jsonPath; uint32_t line; String256 message; }`. Per amendment 4, `LoadScenarioFolder` builds a `JsonLineMap` (token offset to line) while parsing and passes it to the validator as an optional `ILineMap`; with none, findings carry the JSON path only (line 0). Line numbers for setup text are the 1-based index of the setup entry.
- One test per T-2 rule: envelope/id missing; id differs from file name; id duplicate in folder; mode not in vocabulary; world not found (Warning); setup command unknown; argument unknown / missing required / wrong type / out of range / not an enum value / too many positional; command missing from this stage's export but in the base export (Warning); check not in vocabulary; duplicate check (Warning); no checks (Warning); walkthrough overlay not in vocabulary; walkthrough `check` not among own `checks`; empty `watch` (Warning). Plus: missing catalogue and missing vocabulary each give exactly one Warning and skip dependent rules.
- **No rule is added beyond the T-2 table.** If a task seems to need one, stop and send it to T-2 first.
- Known limit (AC 4): a missing `cell` for `action=storm` is deliberately **not** a finding; the test asserts it passes validation, and a runner test asserts the handler error surfaces at run time.

### CheckRegistry and loader (tasks 8-9)
- `CheckRegistry`: `Register(const ICheck&)` false on duplicate id; `Find(StringCRC)`; `ListIds`. Fixed-capacity `HashTable`/`DynamicArrayC`; does not own checks: per Feature 2 amendment 6 (this feature's amendment 6) the check objects are function-local statics owned by `S25WeatherChecks`, valid for the process lifetime, and the registry stores non-owning pointers.
- `LoadScenarioFolder(path, validator, registry, ..., LoadResult&)`. `LoadResult { DynamicArrayC<Scenario> valid; Findings findings; uint32_t rejected; }` (builds a `JsonLineMap` per file and passes it to the validator as an `ILineMap`). A bad JSON file or any Error finding rejects only that file (recorded with file and line); Warnings load and keep the finding. Unregistered check ids are rejected here (AC 6), distinct from the validator's vocabulary rule.
- Runs at stage start and on `cow.scenario.list {"reload":true}`. File access goes through an `IFolderSource` seam so tests use in-memory files.

### LiveTraceRing and check lines (tasks 10-12)
- `LiveTraceRing : IWeatherTrace`, capacity 65 weeks, nine float32 fields per cell per week, oldest dropped first. `Append(const WeatherSnapshot&)` copies `GetFields()`; `Clear()`; never serialised. Memory preallocated at world load from cell count (about 7 MB Small, 16 MB Large).
- Cleared on world load, `cow.scenario.run` and parameter changes that restart weather; the module wires these, the ring just exposes `Clear()`.
- `CheckLineModel`: per scenario check `{ id, label, kind, state (Pass|Fail|MagnitudeMiss|Pending|InvalidWorld|HeadlessOnly), measured, threshold, detail }`. `Update(const ICheck&, const IWeatherTrace&, const WorldInfo&)` calls Feature 2's `Evaluate`; unmet requirements become `Pending` with the reason text (`needs weeks 1..52, have 9`); a check whose `CheckRequirements.needsComparison` is true (the "headless-only" flag; amendment 1) has no comparison trace live, so it becomes `HeadlessOnly` and **never** Pending.
- AC 9 (live equals headless) is a real-A4 test on hand-built terrain: feed the same 13 weeks to a `RecordedTrace` and a `LiveTraceRing` and compare state and `measured` bit-for-bit for every single-run check (`memcmp` on the double, not a tolerance).
- AC 11 timing uses the `scn.check_eval_ms` metric; report the figure at Large in notes, do not assert a bound.

### Runner, sinks and walkthrough (tasks 13-17)
- `ScenarioRunner` state machine `Idle -> LoadingWorld -> SettingUp -> Ready -> Running`, plus terminal `SetupFailed`. Driven by `Tick`-style calls from `ScenarioModule` (SimPU only); no threads, no locks.
- Dependencies injected by interface: `IWorldSource` (`RequestLoad(world)`, `IsReady(revision)`, `CurrentWorld()`), `IScenarioCommandSink` (`bool Execute(const CommandLine&, ExecResult&)`), `IClockControl` (`Pause()`), `IOverlayControl` (`Set(overlayId, bool)`, `RestoreDefaults()`; plus `Snapshot()`/`Restore()` only if a DiaCellLayers overlay-query exists), `ICheckEvaluator`. Fakes live in `Testing/`.
- Setup lines run strictly in order; first error stops in `SetupFailed` with line index, command and error; the world is left as it was after the lines that succeeded (AC 13). `cow.scenario.run` pauses the clock and skips `LoadWorld` when the target world is already the ready current world.
- `<chosen>` storm cell: the runner resolves the placeholder at run time using Feature 3's chooser (`S25TestPlan` rule). If Feature 3 is not built, the scenario for Test 3 is exercised with a fake chooser and the real wiring is task 24.
- `IScenarioCommandSink` implementations: `LiveCommandSink` (calls the sim-hosted dispatch) and `HeadlessCommandSink` (converts `cow.weather.*` lines to A4's typed `WeatherCommand` and applies them through the direct sink; any other command is reported unsupported).
- Walkthrough: `Walk(next|prev)` clamps at both ends, no wrap, refused with a reason when idle or no steps. Showing a step turns on exactly its overlays and turns the others off **through the layer/overlay commands** (no private path), shows text, pins the check line. Leaving restores the **stage defaults** recorded in the stage config (base layer `weather.precipitation`, wind overlay off), not an earlier state, because no overlay-query command exists (amendment 3; if task 0 finds a DiaCellLayers query, the snapshot is used instead and the amendment is dropped).

### ScenarioModule, commands, panel (tasks 18-19)
- Registers `cow.scenario.list` (query), `cow.scenario.run` (command, `{"id"}` or `{"action":"stop"}`), `cow.scenario.walk` (command, `{"action":"next"|"prev"}`), category `scenario`, mandatory non-empty help. All-or-nothing: on any registration failure, unregister the ones already registered and log one Error on channel `SCN`. These three names are **not** in `S25CommandRegistrar` (Feature 1/3's `cow.s25.*` names); they roll back separately (Feature 3 amendment 2). A forced-failure test (injecting a failing host on registration N=1,2,3) asserts no names remain.
- Invalid arguments (unknown id, action, `walk` with no scenario) return an error naming the field and change nothing.
- Panel reads a **published model** (immutable snapshot published each update through the existing shared-card mechanism), never module state across threads (PU boundaries are streams). Panel posts only the three commands. Card shows scenario id, watch text, check lines labelled "understanding, not verdict", and walkthrough controls.
- Instrumentation (task 20): channel `SCN`; Info for loaded/rejected counts, run start, state transitions, walkthrough step; Warning for validator Warning, headless-only check shown, failed `LoadWorld`; Error for setup failure and failed registration. `DIA_TRACE_ZONE` around load, validation, per-week evaluation. Health: Degraded when any file was rejected. Metric `scn.check_eval_ms`.

### Content (tasks 21-23)
- Fourteen files per the spec's table (`s25_t1_coastal_rain` ... `s25_t9_determinism`, `s25_p_*`), all `s25_coast_range` except `s25_t6_droughts` and `s25_t7_variability` (`s25_dry_interior`). Each has `watch` (1-3 sentences) and a 2-4 step walkthrough. `vocabulary.json` (`cow.scenario_vocabulary` v1): the checks, overlays and layers, `modes: []`. `s25_t8_boundary` and `s25_t9_determinism` are mostly `HeadlessOnly` live (amendment 7): their `watch` text says so and names `cow.s25.run`.
- Vocabulary sync test fails both ways: registered but absent, and listed but unregistered.
