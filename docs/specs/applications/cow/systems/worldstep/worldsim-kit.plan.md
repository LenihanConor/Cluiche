Files are added with `dia docs vcxproj-add CoW|GoogleTests ...`, never by hand.

### `MutationQueue<TEntry, 128>` and `SpinUpSlot<TSim>` (Tasks 2, 3)
- `MutationQueue<TEntry, N>`: header-only, wraps `DynamicArrayC<TEntry, N>`: `bool Enqueue(const TEntry&)` (false when full, no state change), `Count()`, `bool Dequeue(TEntry&)` (arrival order), `Clear()`. The Warning and Degraded on refusal are the base's (Task 9).
- `SpinUpSlot<TSim>`: `std::atomic<uint8_t>` state over `Idle/Running/Done/Cancelled`, `revision`, a `TSim*` result. `TryBegin(revision)`, `Cancel()`, `IsCancelled()`, `Complete(TSim*)`, `TryTake(TSim*&, uint32_t&)`, `Reset()`. A cancelled or stale result is discarded by the caller.

### `WorldStepStageBase<TSim, TEntry, TLatch>` (Tasks 6 to 13)
- The spec's shape. `TSim` is a Draoi sim exposing `Step` and `Capture`/`Run`/`Commit`; in these tasks it is a fake. Hooks are a protected nested abstract struct; the base holds a `Hooks&`. Task 0 confirms the lifecycle base providing `DoStart/DoUpdate/DoStop`, and where `HoldGenerationToken` and the `WorldGenerationFailed`/`WorldGenerationComplete` messages live (`world-handoff.plan.md`).
- Stage ids `weather`, `hydro`, `ecology` (`WorldSimNames::StageId`); `WorldStepModule`'s `StepChainConfig` order is `["weather", "hydro", "ecology"]`.
- Health: `HealthStatus` via one `IHealthReporter` in the base; each system supplies a `CauseCode` enum plus text function. Metrics `cow.<sys>.step_ms` and `cow.<sys>.discarded_steps` registered as `MetricInfo` with names from `WorldSimNames::MetricName`.
- Threading: `Run` touches only the working sim and latch; readiness, queue and spin-up poll are SimPU-only; the base sets the cell-fields "reads forbidden" flag during `Run`. Log channel passed in by the system (Task 0 confirms; S-1 uses `WGEN`).
- `FakeWorldStage` (Task 6): `FakeSim`, `FakeEntry`, `FakeLatch`, a `CallLog`, switches (`extraReady`, `latchOk`, `initFails`, `runBlocksUntil`), a `StepKey`-driven manual `Capture/Run/Commit` driver, a `SerialExecutor`, and a fake world the test advances. A5-style behaviour is a switch, not a second class.

### Restore half (Tasks 15b to 19)
- CoW feeds the Draoi codec: ranges read from the layer sidecar entry (`cow.<sys>.layers/<field>`, `min`/`max`, through `ValueSchemaRegistry`/`ValueSchemaService`; Task 0 names the lookup) or, for a state field with no layer, from `Global/<System>/<sys>_state.schema.json` (format `cow.<sys>_state`); `params_hash = ParameterFile::Hash()`.
- No in-record `version`; `GetVersion()` is `kFormatVersion`; upgrades via `Dia::SaveGame::SaveRegistry::RegisterMigration`; participant id `cow.<sys>`.
- The 7-step restore, the event-order fallback, and the pending blobs `{pending_version: 1, valid, step_day, cell_count, ...}` / `{pending_version: 1, valid: false}` are as in the spec; the pending blob omits `biome_palette` and decodes against its committed record's palette.

### Commands (Tasks 20 to 24)
- `SimCommandSet`: `struct Entry { const char* name; EntryKind kind; SimHelpInfo help; Handler handler; }`; `RegisterAll(SimQueryHost&, const Entry*, uint32_t, StringCRC owner)`; on failure at entry n, unregister 1..n-1 with each entry's own kind's function, one Error naming entry n, return false; `UnregisterAll` idempotent. Tests use a fake host with a fail-the-n-th switch (Task 0 confirms).
- `ParamCommandHelper::Register(SimCommandSet&, sys, ParameterFile&, MutationEnqueue, SystemActionHandler*)`; one command `cow.<sys>.params`; actions `set | get | list | reload | save_defaults`; other actions go to the system handler or error; `set` reply has `effectiveDay` and, when deferred, `visibleDay`; `save_defaults` is guarded by a dev-build flag (Task 0 names it) and uses the in-place writer from Parameter Files.
- `cow.<sys>.records {action: reload|list}` through `SimCommandSet`; the kit takes a `RecordReloadFn`.

### Names (Task 4) and S-1 rename (Tasks 33, 34)
- `WorldSimNames.h`: `LayerId`, `LayerSchemaKey`, `ParamSchemaKey`, `CommandName`, `SaveId`, `StateFormat`, `ParamsFormat`, `PresetFormat`, `PresetPath`, `StageId`, `MetricName`; tokens `worldgen`, `weather`, `hydro`, `ecology`, `succession`; `snake_case` fields. The pattern test walks S-1's real registrations.
- Rename 35 layer ids at `WorldLayerSource.cpp:122-159` to `worldgen.<snake_case>`, schema keys `cow.worldgen.layers/<snake_case>`; golden keys renamed by a throwaway script outside the repo with **every hash unchanged**; never run with `DIA_UPDATE_GOLDEN`; if a hash covers layer-id text, stop and report (Task 0). Site kind names and `CoW.Guarantee.*` ids are not touched.

### Verification cadence
Per task: narrow `dia run googletest --filter="<suite>" --shards 2`. Feature scope `--filter="*WorldStep*:*WorldSim*:*SimCommandSet*:*ParamCommand*:*WorldGen*:*WorldLayer*:*MutationQueue*:*SpinUpSlot*"` only in the verification task, plus the S-1 E2E scenario (`Cluiche/Tests/E2E/scenarios/cow/s1worldgen`; build first; kill any leftover `CluicheTest.exe`). No full suite per feature, no sanitizer, no mutation checks. World-sim verification uses cell data, not screenshots.
