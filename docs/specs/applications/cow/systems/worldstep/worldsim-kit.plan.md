### `MutationQueue<TEntry, 128>` and `SpinUpSlot<TSim>` (Tasks 2 and 3)
- `MutationQueue<TEntry, N>`: header-only, wraps `Dia::Core::Containers::DynamicArrayC<TEntry, N>` with `bool Enqueue(const TEntry&)` (false when full, no state change), `uint32_t Count() const`, `bool Dequeue(TEntry& out)` (arrival order), `void Clear()`. Refusing the 129th entry is the queue's job; the Warning log and Degraded health are the base's (Task 9).
- `SpinUpSlot<TSim>`: a state `std::atomic<uint8_t>` over `Idle/Running/Done/Cancelled` (`std::atomic` is permitted internally; no STL in the public signature), `uint32_t revision`, and a `TSim*` result. API: `bool TryBegin(uint32_t revision)`, `void Cancel()`, `bool IsCancelled() const` (the worker polls it between weeks), `void Complete(TSim*)`, `bool TryTake(TSim*& out, uint32_t& revision)` (SimPU poll in `DoUpdate`), `void Reset()`. A result for a cancelled or stale revision is discarded by the caller (the base), never taken as pending.

### `WorldStepStageBase<TSim, TEntry, TLatch>` (Tasks 6 to 13)
- Exactly the spec's shape: `struct Hooks` with `InitialiseSim`, `ExtraReady`, `LatchInputs`, `ApplyEntry`, `RunStep`, `PublishCommit`, `OnStartExtra`, `OnStopExtra`; the owned members `mActive`, `mPending`, the five revision members, `mStepValid`, `mVisitGeneration`, `mQueue`, `mSpinUp`, `mHold`. Hooks are a protected nested abstract struct the derived stage implements; the base holds a `Hooks&` supplied at construction (Task 0 confirms the module lifecycle base class that provides `DoStart/DoUpdate/DoStop`, and where `HoldGenerationToken` and the `WorldGenerationFailed`/`WorldGenerationComplete` messages live: `world-handoff.plan.md`).
- Stage ids are the system tokens: `weather`, `hydro`, `ecology` (`WorldSimNames::StageId(sys)`); the World Step default order is `["weather", "hydro", "ecology"]`.
- Health: `Dia::Observation::HealthStatus` (`kOK`/`kDegraded`/`kFailing`) through one `IHealthReporter` held by the base; each system supplies a `CauseCode` enum plus a text function. Metrics: `cow.<sys>.step_ms` (a duration) and `cow.<sys>.discarded_steps` (a counter), both registered as `MetricInfo` by the base through `MetricRegistry`, with the names built by `WorldSimNames::MetricName(sys, "step_ms")`.
- Threading: `Run` touches only the working sim and the latch. Readiness, the queue and the spin-up poll are SimPU-only. `WorldCellFields` reads and `Enqueue` assert off-SimPU/in-`Run` in Debug (same assert macro as the existing S-1 SimPU checks; Task 0 names it).
- Log channel for kit code: confirm in Task 0 (the spec lists the short codes `WGEN`, `WTH`, `HYD`, `ECO`; existing CoW code logs on `"CoW"`). The base logs through a channel code passed in by the system.

### `FakeWorldStage` (Task 6)
- `Testing/FakeWorldStage.h`: `FakeSim { int id; bool initOk; }`, `FakeEntry { int delta; }`, `FakeLatch`, and `class FakeWorldStage : public WorldStepStageBase<FakeSim, FakeEntry, FakeLatch>` implementing the hooks with recorders (`CallLog` of `(hook, key)`), switches (`extraReady`, `latchOk`, `initFails`, `runBlocksUntil`), a `StepKey`-driven manual driver (`Capture/Run/Commit`), a `SerialExecutor`, and a fake world (revision, width, height) that the test advances. Tests drive the base through the same `IWorldStepStage` calls the chain makes. A5-style behaviour (`ExtraReady=false`, `LatchInputs` failing) is a switch, not a second class.

### Save codec (Tasks 15 to 19), `WorldSimSaveCodec.h/.cpp`
- `enum class SavedKind : uint8_t { F32, U8, U16 }`, `enum class SavedScope : uint8_t { PerCell, PerBasin }`, `struct SavedField { const char* name; SavedKind kind; SavedScope scope; const char* layerKey; double minOverride, maxOverride; bool hasOverride; }`, and the system declares a `SavedField` array (pointer and count, PD-004). The range for each field is read from the layer sidecar entry (`cow.<sys>.layers/<field>`, `min`/`max`) through `ValueSchemaRegistry`/`ValueSchemaService` (Task 0 names the lookup); `minOverride/maxOverride` are used only for a field with no layer.
- `struct SaveError { String32 field; String256 reason; }`. `WriteHeader(Json::Value&, const Header&)`, `WriteArray(Json::Value&, name, const float*|uint8_t*|uint16_t*, count)`, `Validate(const Json::Value&, const SavedField*, uint32_t, const Caps&, SaveError&)` (all-or-nothing), `ValidatePending(...)` (the same checks over the pending blob), and a restore driver `RestoreSequence` that calls the stage's `InitialiseSim` and `RestoreCommitted(record)` hooks. Arrays use `Json::Value::append(double)` with 17 significant digits; `-0.0` is written as `+0.0`; a `ready:false` record holds only `ready`. No in-record `version`; `GetVersion()` is the stage's `kFormatVersion`; upgrades go through `Dia::SaveGame::SaveRegistry::RegisterMigration`. Participant id `cow.<sys>` (`WorldSimNames::SaveId`).
- Biome palette (spec-6 resolution 1, adds to AC 5): a record holding per-cell biomes writes `biome_palette: [id strings in registry order]` once, and each cell stores an index into it. Load remaps each palette id to the current registry through `ResolveOrFallback` (one warning per unknown id, from the registry) and records `BiomeRegistry::Hash()`; a hash mismatch with a successful remap logs one Info. The codec takes `const BiomeRegistry&`; it is not a global.
- The 7-step restore, the event-order fallback (stash the record, apply on the next matching `WorldGenerationComplete`) and the `{pending_version: 1, valid, step_day, cell_count, ...}` / `{pending_version: 1, valid: false}` blobs are exactly as in the spec.

### Commands (Tasks 20 to 24)
- `SimCommandSet`: `struct Entry { const char* name; EntryKind kind /*Command|Query*/; SimHelpInfo help; Handler handler; }`; `bool RegisterAll(SimQueryHost&, const Entry*, uint32_t count, Dia::Core::StringCRC owner)`. On a failure at entry n it unregisters entries 1..n-1 with `UnregisterCommand` or `UnregisterQuery` according to each entry's own kind, logs one Error naming entry n, and returns false. `UnregisterAll` is idempotent. `SimQueryHost` is `Dia/DiaDebugServer/SimQueryHost.h`; tests use a fake host or a real one with an injectable failure (Task 0 decides which; a fake host with a "fail the n-th registration" switch is the plan).
- `ParamCommandHelper`: `Register(SimCommandSet&, const char* sys, ParameterFile&, MutationEnqueue /*function: queue a set/reload mutation*/, SystemActionHandler*)`; one command `cow.<sys>.params` with `SimHelpInfo`. `action` is `set | get | list | reload | save_defaults`; any other action is passed to the system handler under the same name, or is an error. Replies exactly as the spec's table, with `effectiveDay` and `visibleDay` in the `set` reply (resolved ODQ 3: `visibleDay` present only when the step is deferred, `capture + k`). `save_defaults` is guarded by a build-configuration flag (Task 0 names it; shipping builds refuse with an error) and writes only the sidecar's `default` fields through the in-place writer from Parameter Files (byte-identical elsewhere). `source` in `get`/`list` is `default`, `pack:<id>` or `set`.
- `cow.<sys>.records {action: reload|list}` (spec-6 resolution 2): registered through `SimCommandSet`; `reload` is queued and strict (a bad record fails loudly: health Failing, naming file, record and field, via the base's cause code); `list` returns the record ids.

### Cell fields and selectors (Tasks 14, 25 to 29)
- `WorldCellFields : Dia::Condition::IConditionContext`. `struct FieldReader { float (*getFloat)(const void* ctx, uint32_t cell); bool (*getBool)(const void* ctx, uint32_t cell); const void* ctx; }`; `bool Register(StringCRC slot, StringCRC field, FieldReader)`; `bool Has(StringCRC slot, StringCRC field) const`; `void SetCell(uint32_t)`; `void Clear()` (rebuilt on `WorldGenerationComplete`). Handles are `(slot, field)` CRC pairs resolved at use (ODQ 2 resolved). Reads are SimPU-only; a read while a `Run` is active asserts in Debug (the base exposes an `InRun()` flag the fields object receives by pointer).
- Contributions: S-1 registers `terrain.*` (`elevation`, `latitude`, `water_source` (enum ordinal), `terrain_type`, `is_river`, `is_protected`, `flow_direction`, ...), `biome.index`, and one bool `biome.tag.<tag>` per registry tag. `terrain.is_protected` covers corridor sites, `Pass`, `RiverCrossesBarrier`, `Hearth`, `Nexus` and world-throne cells (spec-6 resolution 3; it replaces `terrain.is_crossing`). A5 (later) contributes `hydro.basin_kind` with `none`, `lake` or `dry`; A5's `any` is `!= none`. The kit tests use a fixture contribution for `hydro.basin_kind`.
- `CellSelectorSet`: loads one `{derived, selectors}` JSON block. `all` is predefined. Limits: 32 selectors, 16 derived fields (spec-6 resolution 3). Selectors are `ConditionExpr` JSON via `ConditionExpr::LoadFromJson`; validation uses the new `Validate(IConditionContext&)` overload (with the derived fields registered into the context under `slot: "derived"`). Derived fields: `distance {from}` (multi-source hex-step distance, unreachable = +infinity) via `Dia::Pathfinding::MultiSourceSteps` over `HexNeighbours`, and `upstream {of, maxSteps}` via `MultiSourceSteps` over a `TreeGraph` built from `terrain.flow_direction` (1 within `maxSteps` along flow toward a matching cell, else 0). Resolve order: dependency order of derived fields and selectors; cycles are a load error naming the item; `maxSteps < 1` is a load error. A selector resolves to a sorted `DynamicArrayC<uint32_t, 65536>` cell list (or a pointer and count into one pooled array), identical bytes for the same world. "Empty where used" is the consumer's check, not the set's.

### Names (Task 4)
- `WorldSimNames.h` (header only, constexpr-friendly where possible, output into fixed `String64`): `LayerId(sys, field)` -> `"<sys>.<field>"`, `LayerSchemaKey` -> `"cow.<sys>.layers/<field>"`, `ParamSchemaKey`, `CommandName(sys, verb)` -> `"cow.<sys>.<verb>"`, `SaveId` -> `"cow.<sys>"`, `StateFormat` -> `"cow.<sys>_state"`, `ParamsFormat` -> `"cow.<sys>_params"` (a pack uses the same format as its sidecar, per Parameter Files' spec-6 resolution), `PresetFormat` -> `"cow.<sys>_preset"`, `PresetPath(sys, id)` -> `"Global/<System>/Presets/<id>.<sys>_preset.json"`, `StageId(sys)`, `MetricName`. System tokens are `worldgen`, `weather`, `hydro`, `ecology`, `succession`. Fields are `snake_case`; a helper `ToSnakeCase` is test-only (used by the rename task's checker). S-1's own `cow.worldshape` presets are a different concept and are not renamed.
- The pattern test (`TestWorldSimNames`) walks every layer id, command name, schema key, save id and stage id that S-1 registers (through the real `WorldLayerSource` table, the S-1 command list in `WorldGenerationModule` and the stage sidecar) and asserts each matches its generated pattern. Later kit users add their own rows.

- Test files under `Cluiche/Tests/GoogleTests/CoW/WorldSimKit/`: `TestMutationQueue.cpp` (`MutationQueue*`), `TestSpinUpSlot.cpp` (`SpinUpSlot*`), `TestWorldStepStageBase.cpp` (`WorldStepStageBase*`), `TestWorldSimSaveCodec.cpp` (`WorldSimSaveCodec*`), `TestSimCommandSet.cpp` (`SimCommandSet*`), `TestParamCommandHelper.cpp` (`ParamCommand*`), `TestWorldCellFields.cpp` (`WorldCellFields*`), `TestCellSelector.cpp` (`CellSelector*`), `TestSelectorClauses.cpp` (`SelectorClauses*`), `TestWorldSimNames.cpp` (`WorldSimNames*`). - Hex fixtures are hand-built in test files (a small 6 x 4 world and one 3 x 3 flow tree) with answers computed by hand in comments and asserted as literals, not by calling the production helper. Determinism checks use `memcmp`.

### Verification cadence
- Per task: a narrow `dia run googletest --filter="<suite under work>" --shards 2` (always `--shards 2`). The feature scope `--filter="*WorldStep*:*WorldSim*:*CellSelector*:*CellFields*:*SimCommandSet*:*ParamCommand*:*Condition*:*WorldGen*:*WorldLayer*:*SelectorClauses*:*MutationQueue*:*SpinUpSlot*"` runs only in the verification task, plus the S-1 E2E scenario (`Cluiche/Tests/E2E/scenarios/cow/s1worldgen`; build first, E2E does not build; kill any leftover `CluicheTest.exe`).
- No full suite per feature (one full run at the stack close-out). No sanitizer. No mutation checks. Perf is a Debug ballpark only: one check that `CellSelectorSet` resolves 32 selectors on a Large 104 x 64 world in well under a second in Debug, no Release benchmark. World-sim verification uses cell data and stats, never screenshots.
