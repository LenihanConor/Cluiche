## Implementation Patterns

### Phase A: concept, adapter, scratch, test grids (Tasks 2, 3)
- Namespace `Dia::Pathfinding`. New files under `Dia/DiaPathfinding/`: `GridSearch.h` (+ `GridSearch.inl`), `GridSearchScratch.h/.cpp`, `HexNeighbours.h`; test helper `Testing/GridSearchTestGrids.h` (PD-009; the existing `Testing/PathfindingTestHelpers.h` stays untouched).
- `template<class G> concept CIndexGraph = requires(const G& g, uint32_t c) { { g.CellCount() } -> std::convertible_to<uint32_t>; g.ForEachNeighbour(c, [](uint32_t){}); };` in `GridSearch.h`. `ForEachNeighbour` is a template member taking any callable; neighbours are visited in a fixed order. No virtuals.
- `HexNeighbours` (`HexNeighbours.h`): holds `const HexTopology*`; `CellCount()` forwards; `ForEachNeighbour(c, fn)` loops `dir = 0..5`, calls `topo.NeighbourAt(c, dir)`, skips `kNoCell` (same `kNoCell` constant as `HexTopology.h`). Used by S-1 so direction order matches today's loops (`for d in 0..5` over `NeighbourAt`).
- `Testing/GridSearchTestGrids.h`: small hand-built hex grids with known answers (fixed `HexTopology` sizes with explicit pass/blocked masks and expected arrays), `ChainGraph` (N cells in a line) and `TreeGraph` (child adjacency from a parent-index array), both satisfying `CIndexGraph`; a `static_assert` list lives in the Task 2 test.
- `GridSearchScratch` owns the reusable queue, bucket arrays and the binary heap as Dia containers (`DynamicArray<uint32_t>` / `DynamicArray<HeapEntry>`; the heap is a Dia-owned binary heap over a `DynamicArray`, PD-004). Provide `void Reserve(uint32_t cells)` and an internal `Reset()` that clears sizes but keeps capacity. No STL in any public header.
- Constants: `constexpr uint32_t kUnreached = 0xFFFFFFFFu;` (in `GridSearch.h`; keep distinct from `kNoCell` even though they share a value).
- Error and log conventions: pure functions, no logging, no asserts on caller data except `DIA_ASSERT` on null required output pointers in Debug. Callers own all output arrays (sized `CellCount()`).
- Test files (new, `Cluiche/Tests/GoogleTests/DiaPathfinding/`): `TestGridSearchConcept.cpp`, `TestGridSearchSteps.cpp`, `TestGridSearchFlood.cpp`, `TestGridSearchDijkstra.cpp`, `TestGridSearchPriorityFlood.cpp`, `TestGridSearchScratch.cpp`, `TestGridSearchPerf.cpp`. Suite names `GridSearchConcept*`, `GridSearchSteps*`, `GridSearchFlood*`, `GridSearchDijkstra*`, `GridSearchPriorityFlood*`, `GridSearchScratch*`, `GridSearchPerf*`.

### Phase B: the four helpers (Tasks 4 to 8)
- `MultiSourceSteps<G, Passable>(const G&, const StepSeed*, uint32_t seedCount, Passable, uint32_t maxSteps, uint32_t* outSteps, uint32_t* outSeedId /*nullable*/, GridSearchScratch&)`. Bucketed BFS: bucket index = steps; seeds inserted into the bucket of their `startSteps`. Documented order: lower start offsets win; ties keep the lowest seed index, then the lowest cell index; neighbour order is the graph's. `outSteps` initialised to `kUnreached` for every cell first; impassable cells stay `kUnreached`; a seed on an impassable cell is ignored; `maxSteps` inclusive. Today's S-1 loops are plain FIFO BFS with a pre-seeded queue (e.g. `TerrainLandmass.cpp` ~217-235); with one start offset of 0 the two must be bit-identical. Task 0 reads each site and records whether bucketing and FIFO order agree for every start-offset case (`BiomeClimate.cpp` ~118, where rivers start at `kRiverPenalty`).
- `FloodRegion(const G&, uint32_t start, InRegion, uint8_t* seen, uint32_t* outCells, GridSearchScratch&) -> uint32_t` in BFS order (matches `TerrainLandmass.cpp` ~410 `Flood`, which appends visited cells and marks `seen`). `ConnectedComponents(const G&, InRegion, uint32_t* outLabel, uint32_t* outSizes /*nullable*/, GridSearchScratch&) -> uint32_t` returns the component count; labels in ascending first-cell order; `outLabel` is `kUnreached` outside the region; `outSizes` is indexed by label.
- `MultiSourceDijkstra<Cost, G, StepCost, OnSettle>(...)`: `Settle` enum, `DijkstraOptions<Cost>`, `AcceptAll` default functor (declared in `GridSearch.h`), heap ordering `(cost, cell index)` as a strict total order; `stepCost(from, to) < 0` blocks the edge (PD-008); unreached cost is `std::numeric_limits<Cost>::infinity()`; `outPrev` is `kNoCell` for seeds and unreached cells; `stopAt` stops when the first settled cell has `stopAt[c] != 0` and writes `outStoppedAt`. `Cost` is a template parameter so S-1's `double` depth zones and `float` navigation/regions keep their own arithmetic (do not widen or narrow inside the helper; accumulate `cost + stepCost` in `Cost`).
- Settle hook: `onSettle(cell, cost, seedId) -> Settle`. `Accept` settles and expands; `Skip` drops the entry; `Park` moves the entry to a parked list in the scratch; `ResumeParked(GridSearchScratch&)` is a free template (or member of the scratch; Task 0/7 decide and record) that re-pushes parked entries and the caller then calls the search again to continue. The continuation needs the same options and output arrays; define it as: the second call to `MultiSourceDijkstra` with `seeds = nullptr, seedCount = 0` after `ResumeParked` continues from the heap without reinitialising outputs. Document this in the header.
- `PriorityFlood<G>(const G&, const float* elevation, const uint8_t* isOutlet, float epsilon, float* outFilled, float* outLevel, GridSearchScratch&)`: heap order `(level, filled, cell)` exactly as `TerrainDrainage.cpp` ~72-104 (`filled[nb] = max(raw, e.filled + kFillEpsilon)`); cells never reached keep raw elevation in `outFilled`; `outLevel` is the exact spill level. Task 0 records the current code's exact ordering and unreached rule.
- Determinism: results identical across runs and builds; no `unordered` containers; no pointer-address-dependent ordering.

### Phase C: S-1 migration (Tasks 12 to 22)
- Files (CoW, `Cluiche/CoW/Shared/WorldGeneration/`): `BiomeClimate.cpp`, `TerrainLandmass.cpp` (three sites), `TerrainMountains.cpp`, `NodesRiver.cpp`, `TerrainDepthZones.cpp`, `NavigationQuery.cpp`, `RegionPartition.cpp`, `TerrainDrainage.cpp`. S-1 keeps its own `std::vector` locals; only the search body is replaced. Convert `std::vector<int>`/`<float>` buffers to the caller-owned pointer arguments via `.data()`; keep the S-1 types that downstream code reads.
- Each migration is its own task, in a fixed order from lowest to highest risk, and each ends with the golden check. Wiring and adapters stay in CoW (CLAUDE.md layer rule):
  - `NodesRiver.cpp` needs a child-graph adapter (the spec's `TreeGraph`). The spec only names `TreeGraph` in `Testing/`. Production code must not include a Dia `Testing/` header. Plan: a small local `struct ChildGraph` (satisfies `CIndexGraph`) in an anonymous namespace in `NodesRiver.cpp`. If the user wants a production `TreeGraph` in Dia, that is a new Dia header not in the spec: ask first (Open item 3).
  - `NavigationQuery.cpp` needs an adapter from `IPathCostProvider` to the `StepCost` callable (the spec says "an `IPathCostProvider` adapter is provided"): a local lambda or struct in `NavigationQuery.cpp` calling the provider and returning its `kImpassableCost` (negative) unchanged.
  - `RegionPartition.cpp` uses `outSeedId` and an `onSettle` closure over the cap/floor state (phase 0 parks satisfied regions, `ResumeParked` then phase 1).
- Verification per call site: `dia run googletest --filter="*WorldGenLayerGoldens*:<site suite>" --shards 2` where the golden suite name is read in Task 0 from `Cluiche/Tests/GoogleTests/CoW/TestWorldGenLayerGoldens.cpp` (4 presets x seeds 1 to 3, Small, every layer, against `CoW/Golden/worldgen_layers.golden.json`). Never regenerate or re-baseline the golden. If a site cannot be made bit-identical: revert that site, stop and report (Open Design Question 1).
- Site suites (Task 0 confirms): `TestBiomeClimate*`, `TestBiomeGenerator*`, terrain tests (`TestTerrainDeterminism*`), `TestNodesRiverFill*`, `TestNavigationQuery*`, `TestReachabilityValidator*`, `TestRegionPartition*`, `TestRegionRepair*`, `TestRegionsAndSites*`.

### Verification cadence
- Per task: narrow filter with `--shards 2` (always). Feature-wide scoped run only in the verification task: `--filter="*GridSearch*:*Pathfinding*:*WorldGen*:*Region*:*Reachability*:*Navigation*:*Biome*:*Terrain*" --shards 2`. No full-suite run here (one full run at stack close-out). No sanitizer. No mutation checks. Perf is a Debug ballpark only (no Release benchmark, no bench rig).

## Open items

1. **Site count.** The spec says "nine hand-written searches" but lists ten migration rows (landmass coast distance counted once with two passes). The plan follows the table; confirm the count is intentional.
2. **Spec line numbers.** The file and line references in the spec are approximate; Task 0 records the real locations. The site list itself is unchanged.
3. **Resolved 2026-11-18:** `AdjacencyGraph` is a production Dia type (Task 2a, AC 9-11); `NodesRiver` uses it (Task 17a); `TreeGraph` in `Testing/` is a thin fixture over it. **Production `TreeGraph`.** The spec names `TreeGraph` only as a test helper (`Testing/GridSearchTestGrids.h`), yet `NodesRiver.cpp` must run `MultiSourceSteps` over a child graph. Production code should not include a Dia `Testing/` header. The plan uses a CoW-local adapter. If the user wants a reusable `TreeGraph` in the Dia API, that is an extra Dia header not in the spec, so it needs sign-off before any task adds it.
4. **`ResumeParked` shape.** The spec gives the semantics ("parked entries rejoin the queue, and the search continues") but not the signature or how the search is re-entered. The plan documents "second call with no seeds after `ResumeParked`"; Task 7 may find a better shape and must report it before changing the spec's API text.
5. **Heap tie order for `PriorityFlood` and Dijkstra.** The spec states `(level, filled, cell)` and `(cost, cell)` but whether S-1's current heaps break ties exactly this way is confirmed only in Task 0; any difference is a Task 0 finding that decides between bit-identical migration and a documented order change (the latter is out of scope: stop and ask).
6. **`SLOW_` region test.** The spec says its existing failure is "tracked separately"; the plan only compares with the Task 10 baseline.
